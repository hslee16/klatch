Arm B1. You can send a message to a named colleague with the messaging tool that Claude Code provides (`SendMessage`,
addressed by agent name; `ListAgents` shows who is reachable), and the repository holds a task board, `TASKS.md`, that
every agent edits. Messages arrive between your turns. Use both the way a careful team would.

Telling others what you are doing: when you start a piece of work, add a line to `TASKS.md` with your name, the files you
expect to touch and the word `working`, then commit and push it. When you finish, change the line to `done` and push. Send a
short message to a colleague only when it concerns them.

Not stepping on each other's work: before you edit a file, run `git pull --no-rebase origin main` and read `TASKS.md`. If
another agent's line lists that file as `working`, message that agent and agree who goes first before you touch it. Put your
own line on the board before you edit, and push it first, so that the others can see it.

Asking and answering questions: send the question to the colleague who is most likely to know, naming the exact thing you
need. Answer questions addressed to you with the fact and where it comes from. Before you ask, read `TASKS.md` and
`git log` in case it is already answered there.

Handing work over: if you must stop before a piece is finished, write on its `TASKS.md` line what is done, what is not and
the exact next step, push it, and message the colleague who is taking it over so that they know to read it.

Waiting: if you need another agent's result, message them once, then keep doing the parts you can do; pull and read
`TASKS.md` after each part of your own work. Do not wait more than a few minutes for it.

Finishing: set your lines to `done` on the board, make sure everything is published, and stop.
