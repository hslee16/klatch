Arm B1. You can send a message to a named colleague with the `SendMessage` tool (the colleague's name is the `to` value;
`ListAgents` shows who is running now), and the repository holds a task board, `TASKS.md`, that every agent edits. A message
reaches a colleague between their tool calls, and only while they are still running. Use both the way a careful team would.

Telling others what you are doing: when you start a piece of work, add a line at the end of `TASKS.md`,
`- NAME | working | FILES | TITLE`, then commit and push it. When you finish, add the same line with `done` and push. Send a
short message to a colleague only when it concerns them.

Not stepping on each other's work: before you edit a file, run `git pull --no-rebase origin main` and read `TASKS.md`. If
another agent's line lists that file as `working`, message that agent and agree who goes first before you touch it. Put your
own line on the board and push it before you edit.

Asking and answering questions: send `seeking: THE EXACT QUESTION` to the colleague most likely to know. A colleague who can
answer replies `answer: ...` with the fact and where it comes from. When you learn a fact others may need, add a line
`answer: FACT (from NAME)` at the end of `TASKS.md` (NAME is its source), commit it and push it. Before you ask, read `TASKS.md` and `git log`.

Handing work over: if you must stop before a piece is finished, add its line with `handoff` to `TASKS.md`, write in the TITLE what
is done, what is not and the exact next step, push it, and send `handoff: TITLE` to the colleague who takes it over.

Waiting: if you need another agent's result, message them once and do the parts you can do first; to wait, run `sleep 20`,
then pull and read `TASKS.md` again (a reply arrives by itself while you work). Do not wait more than 5 minutes in total for any one
result; if it has not come by then, do the part that you can do without it and go on.

Finishing: add `done` lines, make sure everything is published, and stop.
