| Passphrase | `init-passphrase`, `reset-passphrase`, `unlock-window`, `shell` | `init-passphrase` sets the first passphrase (typed twice, at a terminal, audited `passphrase-set`; with none set there is nothing to prove, so it is refused from inside a coding-agent session, and an install that has not set one stays open to a program with a terminal until the human does: SECURITY.md, #1262) and, with one set, changes it after asking for the old one (the failure limit applies; `passphrase-changed`). `reset-passphrase` is the recovery path: the store's recovery code (typed, constant-time compared, charged like a wrong passphrase) replaces the passphrase (`passphrase-reset`); the code can already restore the key, so it gives its holder nothing more. `unlock-window` shows or sets the window (10 to 1800 seconds, default 60; needs the proof). `shell` needs standard input itself to be a terminal and reads admin, worker, anchor, run and judge commands under one proof held in that process's memory for the window; it runs no other command and not itself. Every prompt names the command it approves (printable ASCII only); the commands that print stored text need standard output to be the controlling terminal and the same device as the prompt (standard error that terminal or /dev/null); the typed-back confirmation is read from the terminal, never a pipe. Audit rows: `proof-ok` (the window length), `proof-failed` (`failures=N`, never the attempt), `proof-locked` and `proof-refused` (at most one a minute each, so a loop of refused commands cannot fill the audit), `passphrase-rehashed` (the cost was raised). `proof-failed-many` (#1310, alarm only: written once, by the proof path, in the same transaction as the `proof-failed` row that brings the failures of the last 24 hours across all terminals to exactly 50; `failures=N terminals=T window=24h`, counts only; it locks nothing and adds no delay; `klatch doctor` warns while the count is at or above 50).
