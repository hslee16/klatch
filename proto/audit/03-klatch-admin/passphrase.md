| Passphrase | `init-passphrase`, `reset-passphrase`, `unlock-window`, `shell` | `init-passphrase` sets the first passphrase (typed twice, at a terminal, audited `passphrase-set`; with none set there is nothing to prove, so it is refused from inside a coding-agent session, and an install that has not set one stays open to a program with a terminal until the human does: SECURITY.md, #1262) and, with one set, changes it after asking for the old one (the failure limit applies; `passphrase-changed`). `reset-passphrase` is the recovery path: the store's recovery code (typed, constant-time compared, charged like a wrong passphrase) replaces the passphrase (`passphrase-reset`); the code can already restore the key, so it gives its holder nothing more. `unlock-window` shows or sets the window (10 to 1800 seconds, default 300; needs the proof). `shell` needs standard input itself to be a terminal and reads admin, worker, anchor, run and judge commands under one proof held in that process's memory for the window; it runs no other command and not itself. Every prompt names the command it approves (printable ASCII only); the commands that print stored text need standard output to be the controlling terminal and the same device as the prompt (standard error that terminal or /dev/null); the typed-back confirmation is read from the terminal, never a pipe. Audit rows: `proof-ok` (the window length), `proof-failed` (`failures=N`, never the attempt), `proof-locked` and `proof-refused` (at most one a minute each, so a loop of refused commands cannot fill the audit), `passphrase-rehashed` (the cost was raised). Proof: `proof/tests.rs`, `tests/admin_proof.rs` (every `AdminCmd` variant, on a pseudo-terminal with a wrong passphrase and with none, with the passphrase in the environment, an argument or a pipe) |
