- `Backend` has a cancel hook (`canceller()` and `handle_cancellable()`, #1562). The default reports "not cancelled" and runs a look to its end. The shared-gateway backend (`SharedBackend`) registers each look under its call id, so a look waiting on the owner thread ends within one 20 ms tick of a cancel with the `Cancelled` outcome, and a look the owner has not started is never run. Only pure looks (`who`, `claims`, `history`, and `read` with `peek: true`) can be cancelled; any request with an effect is a plain request and is never reported `Cancelled`. `klatch acp` is wired to the hook (the key names the session and the JSON-RPC id, and a prompt for an unknown session is not recorded). Today `klatch acp` runs over the in-process gateway, whose hook is the default (not cancelled), so in production a cancel still only drops the answer when the look returns; the shared backend is reached only by tests until `acp` uses it (#1562).
