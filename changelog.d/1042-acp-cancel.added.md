- `klatch acp --stdio` reads its input on a helper thread, so a `session/cancel` that arrives while a prompt is being handled is seen at once: the prompt ends with `stopReason` `cancelled` and no answer, a prompt that was read but not started when its cancel came makes no look, and a cancel for another session, for no running prompt, or one that carries an `id` changes nothing. Messages, their order and framing, error replies, the end of input and a read error behave as before. The queue between the reader and the handler holds 64 lines. A look already running in the backend is not interrupted; the cancel takes effect when it returns (#1042).
