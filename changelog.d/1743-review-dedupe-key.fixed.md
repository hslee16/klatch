- Crossing requests are matched as already waiting only for the same requester and target room (#1743). The review queue's dedupe key was message and label only, so a second member asking to cross the same message, or the same member asking for another room, was handed the first item's queue id and target room, and the verdict applied to the first item's target. The key is now message, label, requester and target room, for the uncapped enqueue as for the capped one; a plain item (no requester, no target) still queues once per label. The schema is unchanged (there was no unique index on the queue), so there is no migration, and items already waiting keep their ids.
