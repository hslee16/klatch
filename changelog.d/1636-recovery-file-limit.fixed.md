- The recovery attempts file (`<store>.recovery-fails`, #1281) is opened without following a symlink and without blocking on a pipe, at most 64 KiB of it is read (a file over that, or one that is not a regular file, is a wait and never a free attempt), and the check and the append happen under one lock, so racing callers at the moment one attempt is due get exactly one. A recorded time of `i64::MAX` no longer wraps in release builds and grants a free attempt. `klatch doctor` warns with the count of recorded, unsettled attempts, and a wrong recovery code prints the count and the file on stderr The attempts file is created with mode 0600 and refused when it has more than one hard link; waiting for its lock is bounded to 3 seconds, after which the recovery is refused with a message naming the file, and a file that is oversized or not a plain file is refused with a message to inspect and remove it, never a free attempt. On a file system where `flock` is not supported (some NFS mounts on macOS) every recovery on that store is refused (#1636).
