- The no-network guards of klatch and klatch-server now read the source with a real tokenizer (a // inside a string no longer hides code) and flag raw syscalls and SYS_ numbers, libc aliases and spacing variants, extern blocks with any ABI or none, link_name, the exec family, system, popen and posix_spawn, aliases of Command, brace-nested nix, rustix and std::os::unix paths, the connectx family of extra libc names, and a #[path] or include! that pulls a test-only file into shipped code; they also read build.rs, tests and fuzz. klatch-server gets the same scan with an exact file-and-line allowlist for the daemon peer credentials, the loopback socket pair and its Unix socket tests (#1781, #1783).
- The no-network guards no longer miss code behind a C string (`c"..."`, `cr#"..."#`) or an escaped quote char (`'\''`), skip only the real build output directories (never a `target`, `corpus` or `artifacts` directory under `src`), apply the socket, `std::net` and program checks to `build.rs`, `tests` and `fuzz`, find program starts by the identifier `Command` in every form (type alias, `.map(Command::new)`, `<Command>::new`) with each program name allowed only in the files that need it, read `#[path]` of any extension and refuse a missing target, resolve the `loopback::Stream` and `Listener` aliases and count binds and connects by tokens in klatch-server, and read mod declarations from tokens so a comment or a second declaration cannot fake the required `#[cfg(test)]` (#1783).
- The no-network guards skip a first-line shebang like rustc, treat exactly rustc's white space (including the U+200E and U+200F direction marks) as white space between path segments, follow `use .. as` renames and `type X = ..` aliases of the socket types file-wide in klatch-server, report an attribute that is never closed instead of panicking, and say in their docs that they are a tripwire over source text, not a proof (#1783, #1787).
