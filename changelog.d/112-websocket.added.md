- `GET /v1/ws` on `klatch-server http` (loopback, `ws://`) and `klatch-server https` (mutual TLS, `wss://`): the klatch wire over one WebSocket connection, the same session and the same frames as `GET /v1/stream` and `POST /v1/frames` with one frame line per text message each way (requests, events, acknowledgements, resume from `seq`). The caller is the worker credential, checked at the upgrade (the one `401` otherwise); a request that carries an `Origin` header is refused with `403` unless `--ws-allow-origin ORIGIN` names it (off by default, repeatable, exact, no wildcard); client frames must be masked, a message is at most 1 MiB, binary is refused, the server pings every 20 seconds and closes a connection that sent nothing for 60, and every close is waited on for at most 2 seconds. No new listener and no new crate with a network stack: the frame layer of `tungstenite` (no handshake, no runtime, no `sha1`) and ring's SHA-1 for the upgrade answer; `cargo deny check` passes with `proto/deny.toml` unchanged (#112, epic #13).
