- `klatch read`, `klatch wait` and the MCP tools `klatch_read` and `klatch_wait` now print at most a bounded part of a busy room per call (read: 40 messages and 16000 bytes, wait: 20 messages and 16000 bytes per room; before, `read` printed every unread message), whole messages from the oldest, with a line saying how many were not shown and the command to continue. Only what was shown is marked read, so the next call continues in order; a single message over the byte cap is cut with a visible marker. `wait` no longer promotes the newest and addressed messages and drops the rest: what it does not show stays unread (#1390). The wire method `read` takes optional `max_messages` and `max_bytes` (additive; omitted, it is unbounded as before).
