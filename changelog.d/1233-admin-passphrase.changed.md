- Upgrading: until you run `klatch admin init-passphrase` once, every admin, launcher and keystore command refuses and says so. The terminal and process-tree heuristic for `klatch admin` and for `worker`, `anchor`, `run` and `judge` is removed (a detached process escaped it, #834); the passphrase replaces it (#1233, #318). `human` is now a reserved member name. See SECURITY.md for what the passphrase does and does not stop.
- The admin passphrase prompt names the exact command it approves, destructive confirmations are read from the terminal and never from a pipe, `klatch admin shell` needs a terminal on standard input, and `admin recover` and `admin restore` work when the store key is lost (the recovery code approves them, since the verifier is in the unreadable store) (#1233).
- `admin recovery`, `export`, `run-archive`, `rotate-key` and `rotate-label-key` refuse when standard output is not a terminal, `admin recovery` asks for a typed confirmation, store-less `recover` needs an existing encrypted store the code opens, and prompts strip hostile characters from argument text and name the store (#1233).
- The commands that print stored text (`audit`, `refusals`, `review-queue`, `scrub-list`, `archives` and the secret printers) and `klatch admin shell` require standard output (and input, for the shell) to be your controlling terminal, and prompt text from arguments is printable ASCII only (#1233).
- Acts that print stored text also require standard output to be the very terminal the passphrase is typed at and standard error to be it or `/dev/null`, a recovery code is hidden by the parsed command rather than by its words, and a confirmation label for a name with unusual characters shows its length and digest (#1233).
