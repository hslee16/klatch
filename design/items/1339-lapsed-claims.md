A named claim that lapsed unreleased is a lapsed_claim stuck event (#1339; no schema change; 2026-11-24).
`klatch stuck ROOM` and the wire method `stuck` gain an eighth kind, `lapsed_claim` (`room`, `claim`, `holder`, `lapsed_secs`; key `lapsed_claim:ROOM:CLAIM:HOLDER`), so a dead producer such as the gh-watch receiver shows up without a human noticing. **Where it lives:** `stuck`, not `doctor`: doctor is about the local install, stuck is the room's standing cases, and the event rides the same guard (a room above the caller's label is refused, and the event names only that room's claims). **Producer marking:** none. Any named claim counts, so no claim flag or wire change exists; `ask:<N>` claims (the ask lapse machinery has them) and passive edit claims (reason `PASSIVE_REASON`) are left out. A claim is reported when its lease ended, it was never released (a release deletes the row, so only a lapse remains), and its holder has no `done` status set since the claim was first taken (`members.status LIKE 'done%'` and `status_ts >= since`; a `done` before the claim does not hide it, and a claim after a `done` clears it as before). **How long a lapse is shown:** `LAPSED_WINDOW_SECS`, which is `YIELD_WINDOW_SECS` (600), fixed and not a setting; at most `LAPSED_CLAIM_MAX` (20) events per room, newest lapse first, one bounded query over the room's claim rows, run only when `stuck` is read, nothing on the claim path. **Text:** the line and the wire fields are fixed (`lapsed_claim room R claim C holder H lapsed Ns`); the claim key goes through `claim_label` (`(unnamed)` unless plain), the reason is never read. The mediator makes no proposal for it. **Durable since #1586:** the store sweeps lapsed rows on the next claim attempt in any room, so the event first vanished once anything swept the row; the sweep now records each named lapse in `claim_lapses` (schema 45, see design/items/1586-claim-lapses.md) and the event reads that table as well as the unswept rows.
