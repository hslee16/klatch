A flagged sender is also marked on tail, history and the live stream (#1032, follows #990; no schema change; 2026-11-20).
#990 marked a flagged (advisory) sender on `read`, `wait` and the hook digest only. **Shape:** the same overlay, `Gateway::mark_advisory`, now also runs on what `tail` (and `tail_scan`, which the stream pages by) and `history` return, so those methods hand back `Message.advisory` exactly as `read` does, from the room's `room:ROOM:advisory:MEMBER` policy keys. The `history` session method already serialised the flag through `message_json`, so it adds `"advisory": true` for a flagged sender and omits the key otherwise. **Stream:** the `message` frame gained an `advisory` field that is serialised only when true (`skip_serializing_if`, default false on read), which is the same optional-field pattern as `kind` and `payload`, so the wire stays inside protocol version 1 and a consumer that does not know the key sees what it always saw. `PROTOCOL.md`, the TypeScript type and the Rust client frame handling carry it; the Python client passes frames through as dictionaries and needs no change. **Forgery:** unchanged from #990; the mark is a fixed constant decided by the policy record keyed by the sender name the gateway attributed, so a member name or message text can neither forge nor hide it, and the #990 forgery cases are repeated for `tail` and `history`. **Limits:** display only and never authority; a requirement lifted after a flagged join leaves the mark until that member rejoins; `klatch admin export` reads through `tail` but writes its own fixed JSON shape, which does not include the flag. No operation is added or changed, so `proto/AUTHZ-AUDIT.md` is unchanged.
