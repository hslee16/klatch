Forwarded identity is never trusted: the headers are ignored and counted by name (#110, epic #13; no schema change; 2026-11-23).
The owner decided that klatch never takes a proxy's word about who a caller is (option A on #110), so the planned allow-list of proxy addresses is dropped; it would have needed a peer address, which klatch deliberately never reads. Behind a reverse proxy or stunnel the identity is always the worker credential. A request that carries a header from a fixed list (`Forwarded`, `X-Forwarded-For`, `X-Forwarded-User`, `X-Forwarded-Email`, `X-Forwarded-Client-Cert`, `X-Real-IP`, `X-Remote-User`, `X-Client-Cert`, `X-Client-Verify`, `X-Amzn-OIDC-Identity`, and the `X-SSL-Client-*` family as one name) is counted once, and each name it carried once, in `klatch-server/src/forwarded.rs`. That module is handed header names only, never a value, so it cannot store or log an address or any header text. `tests/route_audit.rs` allows only that file to spell the names and checks it names no header type, value accessor or output.
Where the count shows: one counts-only line on stderr when `klatch-server http` stops (`klatch-server: forwarded identity headers ignored: requests=N name=K ...`), also at zero. The live line and the audit rows are the design item for #1490. Not run: any real proxy or stunnel; the guide's ssh and stunnel lines are still unverified.
