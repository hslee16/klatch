The coordination bench has a harness, a results ledger and a report generator, all standard library Python (#1364; no schema change; 2026-11-22).
Epic #1362 asks whether klatch makes agent teams coordinate better than a team without it, and SPEC.md in experiments/coordbench fixed the rules; this item is the machinery that applies them. `run.py` runs one scenario against the arms B0, B1, K1 and K2, N times each, in interleaved seeded blocks, each run in its own scratch directory: an empty KLATCH_HOME and KLATCH_KEY_DIR (mode 700), a HOME of its own, a bare `origin` made for the run and one fresh clone per agent. It refuses a store path under `~/.klatch` or `~/.claude`, outside the temp root, or behind a symlink, runs the klatch CLI only by the `--klatch-bin` path, and builds every child environment from an allowlist so no credential reaches klatch or a fake agent.

Agents are started through a driver interface with two implementations. `fake` runs scripted deterministic agents (file edits, git and klatch commands, configurable failures and spend) that print the stream-json a real session prints, so the whole harness is tested with no model and no spend. `claude` builds headless `claude -p` commands (the model id from the config, `--setting-sources local`, an allowlist of tools, a per-agent budget) and is tested only by its command construction and a stream parser run on output written by hand. Real agents are refused unless `--budget-approved-in` names where the human approved the budget; a dry run prints the plan and the cost range from the SPEC 8.1 planning figures and runs nothing.

A fixture is a directory (setup script, task texts, a fake script) and the hidden checker lives outside it in `checks/`, so no checkout ever contains it. After the agents exit, or when the wall cap or the per-run spend cap kills them, the checker runs on a clone of the final origin; every run is kept as one JSON record in the SPEC 7.1 schema (failed, aborted and invalid runs too), with one ledger line per run and a suite file that records the caps and any cap hit. Large stream logs go to `--logs-dir` outside the repository with their sha256 in the record.

`report.py` turns a results directory into REPORT.md and JSON: per scenario and arm N, completion rate with a Wilson interval, medians and spread; Fisher exact and Mann-Whitney between each K arm and each B arm with seeded bootstrap intervals, the Holm correction over the primary tests, the EXPLORATORY label under N of 5, and a comparison with a previous results directory that flags a median worse than the previous one by more than the previous interquartile range (confirmed only by the corrected test at N of 5 or more). The statistics (Fisher, Mann-Whitney, Hodges-Lehmann, bootstrap, Wilson, Newcombe, Holm) are implemented in `stats.py` because scipy is not available, and are unit tested against values from the literature and closed forms.

Not built here and still needed for a real run: the human's budget approval, the fixtures and hidden checkers of the scenario tickets, the arm review in #1365. The fields `duplicate_work`, `claim_conflicts`, `overwrites` and `store_export` are null until a scenario supplies a unit-to-path map, and `coordination_context_tokens` is a characters-over-4 estimate.
