Code health K02: the Python and TypeScript client libraries are reorganised inside, public API unchanged (#1443; part of the code health epic #1441; no schema change; 2026-11-23). The two published clients (`clients/python/klatch_client.py`, `clients/typescript/klatch.ts`) scored 6.46 and 6.58 in CodeScene because `connect_socket`, `connect_http`, `request`, `close`, the frame decoder and the server-sent-events reader were long, nested and full of compound conditions. Nothing observable changed: every public name, signature, exception, wire frame and exported type is as before (the TypeScript `.d.ts` differs only by new `private` member names, built and diffed against main). The two clients keep the same structure for the same job: identity checks, the loopback url check, the socket connect, `identify`, awaiting a response and turning it into a result or an `ApiError`, and the close paths are each one small function in both; the HTTP transport takes a target (host, port, member, token) and a patience (connect timeout, reconnect attempts and delay) instead of seven or eight loose arguments; the event stream is assembled by an `_EventAssembler` / `EventAssembler` (plus a line splitter in TypeScript) instead of one loop with five levels of nesting.

Tests first. The socket and stdio paths had no test but the conformance run against a real daemon, so `clients/python/test_socket.py` and `clients/typescript/socket.test.ts` were written and shown green on the untouched code before any refactoring: they run a small in-process Unix-socket server that speaks the daemon's wire (a hello, then one answer per request) and a fake gateway process for stdio, and pin the request framing and ids, `identify` for a name, a member with a token and neither, bad identity arguments, a refused identity, frame skipping while a request waits (messages, caught-up marks, refusals, heartbeats, unknown types, blank and non-JSON lines, other protocol versions), the optional parameters of `post`, `dm`, `history`, `claim`, `release` and `review_verdict`, `collect` and `next_message`, and `close` (write side shut, answer 0, idempotent, after a drop, stdio exit code). The TypeScript file is imported by `http.test.ts` because CI names only `conformance.test.ts` and `http.test.ts`. All of it was a pure refactor, so these tests pass before and after; no test was red first.
