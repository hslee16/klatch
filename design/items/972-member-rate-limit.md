A rate limit for one member, over the global one (#972; 2026-11-20).
The global limit (#187) is one number for everyone. `klatch admin rate-limit --member NAME POSTS SECS` gives one member its own limit, stored in the policy table under `rate-limit:member:NAME` next to the global `rate-limit`; `--member NAME --off` removes it. Precedence is the member's own limit, then the global limit, then none, and a member limit may be higher or lower than the global one (a trusted bot can have more, a noisy one less). The window and the bounds are the global ones (1 to 10000 posts in 1 to 3600 seconds), the count is still over every room, and a refusal is still the rule `rate-limit`. No schema change.
The act is named `member-rate-limit` and is a floor: because a member limit overrides the global one, an agent (or the admin agent) that could set it could lift its own limit. `ForbidFloors` and the admin agent refusal both refuse it; the global `rate-limit` stays an ordinary admin act. The new method is in the zero trust `GUARDED` list and in AUTHZ-AUDIT.md.
