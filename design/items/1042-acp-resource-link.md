`klatch acp --stdio` reads a `resource_link` prompt block as its text form (#1042; 2026-11-21)
The ACP spec makes `text` and `resource_link` the two prompt block types every agent must accept (#869); the librarian read only `text`, so an editor prompt carrying only a link got the help text. **Decision (human, 2026-11-21):** a `resource_link` is read as its text form, the block's `name` and `uri` joined by a space on one line, and joined in order with the other blocks by newlines, so a link-only prompt is answered. The link is data: it is never fetched, opened or run, and the librarian stays grammar-only (a link can only spell one of the same four looks a typed line can, and the same clearance applies). Each of `name` and `uri` has control characters (newlines included) removed and is cut to 256 characters, so a link cannot start a second query line, smuggle terminal escapes, or make the answer echo unbounded text. A link with neither field, and the other block types (`image`, `audio`, embedded `resource`, none advertised), are skipped. No schema or wire change. **Cancel is unchanged:** `session/cancel` is still read only after the current prompt is answered (stdin is read one line at a time), because looks are instant; a reader thread is deliberately not added now. Ticket #1042 stays open for cancel only, to revisit when a slow look exists or a real editor run (#1041) shows the need. **Tests added:** a link is read as "name uri" (red first); a link after text is joined in order; control characters are stripped, length is bounded and a newline cannot start a second query; a link with no fields is skipped (green already, pins the edge).
