doctor warns while no admin passphrase is set (#1262; no schema change).
On an upgraded install with no admin passphrase, the first `klatch admin init-passphrase` proves nothing, so a program with a terminal could set it before the human. The owner chose a warning over a one-time code or an installer prompt. `klatch doctor` reads the policy table through a read-only connection (`read_policy_has`, a presence test, the verifier is never brought back) and, when a readable store has no `admin-passphrase`, adds one warning that names the fix: run `klatch admin init-passphrase` yourself, in a terminal.

    Doctor stays read-only and off the hot path (it runs only when asked), says nothing without a store or a readable key, and keeps its exit convention: warnings exit 0, only a failed probe exits 1. `klatch init` adds two static lines to its closing notice and reads nothing, so it needs no key and no prompt. Neither command sets, issues or asks for a credential. A fresh install with no store yet is not warned about; the first command that creates the store is followed by the refusal "no admin passphrase is set" on every admin act.
