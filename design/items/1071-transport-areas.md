The Transport trait is split into area files, so a new gateway method edits one file (#1071, part of #1064; pure move; no schema change; 2026-11-21).
`gateway/transport.rs` held a 100-method trait, the `Direct` impl and (in `shared.rs`) the `forward!` list, so every PR that added a gateway method edited the same three places and collided. The human chose option A of the ticket and asked for CodeScene (`cs`) to organise it. `gateway/transport/` now has one file per area, each holding the area's trait, its `Direct` impl block and its `SharedTransport` impl block: `messages` (join, post, read, history, receipt, ack, the subscription), `delivery` (wait and wake state, mute, delivery view, change token), `members` (who, scope, role, status, credential), `hooks` (hook runs, mode, session, stop), `claims`, `board` (board, cards, asks, stuck, digest), `review` (crossings and the reviewer queue), `admin` (rooms, runs, members, audit, refusals), `access` (labels, clearances, roles, grants, invites, ssh keys), `limits` (rate limits, leases, stale and ask lease, require) and `scrub` (canaries and scrub terms). `transport.rs` keeps `Direct`, the tests, and `Transport`, which is now a supertrait of the eleven area traits with a blanket impl, so `&dyn Transport` and `T: Transport` read exactly as before. A code that names a concrete `Direct` or `SharedTransport` and calls area methods imports `crate::gateway::areas::*` (only tests do).

How to add a method now: add it to the area trait, the area's `Direct` block and the area's `SharedTransport` block (a line in its `forward!` list, or written out when it stores a message), all in one file. `transport.rs` and `shared.rs` are not touched. A new area is one new file and one line in `transport.rs` (the `mod`, the `areas` re-export and the `Transport` bounds). A wire addition (#1069) still touches the client wrappers, `klatch.ts`, the Python client and PROTOCOL.md, but no longer the trait's shared lists. The `forward!` macro and the `Own` and `Lend` helpers stay in `shared.rs` and are `pub(in crate::gateway)`.

`klatch/tests/shared_forward.rs` (#1092) now walks `gateway/transport/`: for every `pub trait X {` it finds the matching `impl X for SharedTransport {` in the same file and fails naming every method with no forward (`DEFAULTED_ON_PURPOSE` still allows `post`). It was red first (the directory did not exist) and was proven against a probe method with a default and no forward in the `hooks` trait, which failed naming `Hooks::probe_1071`, then removed.

Code health (`cs review`, CodeScene CLI, run offline on the files before and after): `transport.rs` 10.0 before, 10.0 after; `shared.rs` 9.24 before (bumpy road in `SharedGateway::start`, duplicate code in `call_backend_as`/`call` and `dm`/`post_labeled`), 9.84 after (the `dm`/`post_labeled` duplicate moved into `transport/messages.rs`, 9.38 there; `call_backend_as`/`call` is no longer flagged); the eleven area files score 9.38 to 10.0 (`access`, `board` and `claims` 9.68 for string-heavy argument lists that are the trait's existing signatures). No behaviour or signature changed, so those two findings and the bumpy road are left for their own tickets; the repo had no earlier `cs` use or config.
