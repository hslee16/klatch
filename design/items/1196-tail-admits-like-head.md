Gateway tail admits like head, and the human export has its own path (#1196; no schema change; 2026-11-21).
`Gateway::tail` and `tail_scan` used to ask only the guard, so a third member of a direct message, or a member below a room's label, could page a room through them under a guard that allows everything; the wire `subscribe` was safe only because `Subscription::poll` calls `head` first. `tail_scan` now admits the caller exactly as `head` does: the stops, the run and `dm-members` rules, the clearance, then the guard. The human admin export keeps working through `Gateway::admin_tail_scan`, a separate method that is an admin act (`tail`): the role check and the guard decide it (on a members' gateway only the admin agent holds it, a plain member gets `admin-scope`), and it makes no direct-message check. It is chosen by the caller, never by recognising a principal name, and no reader a member reaches goes through it. The other keystore-family acts (archive, retention, doctor) read through the store directly, not through `tail_scan`.
