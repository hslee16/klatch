The readiness line is one write and launchers trust it only when complete (#1173, #1207; test and server startup; no schema change; 2026-11-21).

Test launchers (Rust, Python, TypeScript) start `klatch-server http --listen 127.0.0.1:0` with stderr in a file and poll that file for `http listening on <addr>`. The server printed the line with `eprintln!`, which can reach an unbuffered stderr in several writes, so a poll under load could read half of it and parse a cut-off port or fail on `127.0.0.1:` (#1207, and the wrong-port variant behind #1173). The server now builds the whole line, newline included, and writes it in one `write_all` plus flush (`announce_listening`, unit tested with a write-counting stream). Launchers accept the line only once its newline is present, wait up to 60 s, and print the captured server stderr when the line never appears. The port is already bound at port 0 by the server and reported, so there is no port race.
