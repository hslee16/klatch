A listing of the rate limits in force (#1023; 2026-11-20).
`klatch admin rate-limit --list` prints the global limit (#187) and every member limit (#972), one line each: `global` or `member NAME`, a tab, then `N posts in S seconds`; the global line comes first and the members follow sorted by name. With no limit at all it prints `no rate limit`. `--list` takes no other argument. The gateway method is `admin_rate_limits`, which reads the policy keys `rate-limit` and the prefix `rate-limit:member:`; a stored value that does not parse is left out, as the lookup `rate_limit` already does. No schema change.
Reading is not a floor act: the method asks the guard for the admin action `rate-limit-list` (the same shape as `scrub-list`), writes no audit row, and a gateway that refuses floors still allows it. The admin agent allowlist (`admin-scope`) does not include it, as for `scrub-list`, so it is the human's read. The set acts keep their classes (`rate-limit` is an admin act, `member-rate-limit` a floor). The new method is in the zero trust `GUARDED` list and in AUTHZ-AUDIT.md. The listing is terminal only; there is no wire method.
