Hidden facts are drawn from the run seed (#1531; no schema change to klatch; 2026-11-26).
The coordbench fixtures specialists, recovery and history used to draw their hidden facts from one constant seed and commit the result (private files, reference solution, seed and room files, checks/*/facts.json), so a fact learned in one run, or leaked once, was valid in every later run and a model that had seen a fixture could recall it. Now each fixture's `gen_facts.py` has `generate(seed)`; the harness calls it in process with the run's seed (the suite seed plus the block number, shared by the arms of a block so the arms are paired), writes the files under a directory with a random name inside the run's scratch, and takes the private files, the seed and room files, the fake script and the checker's facts from there. The committed files stay as the default seed's copy (`gen_facts.py --check` proves them), used by `--committed-facts`, which only the fake driver accepts, so a paid run always draws from its seed.

Isolation: the facts directory is under the scratch, so the Claude Code sandbox, the guard list and the post-run scan treat it like the rest of the scratch; it is made mode 0300 while agents run (nobody can list it) and has a random name; it is never inside an agent's clone, home, tmp, the log directory or the bare origin. An agent still gets the private file of its own role in its own clone, which is the design of the fixtures. The checker finds its facts through the environment variable COORDBENCH_FACTS (default: the committed copy next to it), so the facts are not in the checkout the checker reads either. History's setup.sh builds the prebuilt git history from the seed, so its commit ids differ per seed.

Identity: the fixture hash is now version 3. For the three seeded fixtures the files that carry the facts (`seeded_facts.outputs` in fixture.json) and the committed default facts file in the checker directory are not hashed, and the generator sources are (they define what a seed makes); the prebuilt history's commit ids are left out. Every other fixture hashes the same bytes as in version 2 and only its version number changed. The record's `fixture` object gains `seed` (the seed the facts came from) and `facts_sha256` (a hash of every file the seed generates), so a run is reproducible from (fixture hash, seed); the validator and the report tolerate records without them, and the report does not pool version 2 with version 3. Old results carry the old hashes and the fixed facts.

Limit: the recovery fact is one pair (K, R) out of 84 maps, so two different seeds can draw the same map; specialists and history draw many values per fact and do not collide in practice.
