Optional hosted judge adapter, label-gated (#53, epic #10; no schema change; 2026-11-18).
`HostedJudge` implements the `Judge` trait over a `HostedTransport` (a trait, so tests use a fake and no network is touched). It is off by default (`HostedConfig::default()` has `enabled: false` and no ceiling). The label gate runs before the transport is called: text is sent only when the judge is enabled, the message's label (`ReviewItem.from_label`, the label it was posted under) and the configured ceiling are both in the label chain, and the message label is at or below the ceiling, as D4 says. A missing, empty, unknown or higher label, an unset or unknown ceiling, and any transport error all return `Defer`, so the item stays queued for the rules, a local judge or the reviewer.

    Not done: nothing builds a `HostedJudge` yet. The ceiling is a floor in D4 (set once at onboarding, no agent may edit it), so the setter, the onboarding question, a real HTTP transport and `klatch judge run` choosing a judge are separate work; they are ticketed (#870, #871), and the setter's act must be added to the `ForbidFloors` list when it exists. The ticket text says content "above" the gate never leaves, D4 says "at or below" is allowed; the code follows D4, so the ceiling label itself is allowed (#872).
