Union merge for append-only registries (#1065)

Part of the collision-avoidance work (#1064). Measured on origin/main over three days, `proto/AUTHZ-AUDIT.md` was the most touched file (12 commits, hand-resolved three times) and the `mod x;` registries were next. Their conflicts are always "both sides added lines", so the root `.gitattributes` marks them `merge=union`: `proto/AUTHZ-AUDIT.md`, `proto/klatch/src/domain/mod.rs`, `proto/klatch/src/gateway/mod.rs`, `proto/klatch/src/gateway/gateway/tests/mod.rs` and `proto/klatch-bench/src/scenarios/mod.rs`. Git keeps both sides instead of stopping. Files with code bodies stay out (`admin/mod.rs`, `klatch-bench/src/lib.rs`, `harness/mod.rs`): a union of two edits of one line would be wrong there and nothing would flag it.

The driver is built in to git, so no setup. It applies to merges git runs itself: a local `git merge`, `proto/scripts/pr-sweep` (its real merge and its `git merge-tree` pre-check) and the integrator. GitHub ignores `.gitattributes` merge strategies, so `mergeable_state` can say `dirty` while the local merge is clean; the integrator merges locally and pushes, and nothing relies on GitHub to resolve.

A union merge cannot tell an added line from two edits of the same line, it keeps both. So each file has a check for that: `tests/authz_audit.rs` fails when a table row key (the first cell, in backticks) appears twice in one section; a duplicate `mod` or `pub use` line does not compile; a repeated scenario fails the unique-name test in the bench. The "Gaps found and ticketed" table starts with prose, so its rows are keyed by the first ticket number in the last cell (#1072): a row that says `#835` and a row that says `fixed in #835 (...)` are one gap, and two rows with the same key fail `gap_rows_are_unique_by_ticket`. A row with no ticket number is keyed by its whole last cell. A second ticket in the last cell does not key the row (the `release_crossings` row names #834 after its own #836), and `SHARED_GAP_KEYS` in the test is the explicit, commented allowlist for a legitimate shared first ticket (empty today). This was chosen over moving the table to its own file because all 13 rows already end in a ticket or a "fixed here" note, so no row was rewritten and no reader changed. The test `the_replayed_union_merge_of_two_gap_edits_is_caught` feeds it the real `git merge-file --union` result of the recorded #1028/#1029 replay (`tests/fixtures/authz-audit-replayed-union.md`, commit 62157c2), where the #835 and #836 rows each appear twice. `proto/scripts/test-merge-union.sh` (in the gate) builds temp repos: two branches each adding a row at the same place merge cleanly keeping both; two branches editing one row merge into two copies and the duplicate check fails; a file without the attribute still conflicts. Replayed on the recorded #1028/#1029 AUTHZ-AUDIT conflict, the merge is clean with the attribute and conflicted without it.
