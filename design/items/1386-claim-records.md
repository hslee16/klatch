Claim events are recorded as counts and class, so conflicts and how they ended are countable (#1386; schema 39; 2026-11-22). The review of the live store found 102 claim notes and no record of conflicts, releases, expiries or hold times, and the dogfood protocol (#1378) had to fall back on a free-text `claim-conflict:` post. The store now keeps one small row in `claim_events` for each event on the existing claim paths: `granted` (a new hold; a renewal by the holder is not an event), `refused` with a rule word from a fixed vocabulary (`same-path`, `overlap`, `shared` when a shared scope is involved, `deadlock`), `released` with who released (`holder`, `session` for the end of the session, `anchor` for a work item reported done, `removed` for a removed member), `expired` (the holder's lease lapsed; recorded when the existing sweep or a release path removes the lapsed row, so a lapse nobody sweeps is counted when it is) and `takeover` (a grant over a claim that lapsed under another member, written in addition to the `granted` row). A row holds the moment, the room, the event word, the claim class (`file`, `ticket`, `ask`, `other`, from the name prefix alone), the reason word, the seconds the claim was held (0 when its start is unknown) and, on a grant that ended a refusal, the seconds waited. It never holds a claim name, a member, a reason or a note, so the room is the only name in it and a sealed room's claim names cannot reach a count.

    Recording changes no claim semantics, TTL, conflict rule or message: it runs inside the transaction the claim operation already holds, so no lock is held longer, and a recording failure is swallowed and counted (`SqliteStore::claim_record_errors`), never returned. A refusal is matched to its later grant through `claim_conflicts_open`, working state that holds the claim name like the claims table does and is never read by the report: a refused member's wait window is two minutes, a handled conflict can take hours, and the first refusal keeps its time. Retention is both an age cap and a row cap, applied as each event is written: rows older than 30 days (`CLAIM_EVENT_MAX_AGE_SECS`) are deleted and at most 20,000 rows (`CLAIM_EVENT_MAX_ROWS`) are kept, the newest; open refusals older than 24 hours are dropped. A new default trait method `ClaimStore::release_at` carries the clock to a release that has no note, so the hold time can be recorded; the gateway `release` uses it and every other store inherits `release`.

    `klatch admin stats` (and `--json`, under `claims.history`) prints claim grants by class, refusals by rule, releases by class and by who released, expiries by class, takeovers, conflicts handled (a refusal followed by a grant to the same member for an overlapping name: the count and the median seconds waited) and the median hold time with how many holds it covers, within the `--room` and `--since` window. A store written before schema 39 reports an empty history. The same no-text guarantees apply: the new queries read counts, class and reason words that pass `vocab`, and the no-leak test runs every option combination over a store with real claim traffic under names that carry a marker. The 2026-11-23 free-text `claim-conflict:` post is removed from DOGFOOD.md.
