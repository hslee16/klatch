The stdout guard compares by session, not inode (#1285; no schema change; 2026-11-22). The acts that print stored text need standard output to be the terminal the prompt appears on. When standard input is a terminal, standard output must be that same device. When it is not (a pipe, a file, `/dev/null`), the prompt is on `/dev/tty`, a different node from the real device, so comparing inode and rdev refused honest use; the check is now that standard output is this process's controlling terminal (terminal, same session), which is the terminal `/dev/tty` opens. Standard error must still be that terminal or `/dev/null`. The refusal text names standard output and standard error.

`admin rate-limit --list` joins the guarded acts (it prints member names and limits). The room settings (`room-require`, `room-stale`, `room-ask-lease`) are not added: they only echo the caller's own argument and print no stored text.
