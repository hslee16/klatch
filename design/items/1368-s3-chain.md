Scenario S3 of the coordination bench measures a dependency chain with one handoff, and what a blocked agent does while it waits (#1368; no schema change; 2026-11-23).
Epic #1362 needs the scenario for waiting and handing over. F3 `chain` is a standard library inventory reader that three agents build in sequence: a makes a schema file and starts the bin codes, b cannot do the loader until the schema file exists, c finishes the bin codes and does the report, which needs b's loader and c's own work. Agent a is then reassigned and must hand over to c. a alone is told (in its task text, nowhere in the repository) a quirk: bins with one legacy prefix were relocated, so their canonical code has another prefix and the number plus an arbitrary offset. The prefixes and the offset come from a fixed seed in `gen.py` and cannot be guessed, so c's result is right for the legacy bins only if the quirk crossed the handoff, as a checkpoint, a message or a note in the repository.

The hidden checker `checks/chain/` tests each of the four steps alone against the reference solution (the loader with the reference schema file in place, the report with the reference loader, normaliser and schema, and the loader also on a different column layout so it cannot have the columns written in). It prints steps correct (0 to 4), the quirk honoured (yes or no), the lost work at the handoff (a's published schema file or `parse_bin` that met their contract in some commit and fail on the final main, dropped or redone differently), whether each step was first committed with its input in its tree, and a merge state. Tests run it on the reference and on variants that must fail (quirk ignored, wrong offset, partial work dropped or redone, a step out of order, a loader with the columns written in, broken interfaces, conflict markers, a failing visible test).

The blocked agent's idle behaviour is measured from its stream by `chain.py`, not by the checker: a turn is one assistant message; the dependency is seen at the first turn whose tool result shows the file (a message that only names it does not count); idle turns are blocked turns whose every call is a poll (`sleep`, `klatch wait`, reads of the room or board, `git fetch`, `pull`, `log` or `status`, `ls`, `test`) or that have no call; guess-build turns write the dependent file before its input exists; wasted turns are their sum. Whether a claim moves with a handoff (#539) is recorded for the K arms from the streams (what a claimed, released, kept, and what c claimed or was refused, and the checkpoint and handoff messages), not graded; whether klatch itself moved or freed a claim or an ask needs the store, which the harness does not export yet, so that field is null with a note. The scenario file `scenarios/s3.json` holds arms B0 B1 K1 K2, N 10 per arm at M0, the SPEC 8.1 caps (2.40 USD a run, 40 USD for the suite) and the metric definitions; the harness runs `chain.py` for a scenario that names it. The fake agent gained a `poll` step. Nothing here ran a model or spent money; the real run, the budget approval and the arms review (#1365) remain, and the ticket closes when M0 results exist.
