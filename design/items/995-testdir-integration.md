Integration tests and the bench make their scratch directories with TestDir (#995; test and bench only; no schema change; 2026-11-20).
The integration tests under klatch/tests and the bench crate (klatch-bench/src) made temporary directories by hand, with cleanup on the happy path only and no size cap, because the `pub(crate)` `TestDir` of #812 was out of their reach. Each of those crates now compiles `klatch/src/store/test_dir.rs` into itself with a `#[path]` attribute (the way #812 did for the binary crate), so there is one source for the guard and no new crate: `tests/common/mod.rs` includes it for the test files that use `common`, the other test files that need a directory include it directly, and the bench library includes it as a private module. `Home` and `Setup` in `common`, the bench `World`, the fault-round `Home` and the judge-eval working directory all hold a `TestDir` and so are removed on drop, also on a panic. A bench round that finds a violation calls the new `TestDir::keep` to leave its store behind for a look, as before.
The `TestDir` self tests moved from `test_dir.rs` to `test_dir_tests.rs`, so the crates that include the guard do not each run them again. The scan test `no_unit_test_makes_a_temp_directory_by_hand` now covers klatch/src, klatch/tests and klatch-bench/src with the same allowed exceptions, plus two lines that only read where the temp directory is (scrubbing it from a message, and checking a path is under it). It was red against 21 sites first. The `linux_*.rs` test files were converted the same way but need a Linux host with the keyring or no-bus setup, so they were not run in the macOS session that made the change.
