Scenario S9 of the coordination bench: a late joiner and a resumed agent, durable record versus reading the git log (#1374; no schema change; 2026-11-23).
Epic #1362 needs the scenario that judges the durable record and the late-joiner briefing (#1409): a new agent joins in the middle of a job, or a session resumes after its context was cleared, and must get up to speed. F9 `history` is a small standard library project, `parcelkit`, at the middle of an eight-ticket build; the harness gets a prebuilt repository (`"prebuilt_history": true`: `setup.sh` learns the arm from `COORDBENCH_ARM` and runs `build_history.py`, which makes 25 commits by three earlier agents with fixed authors, dates and messages, so commit ids repeat) instead of its own first commit. One late joiner, `dana`, takes ticket 7. Its correct implementation depends on three decisions drawn from a fixed seed (`gen_facts.py`, committed output, checked by a test): a file name tag, rows per page and a tare. They are in the record and in no code or visible test (a test proves no value appears in any file of the checkout), none is a conventional default, and two were decided and later superseded, so reading only the early part of the record gives a stale value.

    What is where, so that the information is the same in every arm and only the medium differs: the commit messages carry all five values (three current, two superseded) in every arm. B0 has nothing else. B1 adds TASKS.md in the harness's board format and DECISIONS.md, committed by the earlier agents along the history. K1 adds the prebuilt room history, about 60 messages by `ada`, `bo` and `cy` posted through the klatch binary into the run's temporary store before the agent starts (claims, asks and answers, five `decision:` asks closed `ok`, revisions that name the ask they supersede, checkpoints, a handoff), with no hooks; K2 adds the hooks, and with #1409 the briefing. The handoff note in each medium points at that medium with the same strength. The earlier members are not part of the run's team; only `dana` runs, and the common prompt is unchanged (it still says the others are running now, which the job text corrects).

    The resume variant (`--variant resume`, records under scenario `history-resume`, never pooled with the join runs): the agent's first session is cut after twelve turns by the driver's turn cap, and when it exits the harness starts a second session with the same name in the same clone with the job text again and a short note that its context was cleared and it was in the middle of ticket 7. Nothing else is carried over. The fake driver models it as a second process with the same name (`--session 2`, steps under `NAME#2`). A cut session's nonzero exit is not a crash. Stated gaps: a restarted `claude -p` session is a fresh start, so the briefing's `after compact` header does not appear and a model-written compaction summary is not modelled; the stream has no timestamps.

    The hidden checker tests the ticket and each fact against an oracle and classifies each fact as ok, stale (a contradicted decision), guess, wrong or missing; it finds duplicated work by behaviour (a new function with a finished helper's name or its answers on the same inputs, or a finished module rewritten), and gives four units. `correct` also needs no duplicated work, no conflict markers and passing tests. The metrics come from the stream and git, never from the agent: history reads by kind (git log, the board files, the klatch reads), whether the room was used before the first edit, whether a briefing was shown, and the first correct contribution, defined as the first commit of the agent whose tree passes the checker's `--tree` mode, found by replaying the agent's commits in order and tied to the stream by the commit id in the `git commit` result (else by position); turns and cumulative tokens up to it are reported across both sessions. Limits found: the first correct commit needs a commit to exist (an agent that never commits has none); with `git commit -q` the id is not in the stream and the position is used; K2 shows the briefing only once #1409 is merged; N is 10 per arm per variant by this ticket's proposal (S9 is not in the spec's cost table) and no real run has been made. The ticket stays open until M0 results exist.
