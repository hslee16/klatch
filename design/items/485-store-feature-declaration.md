A store declares the optional features it keeps (#485; no schema change; 2026-11-19).
The area traits give many methods a default that answers "nothing" so a backend can be written a little at a time. The security-relevant ones already default to an error (the earlier #485 change); the rest (sessions, member notes, mute, pruning, wait positions, claim notes, anchors, claim lifecycle, asks, reviews, credentials) still succeed silently, so a backend that never writes them compiles, runs and loses the feature. Each group is now a `Feature`, and `RoomStore::features` is a required method with no default, so a backend cannot avoid saying what it keeps. `Gateway::new` panics, naming the missing features, for a store that does not declare them all: a backend defect found the first time it is wired, not a run-time condition (84 construction sites make a `Result` return too invasive). `conformance::features::every_declared_feature_works` runs the existing conformance tests of each declared feature, so a backend cannot claim one it does not keep. The in-memory spike declares none and is therefore refused by the gateway, which is the point; SQLite declares all and is unchanged.

  Design choices: the groups are coarse (eleven) rather than one per method, so a declaration stays reviewable. Park and unpark sit under member notes, and the review queue under reviews; both are backed by shared conformance tests (#956).
