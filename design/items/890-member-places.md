Who and the board show where a member was observed; the router orders by repository (#181, #890; no schema change; 2026-11-18).
**What shows.** `who`, the board and the wire `who` method carry, for a member whose attributes klatch has observed (the `member_attrs` row of the design item for #181), the derived repository id (`git:<name>-<hash>`, absent outside a repository) and the short directory name: the last path component, at most 40 characters, never the path. **Why only that (zero trust).** A full path can carry a user name, a client name or a layout the reader has no business with, and everyone who can read a room's member list could see it; the repository id and a short name are enough to see that two members work in one repository and to tell their checkouts apart. Both are observations by the host: a directory can name another repository's git directory, so a member can make its value equal another's, which is why nothing reads them as authority (no clearance, room or access follows from sharing a repository). They are filled by `with_places` from the store after the same `admit` that guards the member list and the board (`Who`, `Read`), so a reader the room's label refuses sees neither (`member_places.rs`); the row is in `proto/AUTHZ-AUDIT.md`. **Router (#890).** When more members qualify for an ask's room than `MAX_INVITES`, members whose observed repository equals the asker's come first, then the rest by name. The attribute only orders the members the claims and operator rules already chose: a member of the asker's repository with no claim on the topic is not invited (a test), and with no attributes known the order is by name as before. **Delivery and claims (not changed, ticketed).** A coding session's scope is already derived from the same repository id when none is declared (`ensure_member_scope`), so delivery and claims already follow the derived repository for them; a declared scope (flag or `KLATCH_SCOPE`) still overrides it. Replacing a declared scope by the derived repository would change which claims collide for a member that declared one, a behavior change in conflict detection that this item does not make; it is a separate decision (ticket). **Member name as key.** The name stays the key of every table; a change of key would touch every table, claim, message and cursor, and the done-when of #181 (two sessions in one repository are two members sharing a repository attribute, same-named sessions stay distinct, a rename keeps one member, a fake git layout test) is met by the stable member id beside the name (tests in `scope/attr_tests.rs`). **Tests:** `gateway/tests/member_places.rs`, `domain/board/tests.rs`, `domain/router.rs`. They were written before the code and failed to compile first (the field and function did not exist), not on an assertion.
