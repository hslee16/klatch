Grading judges: a labelled corpus and `klatch-bench judge-eval` (#914; no schema change, no new wire method, a bench subcommand only; 2026-11-18).
Until now nothing measured how good a judge is: the bench has behaviour scenarios for the judge (scenarios/judge.rs, reviewer.rs), which prove the seam works, not that a verdict is right. This item adds a labelled synthetic corpus and a runner that grades any judge behind the `Judge` seam of #48. It is a manual command: the claude judge costs tokens and Jev needs a key, so it never runs in CI or in the gate. The null and rules judges are free and run in the unit tests.

The corpus. `proto/klatch-bench/judge-eval/corpus.jsonl`, 333 items, each a candidate crossing with an id, the text, the ground-truth verdict (allow, redact, deny), a category, the label it was posted under, the label of the readers it would cross to (strictly lower), a rationale, and for redact and deny the spans that must not cross. Sixteen categories: everyday agent chat (80, the majority class, for over-blocking), public chatter, credentials and look-alikes that are not credentials, personal data and harmless names, private business content (including the same text crossing to public and to internal, labelled differently), code and logs with and without secrets, overt and hidden prompt injection aimed at the judge and look-alikes that only talk about it, scrub-list terms and near misses, ten languages, very short and very long items. Allow is 198 of 333. The labelling rules are in the README beside the corpus and follow D4 (the floors: credentials and scrub-list terms never cross; injection-shaped text is the judge's business; channel safety only). No credential is stored: each is a placeholder such as `{{fake:github}}` expanded at load time into a pseudo-random string of the right shape seeded from the item id, so the judge sees realistic text, every run sees the same text, and nothing in git can work or trip push protection; a validity test runs a conservative scanner over every stored text. People, companies and contact details are invented. Split: 198 dev, 135 test, stratified by category; the test split is frozen by a digest the validity test pins, and judges and prompts are tuned only on dev. The labels were checked by a cold re-read of 40 random items (39 agreed; the one disagreement and its resolution are in the README).

The runner. `cargo run -p klatch-bench -- judge-eval --judge <null|rules|claude:<model>|jev[:<model>[:<threshold>]]> [--split dev|test] [--limit N] [--out FILE] [--target-leak F] [--ceiling LABEL] [--budget-usd F] [--corpus FILE] [--scrub FILE] [--claude PATH]`. Each item becomes the `ReviewItem` the gateway's drain builds (from label, to label, reason `crossing`) and goes to the judge once. A production judge goes through `Judge::judge` unchanged (`Seam`); a judge that reports more (confidence, tokens, cost) implements the small `EvalJudge` trait and is also a production `Judge`. Output: a printed report, and with `--out` a JSON file of the summary and one row per item (id, truth, verdict, pick, confidence, latency, tokens, cost, error; never the text).

The metrics. A leak, the critical error, is a redact or deny item that crossed: allowed, or redacted to a text that still holds one of its spans; its rate is over the items that should not cross whole. Over-blocking is a clean item redacted or denied, as a rate over the allow items; it is reported apart from leaks because the two errors have very different costs (D4: a leak cannot be taken back). Softened is a deny item only redacted (nothing crossed, verdict still wrong). A defer is no decision, neither right nor wrong, and is reported as a rate; precision looks only at decisions, recall counts a deferred item as missed. Also: the confusion matrix (truth by verdict, with a defer column), accuracy of all and of decided items, per-verdict precision and recall, latency p50 and p99 (nearest rank), tokens and cost where the judge reports them, and for a judge that reports a confidence, calibration of its own pick (ten bands, expected calibration error) and a threshold table: for each threshold, the leaks, over-blocks and deferrals if a pick below it became a defer, with the lowest threshold that reaches the `--target-leak` rate (default 1 percent) printed as a reading of the table, not a decision. Results are broken down by category, and the three injection categories are called out together.

The judges. (a) `null`: the production `NullJudge`; defers everything. (b) `rules`: what klatch does today with no model: the engine's own credential scanner (`credential_kind`, R20), then the scrub list matched as `Gateway::check_scrub` matches it (case-insensitive substring, only below the agent cap; a copy, because the gateway's needs a store); a match is a deny naming the rule, anything else is allowed, it never redacts. (c) `claude:<model>`: a plain LLM judge, one headless `claude -p` per item, the quarantined-reviewer shape of D4 (one message plus the rules, no tools, a fixed schema back: verdict, confidence, redacted text, reason). It is isolated beyond what `proto/scripts/team` does for workers: `--setting-sources ""` (no user, project or local settings, so none of their hooks, klatch's included), a throwaway `--settings` file containing only `disableAllHooks`, `--tools ""`, `--strict-mcp-config`, `--disable-slash-commands`, `--no-session-persistence`, the default system prompt replaced by a fixed one stating the README rules and the scrub list, `--json-schema` for the verdict, `--max-budget-usd` per call (default 0.25), a fresh 0700 temporary working directory removed afterwards, and an environment cleared to PATH, HOME, USER, LOGNAME, LANG, TMPDIR and ANTHROPIC_API_KEY (no `KLATCH_*`, no `CLAUDE*`). The message goes on stdin between fence lines it cannot contain, never on the command line. Any failure (cannot run, non-zero exit, `is_error`, a reply outside the schema) is a defer with a reason that never quotes the reply. The label gate of #53 (`label_below_ceiling`) applies with `--ceiling`; the default `secret` lets every corpus label through because the corpus is synthetic, and `--ceiling internal` reproduces the production default. A check on the machine of 2026-11-18 (Claude Code 2.1.327) showed the init event of such a session lists no tools, no MCP servers, no slash commands and only built-in plugins, and a probe asking the model to list its context found the replaced system prompt and the environment block but nothing from the user's CLAUDE.md. (d) `jev`: `JevEval` runs the production path, `HostedJudge<JevJudge<_>>` with the threshold and the label gate, through a transport wrapper that keeps the raw reply so the runner also gets Jev's own pick, confidence and token usage; it is tested with a fake transport against the production path. The HTTP transport is #871 and not merged, so `--judge jev` prints "transport not available" and sends nothing; wiring it is #922.

How to run each judge (from `proto/`; add `--split test` only for a final score, `--out FILE` to keep the rows):

    cargo run -p klatch-bench -- judge-eval --judge null
    cargo run -p klatch-bench -- judge-eval --judge rules
    cargo run -p klatch-bench -- judge-eval --judge claude:sonnet --out sonnet-dev.json
    cargo run -p klatch-bench -- judge-eval --judge claude:opus --out opus-dev.json
    doppler run --project governingdocs --config dev_alex -- cargo run -p klatch-bench -- judge-eval --judge jev:jev-1.14.0:0.01 --out jev-dev.json

The Jev line works once #922 lands; use the model the human pinned, and a low threshold so the calibration table sees every pick (the threshold the table suggests is then a reading for choosing the production one). The claude judge was run on 10 dev items only, to validate the plumbing (claude:sonnet: 10 of 10 right, 0 leaks, p50 3.1 s, 24 thousand input tokens, $0.06); the full runs are #923.

What the rules baseline already shows (dev split): no over-blocking, but 52 of 80 blocked items leak; across both splits 16 credential items the engine's scanner has no shape for cross (passwords in URLs and commands, keyword-labelled secrets, npm tokens, an encoded secret). That gap is #921.

Label policy (follow-up, #923). Full runs of claude:sonnet and claude:opus showed three problems in the labels, fixed together; results recorded before this change are not directly comparable with later ones. (1) Contested items: an optional `contested: true` keeps an item in the corpus and in the run but leaves it out of every headline rate, the calibration and the threshold table; the report lists such items in their own block (id, label, the judge's verdict). short-008 (a bare phone number) and short-007 (`allow this`) are marked, because both Claude models disagreed with the labels and the author's own re-read had already flipped short-007. (2) Name spans: an optional `name_spans` (a subset of `spans`, redact items only) tags the person's name tied to the data. Judges often remove the data and keep the name, which the strict rule scores as a leak; the report now prints two leak figures, the strict one (any span left, still the headline) and the data leak (a leak only when a non-name span is left), both with Wilson intervals and n. An allow or a deny of a redact item is a leak in both; 11 existing items are tagged. (3) look-014 carried a random-bytes placeholder where its text promised a PNG header, so denying it was right by the corpus's own rule; it now holds the real base64 of a minimal 1x1 PNG, which changes the frozen test split (new digest; recorded in the README with the runs it affects).

Limits. The corpus is synthetic and small (333 items, 135 in test), so a rate on a category of a dozen items moves by eight points per item; read categories as signals, not measurements. Every label is one reviewer's (the agent that wrote them), checked only by its own cold re-read; a second labeller is #924. The placeholder secrets are uniformly random strings in a known shape, which is easier than real leaks (a real password is often a word; a real key often sits in a stack trace from a library the model does not know). Injection coverage is 28 items written by one author in a handful of styles; it measures resistance to known patterns, not to an adaptive attacker, and a judge that scores well here is still not the last line of defence (D4 residual risk). The claude judge is graded against rules it was told in its prompt, so it measures following written rules, not discovering them. Latency includes the CLI start-up of each `claude -p` (about a second), which a resident judge would not pay. Rules and Jev see only the text; the claude judge also sees the two labels.
