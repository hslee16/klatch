The dm nudge and reply hint also reach an agent that reads through wait and read (#1209; part of #1183; no schema change; 2026-11-21).
The audit of #1183 found that an agent which hears of messages through `klatch wait` or `klatch read` has them consumed before its hook runs, so the hook digest is empty for it and the dm nudge (#1190) and reply hint (#1192) never reached it. **Design chosen:** `wait` and `read` print the same two fixed lines themselves, as separate trailing lines after the message rows (and after the "more messages not shown" line), never changing an existing line. The alternative, making the digest remember what wait or read handed over, needs state the digest does not have and changes who is told what in the hook; printing from the command that consumed the messages needs none and is derived from the room. **The lines:** `klatch: dm from PEER: reply with klatch dm PEER "<text>"` when the room is a dm with the caller in it; `klatch: you and PEER exchanged N messages in ROOM; for a longer exchange use: klatch dm PEER "<text>"` when the returned messages carry the message that crosses the threshold of a long two-member exchange in a room of three or more with no dm between the two. The words are the hook digest's own: `domain::dm_reply_hint` and `domain::move_to_dm_nudge` build them for both, and `domain::crossing_exchange` is the one rule (built on `exchange_run`) that the gateway digest and the commands both ask. Names are validated, the rest is a count and a room; no message text. **Once per pair per room:** the crossing message is handed over once (wait and read consume what they return), so the line is printed once, as in the digest; a later message of the same run, or a run broken by a third member and begun again, counts afresh. **Only when consumed:** `wait` with `--peek` or a filter, and `read --peek`, leave the messages unread, so the hook digest still shows them and carries the help; the commands print nothing for them, which avoids a second copy. **Bounds and formats:** the added line is a fixed template plus at most two member names and a room name, one line per room read, and is printed after the capped rows, so the message cap of `wait` and the history window are untouched; message rows still start with `[`, the new lines start with `klatch: `. The client reads the room with `who` (three or more members; two for a hashed dm name) and `history` (the newest `DM_NUDGE_WINDOW` messages), both already allowed to a member who can read; a room it cannot look at adds nothing. **Limits:** a message the hook digest showed first is handed again by a later `wait` or `read` (the hook leaves the read cursor alone), and the client cannot see the hook position, so that second hand-over prints the nudge a second time; a hook position is not exposed by any operation, and exposing it would change the wire. Filed as #1211.
