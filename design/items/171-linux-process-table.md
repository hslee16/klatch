Session discovery is tested against a real Linux process table (#171; no schema change; 2026-11-22).
The ancestry walk, the liveness check and the `ps` reads run on Linux in a test that starts a fake harness (a symlink to the shell named `claude`) with a real child, a fixture registry in a temp directory, and `PsTable`: a descendant finds the session, an unrelated process does not, a reused pid is stale, `claude bg-spare` is the harness, a cut or foreign program name (`claude-code-sandbox`, `node`, `claude-helper`) is not, and a record from another pid domain is never live. The tests are `cfg(target_os = "linux")`, so they run in CI's ubuntu job and are absent on macOS. `proto/linux-discovery/run.sh` runs them in a Debian container on any machine, reusing the `linux-keys` image, with the repository mounted read-only and nothing of the user's entering the container.

What stays unobserved is a registry written by a real Claude Code on Linux (its pid domain name, its real `comm`); that is ticket #797 and these tests do not close it.
