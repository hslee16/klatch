New design items are fragment files named by ticket, and the release numbers them (#807; no code, schema or wire change; 2026-11-18).
Every parallel pull request appended the next free item number to DESIGN.md, so each merge made the others renumber and rerun the gate, and in waves 1 to 3 three PRs took item 98, two took 104 and the sweep once duplicated item 97. Now a new item is `design/items/<ticket>-<slug>.md`: line 1 is the title (the text inside the bold), the rest is the body. The name carries the ticket number, never a sequence number, so two PRs cannot collide. `release/design-fragments.sh assemble` appends the fragments to DESIGN.md at release with the next numbers in ticket order and deletes them, as `release/changelog-fragments.sh` does for the changelog; `check` (run by the gate) rejects a badly named, empty or bodiless fragment, and `collect` shows the result without changing anything. Until assembly, a reference to an item uses the ticket ("the design item for #NNN"); assemble prints which number each ticket got so the references can be changed. Items 1 to 104 stay as they are because code comments cite them by number, and a PR that still appends a numbered item keeps working because the sweep's docs resolver is kept.

Rejected: a number reservation by claim (`design-item:<N>`), which needed an agent to hold DESIGN.md or a claim for a long time and still clashed when a claim was missed.
