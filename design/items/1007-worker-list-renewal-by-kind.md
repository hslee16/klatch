The worker listing finds the last renewal by kind and member, not by scanning the newest audit entries (#1007; no schema change; 2026-11-20).
`klatch worker list` used to look for each credential's last renewal in the latest 10000 audit entries, so on a busy store an older renewal read as never (#948). The store now has `last_audit_ts(action, target, since)`, a filtered read that returns the newest audit entry of one action on one target at or after a time, however far back it is; the listing asks it for `renew-credential`, the member and the credential's issue time, so an entry from an earlier credential is still ignored. The default is an error like the other audit methods (#485). No operation is added or changed: it is still `admin_credentials`, guarded as before, and the guard runs before the store is read, so `proto/AUTHZ-AUDIT.md` needs no new row.
