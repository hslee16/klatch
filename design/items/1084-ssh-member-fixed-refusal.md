A member-fixed refusal on an ssh session is kept and counted by the breaker (#1084, follows #107; no schema change; 2026-11-21).
#107 refused a request that claims an identity on a `serve --stdio --ssh-key` session with the rule `member-fixed`, but the refusal was made in the session loop, which has no way to keep a refusal row, so `klatch admin refusals` did not show a forging attempt and the breaker did not count it. **Shape:** `Gateway::note_member_fixed(who)` keeps the refusal through the same path as every other refusal (`note_refusal`: a row, then a look at the breaker). The `Backend` trait the session runs over has one new method, `note_member_fixed`, implemented by `Gateway` and by `SharedBackend` (which sends it to the owner thread), and the session calls it just before it answers the refusal. `member-fixed` joins the breaker's safety rules, so five of them in five minutes stop that member everywhere, as five `clearance` refusals do. **What the row holds:** the member the key is mapped to, an empty room, the operation `session` and the rule. It never holds the request method, the field that claimed an identity or the name that was claimed: those came from the peer, and the refusal text to the peer already leaves the name out. **Classification:** the method is OWN_RECORD (it records a refusal about the caller itself and grants nothing) and is allowed after a credential ends, because a session whose credential ended still has a refusal to keep. **Limits:** only request `params` are inspected; the decoder drops extra top-level frame fields, so they have no effect and are not refused, as before. The mapping is still checked at start only (#1083).
