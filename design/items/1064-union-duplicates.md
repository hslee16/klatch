A line twice in a union-merged file fails the gate (#1064; no schema change).
The ticket (owner direction, umbrella of #1065, #1066, #1067) asks to avoid merge collisions structurally: new features add files instead of editing shared ones, a shared list unavoidable is one entry per line so a union merge is safe, and "a check must catch the mistakes a union merge can make (duplicate entries)". Fragments for the changelog, design items and research notes, the local integrator merge and the `merge=union` registries already exist; the missing piece was a check for the duplicate a union merge can leave (both sides add the same line, git keeps both, nothing conflicts).

The smallest design is `release/check-union-duplicates.sh [root]`, run by the gate, with tests in `release/test-check-union-duplicates.sh`. It reads every tracked file whose `merge` attribute is `union` (`git check-attr`, so globs count; no .gitattributes means nothing to check) and reports a repeated entry as `file:line: text (first at line N)`, exit 1, with the fix (delete one copy). The rule is per file type and conservative, only list entries count: in `*.rs` the one-line registry entries (`mod x;`, `pub use a::B;`, `x::all(),`), in `*.md` list items and non-separator table rows, in other files every line with a letter or digit that is not a `#` or `//` comment. Blank lines, headings, fences, rules and prose never count. Known legitimate repeats go in `release/union-duplicates.allow` as `<path> @@ <exact line> @@ <reason>`; an entry without a reason is an error. It is cheap (one awk pass over four files) so the gate runs it; it is not added to the keeper.

The TASKS.md board of the coordbench B1 arm is seeded with `merge=union` inside the run clones, not in this repository, and is left alone. On origin/main the check found no duplicate, so no committed file changed and the allowlist is empty.
