A done status clears when its member returns, shows its age, and `available` is reserved (#260, #223 in part; schema version 32; 2026-11-19).
The human decided on 2026-11-18, on the ticket: options (a) auto-clear `done` when the member posts or claims again, (c) show a status age on the board ("done 12m ago"), and (e) the reserved word `available` that a member sets when it is free for work; (b) an explicit clear and (d) a lifetime were not chosen. This supersedes item 4 of section 25.7 ("no automatic clearing") and settles the two words in #223 (the wider vocabulary stays free text).

    Clearing (a). A successful post or claim by a member clears its stored status when that status starts with `done` (`Store::clear_done`, run by `Gateway::post` after the message is stored and by `Gateway::claim` after the claim is taken). Any other status stays, a refused post or claim clears nothing, and a release or a read does not count as returning. The board's offers then read the member as present again, so an `offering:` it posts after returning shows; an offer it made before saying `done` was already ended by the `status: done` message and is not revived (post it again). The SessionEnd hook sets `done session ended` and does not post afterwards, so a finished session stays done. A member that runs `klatch status <room> done` after posting its `status: done` line keeps the order the convention teaches (post, then the command), so the command is the last write.

    Age (c). `members.status_ts` (schema version 32, migrated in place, default 0) holds the time the status was set; `Store::set_status` writes it and `clear_done` resets it. `who` and the board print `status: done (12m ago)`; a status set before the migration has 0, which means unknown, and prints without an age. The age is the largest whole unit (`45s`, `12m`, `3h`, `2d`). The wire `who` response carries `status_ts` when known (additive; PROTOCOL.md). A status that comes only from a `status:` message (the board's fallback) carries no age.

    `available` (e). `available` is a status klatch reads as "not done": a member with it keeps its offers on the board and counts as reachable for the asker's note (item 67). It needs no code beyond what `done` already distinguishes; what is new is that it is named, taught in the convention text and listed as the convention word `status: available` in CONVENTIONS.md, with a test that the code reads it so. `busy`, `away` and the rest stay free text with no meaning to klatch.

    Convention text. The text shown at session start teaches `available` and the clearing in one clause. It was at 2772 bytes under its 2800 byte bound, so two earlier clauses were shortened (the claim renewal sentence and the `partial #N:` sentence) instead of raising the bound; the full wording stays in CONVENTIONS.md.

    Not built. An explicit clear (b): the status text still cannot be empty, and `available` is the way to say "not done". A lifetime (d): a status does not lapse by itself; presence aging and the SessionEnd hook cover members that are gone. The card (`klatch card`) does not show the age.
