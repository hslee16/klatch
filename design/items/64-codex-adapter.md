The Codex CLI adapter: capability levels traced to the #548 findings, and what stays unverified until a live Codex login (#64, epic #12; no schema change; 2026-11-18).
`harness::Codex` was already registered in `conformance::adapters()` and passes the suite (rules 1 to 4). #64 makes its levels honest. **Native only where #548 observed it:** `session-identity` (hook stdin carries `session_id` equal to the stream's `thread_id`, RESEARCH-NOTES 49.3; native only when the hooks are trusted, 49.7) and `headless-worker` (`codex exec --json` ran, 49.3). Both name `RESEARCH-NOTES.md` as their basis, and `Codex::ground(c)` gives for every capability the sentence and section that back its level. **Changed from the paper adapter:** `context-injection` and `pre-action-enforcement` were native when trusted, and `permission-mode` likewise; none was ever seen (the 401 stopped the turn before model output, klatch installs no PreToolUse hook for Codex, nothing carries the permission mode), so all three are degraded now. `wake` (no `codex queue` on 0.147.0, async hooks skipped) and `pull-path` stay degraded. A room that requires any of those refuses or flags a Codex member, by design.

**Verified-harness join (#877) stays on the generic floor for Codex; this is a documented gap (#884).** The evidence is a live process named `claude` plus a registry record whose pid and start time match. Codex has no registry record and klatch has no Codex registry hook (`init --codex` installs SessionStart, UserPromptSubmit and PostToolUse only), so there is nothing to match a process named `codex` against, and a Codex session is named only by its hook `session_id` or `CODEX_THREAD_ID` (same-user, not a verified process). `runs_claude_code` therefore keeps failing closed for Codex, tested in `src/identity.rs`. To lift it later: a Codex SessionStart hook that writes a registry record and a walk that matches it, with the same rules. No new command or wire method, so no new AUTHZ-AUDIT row (the `join` row now says Codex is the floor).

**Tests.** `src/harness/negotiate.rs` (native set is exactly the observed two; every unverified claim is degraded even when trusted; every ground names a section; this file has a row for each unverified claim) and `conformance::every_registered_adapter_passes`. The negotiate tests failed to compile before `Codex::ground` existed and the level assertions for context-injection and pre-action-enforcement were changed in the same step, so the level change itself was not seen red separately.
