Storage-level import keeps message ids (#1217; no schema change; 2026-11-24).
A backend migration or archive restore through the `Store` trait used `post_as`, which always mints a fresh id, so anything citing an id broke. `ImportStore::import_message(room, message)` appends a message with the id, seq, time, sender, attribution, label and handoff it had. It is a separate trait, not an area of `Store`: every caller that is bound by `Store` (the gateway, the server, every agent-facing path) cannot name it, and only code holding a concrete `SqliteStore` can call it. A test pins both the compile-time shape and the call sites by scanning the source.

  Validation: the id must be 1 to 64 letters and digits and unused anywhere in the store (the unique index on the id is the backstop); the label must be non-empty; the seq must be the room's next, so a replay in order keeps the log dense and ordered; any failure is `Error::Invalid` with nothing written, inside one immediate transaction. An import marks nobody present, creates no member row and moves no cursor, since it restores history and is not a member acting. Bodies and payloads are sealed under the message's own label key and id, as a post is. Not done: a bulk method, an import for the in-memory spike store, and moving cursors or claims across a migration (a migration tool decides those).
