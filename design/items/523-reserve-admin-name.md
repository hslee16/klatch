The names `admin` and `canary` are reserved and no member can take them (#523; no schema change; 2026-11-19). `admin` is the human principal the launcher gateways (run.rs, anchor.rs, worker.rs) act as, and `canary` is the tripwire's sender. A typed name is forgeable (#503), so anything that later keyed on the member name `admin` could be forged by a member typing `KLATCH_NAME=admin`.

    Where it is enforced. One list, `domain::RESERVED_NAMES`, used in three places. The identity layer (`DeclaredName`, `LocalIdentity` for a typed name, a credential's member, and a session's derived name) refuses a reserved name, which covers `join`, the hook join, every CLI call and the wire listener; a session whose name would be reserved falls back to `session-<id>` as it does for an unusable name. Worker issue already refused them and now reads the same list. Last, a gateway built `for_members` refuses a reserved caller on every operation with the rule `reserved-name`, as a backstop for any principal built without the identity layer (the member card, post, join).

    The human is unaffected. The launcher gateways are not built `for_members` and build their `admin` principal directly, so they keep acting as `admin`. A member already stored under one of these names (possible only if made before this change) is refused on its next act.
