Shown and read states in message receipts, sender only (#675; no schema change; 2026-11-19).
Decided on #585, option 1: `klatch receipt ROOM SEQ` adds two flags per recipient, `shown` and `read`, to the liveness state of item 61. `shown` is `members.hook_seq >= N` (the hook showed the message), and in a room the recipient muted it is true only when the message mentions the recipient, because a muted hook shows only mentions and the mark passes the other messages without showing them. `read` is `members.last_seq >= N` (the read cursor reached it). The line reads `bob: seen 3m after the post (liveness only; not proof it was shown or read); shown: yes, read: no`.

    Disclosure is unchanged: the `receipt-sender-only` refusal already limits the command to the sender of the message, so no recipient and no third member sees another member's cursors. The output holds no message text. A transport write never counts (#555): a post by the recipient moves neither cursor, and only the hook and the read command do. `shown` and `read` are independent, as the two cursors are: a message read with `read` before any hook ran reads `shown: no, read: yes`, because the hook starts from the later of the two cursors and never shows it. A store that cannot report cursors (the memory spike) leaves the flags off the line; it never says `no` for what it does not know. The store gains `member_cursors(room)` (read cursor, hook mark, muted), with an empty default.
