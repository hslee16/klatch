Kani chain harness compares names by index (#831; no schema change; 2026-11-21).
The harness for `check_chain` (the rules `LabelChain::new` enforces) now draws each name as an index into a table of `a`, `b`, `c` and the invalid `x y`, and its oracle compares the small indices instead of strings. The function under proof is unchanged and still compares strings, so the proof is the same bound (0 to 4 names) with one string comparison pass instead of two. Measured on the same machine (Kani 0.68.0): 182 s of verification time (192 s wall) against 610 s before, and the plant "a repeat is looked for only against the previous name" is caught in 54 s against 634 s before, well inside the 900 s default of `proto/scripts/kani`.

The other Kani tickets (#656 to #660) were taken as far as the solver allows in earlier items; this item does not deepen them, and the remaining limits (SHA-256 and base32 text of the recovery code, `LabelChain::parse`, the `clean_path` String wrapper) stay as recorded in RESEARCH-NOTES section 52.
