The team launcher relaunches a worker that ended with unread mail (#1011, #591; no schema change; 2026-11-21). A headless `claude -p` worker is deaf once its turn ends (research note 50.4: the wake watcher never reaches the model), so mail sent to a worker that finished, ran out of budget, hit the watchdog or crashed was never read. The human decided (2026-11-21) on automatic relaunch, option 1 of #1011. `klatch read ROOM --count` is the read-only operation: it prints how many messages `read` would show, as a bare number, and marks nothing read (it never advances a cursor, whatever else is given). It is not a new gateway or wire method: it calls the existing guarded `read` as a peek, so it is the caller's own record (a member sees only its own count), is checked by the same guard, role, clearance and credential rules as `read --peek`, adds no AUTHZ-AUDIT command or wire row and needs no zero-trust list entry (the `read` row says so). It needs a live credential, so only the launcher setup that issues credentials can ask on a worker's behalf, and who may issue credentials is unchanged.

  `proto/scripts/team` gains `resume NAME`, and the runner of every worker calls it when its claude process ends (after the credential is revoked and the exit code recorded). `resume` refuses a worker that is running or was stopped with `team stop` (a human stop is never undone), then checks the bounds, issues a fresh credential for the member in the launcher's own setup, reads the count, and either revokes it again (nothing unread) or relaunches the worker in its own worktree with a prompt made of the original task plus the unread digest (`read --peek`, at most 20000 bytes, labelled as data from other members). The bounds: at most `TEAM_MAX_RESTARTS` relaunches per worker (default 3; 0 turns the feature off and the runner never calls `resume`), a relaunch that would take the team past `TEAM_MAX_TOTAL_USD` is refused (what each ended run spent is banked in `run/NAME.spent`, so the cap keeps counting it, and the old log is kept as `NAME.log.prev`), and `TEAM_RESTART_PAUSE_SECS` (default 30) before each automatic relaunch so a crash loop cannot drain the budget. A person running `team resume NAME` by hand is not paused. A relaunch is also skipped when another member holds the worker's ticket claim. Why a worker was not relaunched is kept in `run/NAME.note` and shown by `team status`, which also shows `restarts=N`. `team start` resets the count. The tests use the fakes in `proto/scripts/test-team.sh` (a fake claude and a fake klatch); no credential is issued by any test or by the builder of this change.
