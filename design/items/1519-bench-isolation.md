coordbench keeps agents to their own directories, and says what is prevented, what is obscured and what is only detected (#1519; no schema change to the store; 2026-11-23).
The independent review of the benchmark (#1461) showed a fake agent reading both colleagues' private facts, the live logs and, in K arms, the checkers through a path in the prompt. The fix has three layers of different strength and the record says which ran. Layout (obscurity and a detective aid, not a boundary against the same user): every agent has `<scratch>/agents/<token>/{clone,home,tmp,claude-config}`; the `agents` directory and the log directory have mode 0300 while real agents run (fake agents, which signal each other by listing the log directory, keep it listable); the logs are staged in a random-named directory inside `--logs-dir` with random file names, renamed to `<logs-dir>/<run id>` when the run ends (left 0300 when another process has a run live under that logs root, a `.live.<token>` marker with a pid); the harness changes the mode only of directories it made, never of `--logs-dir` or `--tmp-root`, and refuses either when it is the home directory, not the user's, or writable by group or others. The klatch binary is copied to `<tmp-root>/cb-bin-*` for the suite and the restart script into the run, so no prompt names a path in the repository. SIGTERM and SIGINT restore every hidden mode; a start sweeps stale `cb-*` scratch of dead pids (an `.owner` file). Sandbox (`--isolation sandbox`, default for real agents, the only preventive layer, unverified until isolation_probe.py is run on the machine): the agent's `--settings` file turns on Claude Code's sandbox (Seatbelt, bubblewrap) with `failIfUnavailable` and no unsandboxed retry, denies reads under the scratch root, logs, repository, the real home, `/Users`, `/home` and `/root`, re-allows the agent's own directories, the staged binary and the python3 and git installations, allows writes only in its own directories, the bare origin, the run store and (role members) the restart directory, and adds Read/Edit deny rules for the file tools (absolute paths). It needs Claude Code 2.1.268 or later (deny rules through symlinked directories; the harness refuses an older or unknown version). No network key: the klatch binary opens no socket. Scan (detective, always): `isolation.scan_lines` checks every tool call of every stream and a hit makes the run invalid; the record gains an `isolation` object (mode, checked_calls, violation_count, violations), null when the scan did not run.

What is prevented (if the sandbox works as documented): reads outside the agent's own directories by Bash and its children, python3 and git included; the file tools are covered by permission rules. What is only obscured: a path an agent has not been told and cannot list. What is only detected, and what the scan still misses: a path built at run time inside a python3 program; a symlink made in one call and followed in a later one; code written to a file and run in a later call; a directory path asked of the kernel (libproc, `fcntl F_GETPATH` through ctypes); a path with no `./`, `../` or `/` in front; a variable that holds the root (`F=/; find $F`); a `cd ..` followed by a bare read of the agent's own settings file;  `ps` and `/proc` (listed, but a leak through them shows paths the scan then sees only if the agent uses them). Earlier runs' published log directories in layout mode are listable and readable by a later run of the same user (the sandbox denies the logs root, layout mode cannot). A `--tmp-root` or `--logs-dir` under a user root is refused in sandbox mode, because the file-tool deny rules cannot cover a user root that holds the run. Other agents' argument lists and environments are visible to the same user (#1532).

Measured on this machine, a trivial run with two hanging fake agents and the checker polled every 0.05 s (`poll_checker`, 23 to 28 polls): main 0.205 s mean and 0.237 s max per poll; the first version of this change, which hid the whole scratch directory (mode 0300), 1.381 s mean and 1.492 s max; this version, which hides only `<scratch>/agents`, 0.193 s mean and 0.196 s max. The slow version made the stream pump batch lines under one clock reading, and S4's late-ask test failed 8 of 10 reruns; now `pump` takes one clock reading per line, the checker polls in a thread, and the test passed 20 of 20. The self-test (tests/test_isolation_run.py) runs a fake agent through the whole harness that tries parent directories, sibling clones, the logs by their public and their leaked names, absolute paths, symlinks, python3 one-liners and `git -C` another clone: each is blocked by permissions or detected, the allowed `git log origin/main` and `ls ..` (its own directory) are not flagged.

Every reader of a stream (streams, chain, history, recovery, injmetrics, shared, the isolation scan and the probe) reads events through streamshape.py: an error or retry event can carry "message" as a plain string, and a parser that crashes after a paid run loses the run (found by the first real run of isolation_probe.py). The shapes covered are the ones tests/test_stream_shapes.py tries (a string message, a string or missing content, non-object blocks, ids, names, inputs and counts of the wrong type), not every possible one.

Residual gaps (#1531 seeds, #1532 ps and argv): the hidden facts do not vary by seed; prompts are passed as an argument and so appear in `ps` with the agent's working directory; whether the sandbox blocks `ps` is unverified (`--isolation layout` is the way out if it breaks a K arm).
