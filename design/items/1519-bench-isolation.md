coordbench keeps agents to their own directories, and says what is enforced and what is only detected (#1519; no schema change to the store; 2026-11-23).
The independent review of the benchmark (#1461) showed a fake agent reading both colleagues' private facts, the live logs and, in K arms, the checkers through a path in the prompt. The fix has three layers and the record says which ran. Layout: every agent has a directory under a random token (clone, home, tmp, claude-config), the run scratch and the log directory have mode 0300 while agents run (the owner cannot list them), the logs live under a random name until the run ends, and the klatch binary and the role members' restart script are copies in the run, so no prompt names a path in the repository. Sandbox (`--isolation sandbox`, default for real agents): the agent's `--settings` file turns on Claude Code's sandbox (Seatbelt, bubblewrap) with `failIfUnavailable`, no unsandboxed retry, read denied under the scratch root, the logs and the repository and re-allowed for the agent's own directories, write allowed only there plus the bare origin and the run store, and Read/Edit deny rules for the file tools. Scan (always): `isolation.scan_lines` checks every tool call of every stream and a hit makes the run invalid; the record gains an `isolation` object (mode, checked_calls, violation_count, violations).

What is enforced: listing or opening anything the agent cannot name (permissions), for Bash, python3, git and the file tools alike, on every OS. What the documentation says the sandbox adds: OS-level denial for Bash and its children even when a path is known; the file tools are covered by permission rules, not by the sandbox. What is only detected: a leaked path (other agents' argument lists and environments are visible through `ps` and `/proc` to the same user unless the sandbox hides them; the builder could not run a real agent to check) and anything built at run time inside a python3 program. The self-test (tests/test_isolation_run.py) runs a fake agent through the whole harness that tries parent directories, sibling clones, the logs, absolute paths, symlinks, python3 one-liners and `git -C` another clone: each is blocked by permissions or detected, and the allowed `git log origin/main` is not flagged. isolation_probe.py is the one real session for the coordinator to check the sandbox on the actual machine.

Residual gaps (#1531 seeds, #1532 ps and argv): the hidden facts do not vary by seed (they are committed files from fixed seeds, fixtures are another owner's); prompts are passed as an argument and so appear in `ps` with the agent's working directory; whether the sandbox blocks `ps` and whether it breaks klatch's loopback traffic in K arms is unverified (use `--isolation layout` then).
