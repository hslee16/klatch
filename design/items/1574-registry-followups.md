Registry and process table follow-ups: junk and old records cannot hide a live session, a duplicate pid or a child holding the pipe makes ps unreadable, and the test ps needs a second variable (#1574, #1629; no schema change; 2026-11-26).
**What the tickets asked.** Minor findings of the reviews of #1558 and #1628 (all same-user, none lets a record be believed that was not believed before): junk entries starved the pruning pass; two mutants of the registry reader were unpinned; more than 256 `<pid>.json` files could hide a live session from `klatch sessions`, doctor and the sys lease source; a duplicate pid in the process table silently overrode an earlier row; a program that forks a child holding the output pipe defeated the 5 second timeout; there is no process table where `ps` is not at a fixed place and doctor did not say so; `KLATCH_TEST_PS` was read by every debug build.
**What is built.**
1. Entry bounds count only names that look like a record (`<pid>.json`) or a temporary file (`.<pid>.tmp<n>`). A name of any other kind costs a look at the name only (at most 65536 entries are looked at per pass). The Claude registry reader (`FsRegistry`) and the Codex registry reader (`OwnRegistry`) share `own_records::record_names`: with more than 256 record names, the 256 with the newest modification time are read (a live session keeps its record fresh, a leftover of a crashed one is old; ties break by name so the pick is stable). With 256 or fewer, every one is read, as before. `record_for` (the identity check) never listed anything and is unchanged. Nothing is deleted from the Claude registry (it is Claude Code's); the Codex prune still removes only records it parsed and judged gone, and now sees every temporary file name, at most 256 per pass.
2. Pinned: the swap-safe composition of `read_named` (open without following a link, then check the descriptor) by a test that swaps the name between a plain file and a symlink to another plain file of ours as fast as it can while the reader runs, and fails if the text behind the link is ever returned; and the bound of the temporary file cleanup.
3. `parse_table` treats a second row for one pid (named or not) as an unreadable table, like a row that does not parse: which row is true cannot be known.
4. `run_ps` reads the output on a detached thread and waits for it only until the deadline, so a child of `ps` that keeps the pipe open can no longer stretch the timeout: the run is `Unreadable` at the deadline. The child itself is still killed on timeout; a grandchild that holds the pipe is not killed (killing a process group needs a new `unsafe` call; options in the ticket).
5. `klatch doctor` prints one fixed warning when no `ps` is at `/bin/ps` or `/usr/bin/ps` (NixOS, Guix). Nothing is said when there is one. No behaviour change: every identity check still fails closed.
6. `KLATCH_TEST_PS` is read only in a build with debug assertions and only when `KLATCH_TEST_SEAMS` is set as well, so a dogfooded debug binary does not read it by default. The tests that use it set both. A release build has neither variable in the binary.
**What is not changed.** Which records count as evidence for any walk, liveness, listing or Codex verification; the `Lookup` meanings; `record_for`; the owner and mode rules of the Codex registry; the Claude registry reader's rules (any owner, any mode, 64 KiB cap).
**Left.** The Codex prune judges records against the snapshot taken before the walk (unpinned, #1629 item 6). The cap of entries looked at (65536) is not pinned by a test (it would need a directory that large). Whether doctor calls the missing-ps check is not pinned (a test would need a machine without `ps`). A grandchild of a faked `ps` that holds the pipe is not killed.
