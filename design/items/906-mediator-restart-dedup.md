The mediator does not repeat a proposal after a restart (#906; no schema change; 2026-11-19). A restarted `klatch mediator` used to forget which cases it had proposed on and post the same proposal again for a case that still stands. On its first pass it now reads the lobby's recent history through the same guard-checked `history` call a member makes (no new privilege path, no local file) and counts a standing case as handled when a message the mediator itself sent is exactly the fixed-template proposal planned for it. A post by any other member never counts, whatever its text, so no one can silence the mediator by copying a template.

    The handled set also drops a case once it no longer stands, so a case that ended and returned is proposed on again, in a run as after a restart. Limits: the read looks back at most the history maximum, so a proposal older than that window is not seen; and a case that ended and returned entirely while the mediator was down is treated as the same standing case. The repeat guard on posts still refuses an identical repost inside its window, and the mediator reports that as a refusal. The router (#891) has the same in-memory set and can take the same fix.
