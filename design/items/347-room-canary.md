A canary is planted in every private room by the human's label act (#347; no schema change; 2026-11-19).
**Decision (the human, 2026-11-18).** When the human labels a room to `private` or above (the default agent cap; the level just below the top when the chain has no `private`), the label act plants a canary in it, with no setup. The label act of an admin agent plants nothing and its allowlist is unchanged; a room already labelled when this shipped has none until the human labels it again (nothing is planted retroactively). A room gets one canary at a time: labelling it again keeps it. The token is 128 random bits from the operating system (`kc-canary-` plus 32 hex digits), made per plant and never derived from the room, the time or anything in the repository. The canary is a message from the member `canary` at the room's label with the kind `canary`, so the label floors keep it from every member below that label, and a copy of the token in any other room is refused by the existing `canary` check, which pauses the room it was aimed at.

    **Shown once.** The message is delivered once per member, in the first digest that member gets for the room (the digest cursor is the per-member record, so no new storage). `read`, `history`, `tail`, `wait` and the wake count drop it, and the digest never repeats it. Tradeoff: a member whose first view of the room is an explicit `read` or `history` never sees it, so it cannot copy it (and so cannot be caught by it); a session that starts with its digest, which is the normal path, sees it. The wording is unchanged from `admin canary` ("internal credential, never copy it out of this room"), because whether to soften it to a marker is not decided.

    **Retire.** `klatch admin canary-retire <room>` removes the room's canary token, so the tripwire for it stops; it is a human act (not in the admin agent's allowlist) and an error when the room has none. Labelling the room again plants a fresh one.
