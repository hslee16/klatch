The bench binary is built once per process and never replaced under a running test (#752; no schema change; 2026-11-20).
Cargo removes and re-links the uplifted `target/bench-bin/<profile>/klatch` on every build, even a fresh one, and every world test called `find_binary`, which ran `cargo build` each time. Another test (or another test binary, or a bench run) could be mid-uplift while a scenario tried to start the binary, which gave the macOS CI failure "could not start .../bench-bin/debug/klatch: No such file or directory". I could not reproduce it with real cargo, but the window is real. `find_binary` now builds once per process (OnceLock), runs the build under an exclusive file lock in `bench-bin/.build.lock` (so no two threads or processes build at once), and returns a private copy named by content (`klatch-<hash>`), renamed into place atomically. Cargo never touches the copy, so a binary in use cannot vanish. Deterministic tests use a fake builder that removes the built file and waits.
