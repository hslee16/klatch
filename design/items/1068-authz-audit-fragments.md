The authorization audit is one file per row, assembled for reading (#1068; no schema change; 2026-11-21).
`proto/AUTHZ-AUDIT.md` (part of #1064) was one table file merged with `merge=union` (#1065); union cannot tell an added row from two edits of one row, so it left duplicate rows twice and a human fixed them. The rows now live under `proto/audit/<NN-section>/`: `_head.md` (heading, prose and table header), one file per row named for its operation (`post.md`, `release-crossings.md`; a gap row is named for its first words), and `_tail.md` (prose after the table). Two PRs that add different rows touch different files and never conflict; two edits of one row are a real conflict a human resolves, never a silent duplicate. Row text is unchanged; the readable document is assembled in section order with rows in file-name order (alphabetical, so the rows of a table are no longer in the order they were added). `proto/scripts/authz-audit` writes `proto/AUTHZ-AUDIT.md` (byte-stable, `LC_ALL=C` order) and `--check` tells whether a copy is current. The generated file is gitignored and not committed: a committed copy would be changed by every PR that touches a row and would conflict again. `tests/authz_audit.rs` reads the fragments directly (every wire method, command and admin command is still checked, rows unique by operation, gaps unique by ticket), checks that each row file is one row named for its operation, and checks that the script and the test assemble the same bytes twice. `proto/AUTHZ-AUDIT.md` left the `merge=union` list. To add an operation, add its row file in the right section directory.
