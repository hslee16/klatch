The harness conformance suite and the verified harness of a joining session (#62 and #877, epic #12; no schema change; 2026-11-18).
`harness::conformance` is a suite every adapter must pass, run over each entry of `conformance::adapters()`; adding an adapter (Codex for real in #64) is one line there and `every_registered_adapter_passes` covers it. Each adapter is built twice, with its probe answered well and with it unanswered (`Support::Unknown`, `HookTrust::Unknown`). **Rules:** (1) the id is a short stable word, the same whatever the probe said, and unique across adapters; (2) `level` is total over `Capability::ALL` and repeats its answer; (3) a `native` level names its basis through the third trait method `basis(c)`, a path from the repository root to the test or document that observed it, and the file exists and is not empty (anything below native names none); (4) nothing is native on a guess: a capability the adapter lists as probe dependent is not native without an answer, and no capability is better unanswered than answered well. The suite has its own tests with deliberately bad adapters, one per rule, so a rule that stops catching is seen. This is the one change to the trait: it grew from two methods to three (`id`, `level`, `basis`). **One behaviour changed to pass rule 4:** `ClaudeCode` wake is native only for a measured version at or above the floor; a version too old and an answer that cannot be read are both degraded, so a room that requires `wake` is not satisfied on a guess. The wake watcher itself is unchanged: `Support::wake_enabled` still leaves it running when the probe cannot tell (#482). `ClaudeCode::probing` runs `claude --version` once, and only when the wake level is asked for, so a join to a room that does not require wake never starts it.

**The gateway learns the harness from evidence it checked itself (#877).** `Direct::with_harness` gives the transport a harness, and its `join` then calls `join_with_harness`; without one a join is the generic floor, as before. The CLI sets it only when `identity::runs_claude_code` holds: the evidence is the session found by the walk up the process tree (a live process whose program is `claude`, a registry record whose pid and start time match; for a hook, the record of the very session the hook was started for). That covers the `join` command and the SessionStart hook, which are the only two paths that join. Nothing the caller sends counts. **Fails closed to the generic floor, by design:** a typed name (even inside a real session, since a typed name wins over discovery), a session remembered by id when the registry record is gone or belongs to another session, a key bundle (it proves a member, not its harness), and Codex (a thread id, not a verified process; #64). **Grade of evidence:** same-user, like the registry and the member name derived from it, so the principal stays unattributed; it keeps an honest session from being mislabelled and a plain script from claiming enforcement, and it does not stop a process of the same user that forges a registry record. **The wire has no `join` method**, so there was no wire path to wire: a wire session is already a member, and joins through the CLI or the hook. Tests: `src/harness/conformance.rs`, `tests/harness_join.rs` (a real process named `claude`, a registry of its own, the real binary), `src/identity.rs` and `src/harness/negotiate.rs`. The conformance rules and the new trait method were written with the code that satisfies them, so they were never seen red; the two positive end to end join tests were seen red before the transport and the identity change, the hook test and the negative tests were not seen red individually.
