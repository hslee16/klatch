Session table entries are removed by a drop guard, and panic log lines are paced and path-free (#1643, #1645; no schema change; 2026-11-26).
A `GET /v1/stream` session is entered in the table `POST /v1/frames` reads in exactly one place (`wire_sessions::register`) and removed in exactly one place, the `Drop` of the `Registration` it returns; the session's code and its closer hold that guard, so a normal close, an early return and an unwind from a panic all remove the entry, and nothing removes one by hand. The handler-panic line (`panic_log`) is paced with an injectable clock: the first panic is said at once, and a later panic after 10 seconds brings one summary line with the count since the last line (a fixed template and a number). The panic hook prints the crate directory and what is below it (`klatch-server/src/wire_http.rs`, `serde-1.0.200/src/de.rs`), never an absolute build path and never the message. The debug-only seam `KLATCH_TEST_STREAM_PANIC` still needs `KLATCH_TEST_SHORT_LIMITS` too, and a test pins that a server started without short limits ignores it.
