Session table entries are removed by a drop guard, and panic log lines are paced and path-free (#1643, #1645; no schema change; 2026-11-26).
A `GET /v1/stream` session is entered in the table `POST /v1/frames` reads in exactly one place (`wire_sessions::register`) and removed in exactly one place, the `Drop` of the `Registration` it returns; the session's code and its closer hold that guard, so a normal close, an early return and an unwind from a panic all remove the entry, and nothing removes one by hand. Both panic log lines (`panic_log`) are paced, each with its own pacer and an injectable clock: the panic hook's `internal error at PLACE` line and the handler's `handler panicked` line. The first of each is said at once, and a later event after 10 seconds brings one summary line with the count since the last line (a fixed template and a number), so a burst of panics prints two lines in all. The place shows no build directory or username: a cargo registry path keeps the crate and below (`serde-1.0.200/src/de.rs`), a toolchain path keeps `rustc/...`, a relative path (a workspace crate) is kept, and any other absolute path shows only its file name; the message is never printed. The debug-only seam `KLATCH_TEST_STREAM_PANIC` still needs `KLATCH_TEST_SHORT_LIMITS` too, and a test pins that a server started without short limits ignores it.
