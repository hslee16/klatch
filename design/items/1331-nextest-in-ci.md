CI and the gate run the tests with cargo nextest (#1331; no schema change; 2026-11-22).
The CI step "Unit and integration tests" runs `cargo nextest run --workspace --locked` and then `cargo test --workspace --doc --locked` (nextest does not run doctests; none exist today, so the second command is a guard). The step before it installs nextest with taiki-e/install-action pinned by full commit SHA like every other action. The human chose this on 2026-11-22 from a measurement on the real ubuntu-latest runner (4 vCPU, five variants, three runs each, 15 jobs, 0 failures, 3442 tests): the median job fell from 326 s to 210 s and the test step from 257 s to 135 s, the only gap outside the run to run noise.

Not adopted, because the same measurement showed no reliable gain: dropping debuginfo (`CARGO_PROFILE_DEV_DEBUG=0`, `CARGO_PROFILE_TEST_DEBUG=0`; it shortened compile by 10 to 20 s warm but the test step stayed inside the noise) and a nextest test group limiting the 11 pty-driving binaries to 2 threads (slower or equal; it cannot show an effect on the pty flakes #1298 and #1316 without a heavy-load repro). The `no_plaintext` step with the `test-clock` feature stays a `cargo test` step.

The local gate (`proto/scripts/gate`) keeps parity (#1034): it runs nextest and the doctests when `cargo nextest` is installed, and otherwise prints a notice and runs `cargo test --workspace`. `proto/scripts/test-scripts.sh` covers the nextest path, the fallback and a nextest failure. Other workflows left unchanged: `platform-tests.yml` (manual, runs `cargo test --workspace` on Linux aarch64 and macOS x86_64; nextest was not measured there). `release-dry-run.yml`, `build-release.yml` and the rest run no workspace tests. Each nextest test runs in its own process, so a test that relies on state shared with another test in the same binary would fail only under nextest; the full local run is reported in the pull request.
