A broadcast is a message kind, not a word (#674; no schema change; 2026-11-21). Decided on #635 (option B): the marker of a message meant for every member is the kind `broadcast`, set with `klatch post --kind broadcast` (the handoff `kind` field that already exists on `post`, the wire, the CLI and the Python, TypeScript and Rust clients, so no client needed a new field). A message of that kind passes a narrowed delivery view (item 70) and counts as addressed to every member in a busy hook digest, exactly as an `@all` message did.

    The transition: the word `@all` keeps working with the same effect, so no existing harness or recipe breaks. A message is a broadcast if it has the kind or mentions `@all`; `delivery::is_broadcast` is the one test both the view and the digest use. The word is the deprecated form; it is removed only by a later decision once the clients and recipes have moved, and that removal needs no store change.

    Collisions: `all` joins `admin` and `canary` as a reserved name (#523), so no member, worker or session can be named the broadcast word and `@all` can never also address one member. A member already named `all` (the name was never refused before) keeps its rows but is refused on a members' gateway with the rule `reserved-name`, like any reserved name.

    A broadcast grants nothing and skips no guard: it is posted through the same path as any message (credentials, canary, label, budget, rate), and the kind is a label the sender chooses, so a delivery view is a convenience and never authority. Any member may broadcast, as any member could write `@all`.
