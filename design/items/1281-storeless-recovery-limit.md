The store-less recover and restore have a failure limit in a file (#1281; no schema change; 2026-11-22).
`admin recover` and `admin restore` run when the store cannot be read, so the failure limit of the admin proof (#1233, kept in the store) could not be charged and a recovery code could be tried without limit. The attempts are now kept in a file beside the store (`<store>.recovery-fails`, one line per attempt, the unix time) with the same schedule as the store's limit: three free attempts, then a wait that doubles from 30 seconds up to 15 minutes. An attempt is charged before the code is checked, by one append, so a process killed after typing and several guessing at once each still cost one. A file that cannot be written refuses the attempt, and a damaged line counts as an attempt made now.

Once the store opens again after a successful recover or restore, one `recovery-attempts` audit row says how many attempts were made and the file is removed. The file guards the code against a program that only has the command line; whoever can delete the file can already delete the store. Several processes that read the count at the same moment may each pass the wait once, but each still adds a line, so the next attempt waits.
