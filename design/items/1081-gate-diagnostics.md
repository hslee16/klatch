The gate's release and shell checks say which check failed (#1081; no schema change; 2026-11-20). Step 11 of proto/scripts/gate ran about twenty commands chained with `&&`, sent almost all of them to /dev/null and, on failure, printed the tail of what was left, so an intermittent failure (PR #1076 and #1077 on 2026-11-20) left no trace of the command that failed. Each command now runs through a small `check` helper that keeps its stdout and stderr in a temporary file: a passing check prints nothing (the step is as quiet as before), and a failing one prints its command line and the last 40 lines of its output.

    The pass and fail semantics are unchanged: same order, the first failing check stops the chain, the step is still named "release and shell checks", it prints the same step line and the gate exits non-zero. The conditional checks (actionlint, shellcheck) and the build line at the top are unchanged. If the environment variable GATE_LOG names a file, the helper also appends every check's command line, full output and exit status to it (off by default), for a rerun that has to be examined afterwards. This only makes the failure visible; the root cause of the intermittent failure is not fixed here and stays open in #1081. proto/scripts/test-scripts.sh drives the gate in an export with stub checks and covers the printed diagnostics, the early stop, the quiet pass and the log.
