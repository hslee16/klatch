klatch-server code health: smaller functions, same wire and same guards (#1449, part of #1441; no schema change; 2026-11-23).
Cluster K08 of the CodeScene cleanup is a behaviour-preserving refactor of `klatch-server`. Nothing a client, the CLI or a document can observe changed; the invariants are the same: every listener binds through `check_loopback` (an IP literal, 127.0.0.1 or ::1 only), the webhook intake verifies the HMAC before it looks at the body and drops replays by delivery id and by content (#1058, #1089, #1103, #1132), the binary has no network client, and message and webhook text is data. Characterisation first: `tests/wire_http_golden.rs` pins the exact bytes of every HTTP refusal (404, 405 with `Allow`, 401, the 400, 411, 413, 431 and 501 forms, and the 202 and 404 answers to `POST /v1/frames`) and of the event-stream head and its first event, and it passed on the untouched code before any production change. The existing suites (webhook, loopback, daemon, http_wire, mcp_http, channel and the scans) are the rest of the net.

What changed. `wire_http`: `Route` replaces the nested method and path match, `post_frames` and `mcp_http::post` take one `loopback::Pending` (stream, head, bytes already read, limits and deadline) instead of six arguments and share its `body()`, `stream_session` is split into `register`, `open_stream`, `watch_for_hangup` and `Registration`, and `sse_event` uses `event_type` and `message_id`; the SSE code moved to `wire_sse`. `loopback`: `parse_head` is split into `parse_request_line` and `parse_content_length`, `read_body` takes a `Budget`, `serve_concurrent` takes `Callbacks` and uses `claim_slot` and `blocking_handle`. `webhook`: `scan_flags`, `CiEvent` (with `completed`, `unattached`, `attached`), `flush` and `Intake::accept`; the translation moved to `webhook_translate`. `daemon`: `run` uses `next_connection` and `admit`, and `serve_inner` uses `read_first`, `identify_answer` and `serve_identified`. `channel::watch`: `push_events` and `idle_until_change`. `mcp_http::post`: `admit`, `parse_message`, `exchange`. The `issue_test_credential` example: `canon` and `lexical` are functions. Tests: assertion helpers and tables in `webhook_tests` (now three files by topic), `daemon`, `http_wire`, `mcp_http`; `no_network` is split into one function per rule.

One test text changed, with the same meaning: `no_network::the_daemon_module_has_one_unix_listener...` used to look for the peer credential call, the uid check and `scope.spawn(` in this order inside `run`; the first two now live in `admit`, so it checks that order in `admit` and that `run` calls `admit(` before `scope.spawn(`. In `no_network`'s source scan the unreachable second branch (the daemon naming a network type inside the allowance for the loopback files) was dropped; the daemon is still refused every network type by the first branch. A mutation check (a source line naming `TcpStream`, `std::net`, `UdpSocket`, `UnixStream` and an outbound connect outside their modules) still fails the scan.
