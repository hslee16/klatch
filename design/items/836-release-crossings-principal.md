Releasing crossings is made by a named principal (#836; no schema change; 2026-11-20).
`Gateway::release_crossings` takes a `Principal` and asks the guard for the admin act `release-crossings` (role check first, a refusal kept in the refusals), so the posting side of a crossing is no longer unguarded. `klatch judge` passes the principal `judge` (the launcher's own drain, as the `admin` principal is for `klatch admin`); no role holder's list names the act, so a reviewer is refused under `reviewer` and an admin agent or a plain member on a members' gateway under `admin-scope`. `review_verdict` releases through the same code under the reviewer's own name, already guarded by its own operation. Every crossing audit row now ends `applied by <who>`. What the judge decides and what is released are unchanged: the floors are still checked again at release. The launcher heuristic that gates the `judge` command is still #834.
