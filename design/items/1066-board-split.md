The board code is split by section (#1066, part of #1064; pure move; no schema change; 2026-11-20).
Every board feature (open pull requests, the merge queue, tasks, asks, the advisory mark, the canary) edited the same three files, so parallel pull requests collided in them. `domain/board.rs` is now the directory `domain/board/` and `gateway/gateway/board.rs` is `gateway/gateway/board/`, each with one file per section behind the unchanged public paths (`domain::render_board`, `Gateway::board` and the rest are the same names). In the domain, `mod.rs` holds the `Board` type, the shared helpers and a `SECTIONS` list of renderers; `members`, `offers`, `asks`, `tasks`, `prs` and `queue` hold one section each, and the tests moved to `tests/` by the same split. In the gateway, `mod.rs` assembles the `Board` from one method per section file (`members` returns a `Roster`, `tasks`, `prs`, `queue`, `asks`, `offers`), and the hook digest and receipts have their own files.

To add a section of the board: write its renderer in a new `domain/board/<section>.rs` and add one line to `SECTIONS`, add the field to `Board`, and write the method that fills it in a new gateway file with one line in the `Board` literal in `Gateway::board`. No file is over 600 lines: `hub_files_stay_split` now covers `domain/board` and `gateway/gateway/board` too. Behaviour and output are identical: the full workspace test count and the whole bench result are the same before and after, and `AUTHZ-AUDIT.md` and the zero-trust tests are unchanged.
