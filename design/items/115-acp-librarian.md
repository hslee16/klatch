`klatch acp --stdio`: the read-only librarian offered to editors as an ACP agent (#115, epic #10; no schema or wire change; 2026-11-18).
DESIGN section 20 rule 13 names editors (ACP) as a later bridge and RESEARCH-NOTES section 15 names the librarian as the agent to offer. **Shape:** `session/acp.rs` is an adapter over `Session::call`, the same plain request path `klatch mcp --stdio` (#299) and `serve --stdio` use, so each query meets every check a wire request meets (guard, roles, labels, the receiver budget, the refusal record) and the adapter checks nothing of its own. **Identity:** the process's member, found as for every command; no prompt can name another caller (a test pins it). A member granted the librarian role is also held to `read-only` by the gateway; the command does not require the role, because the four looks it offers are open to any member under that member's own clearance and no write exists in it. **Queries:** the prompt is not given to a model. It is a fixed grammar on the first non-empty line: `read ROOM` (always a peek, so no cursor moves), `history ROOM [N]`, `who ROOM`, `claims ROOM` and `help`. Anything else, including `post`, `claim`, `release`, `dm`, an admin act or a second statement on the line, is answered with the help text and calls nothing, so text another member wrote can never become a call. A wire refusal or failure is returned as the answer text naming the rule and reason, never the matched content; messages come with a notice that they are data. **Protocol assumptions (written from memory of the public ACP specification, not re-read against it on 2026-11-18; ticket filed to verify):** JSON-RPC 2.0, one message per line; `initialize` takes and returns an integer `protocolVersion` of 1 with `agentCapabilities` (`loadSession` false, no image, audio or embedded context), empty `authMethods` and `agentInfo`; `session/new` returns a `sessionId` and ignores `cwd` and `mcpServers`; `session/prompt` streams the answer as one `session/update` notification with `sessionUpdate` `agent_message_chunk` and a text content block, then responds with `stopReason` `end_turn`; `session/cancel` is a notification and is ignored, because a query is answered before the next line is read; `session/load` and `authenticate` are unsupported (`-32601`); an unknown `sessionId` is `-32602`. No permission requests, tool calls, file system or terminal requests to the client are made. **Not built:** a model-backed librarian that interprets free text (the grammar is the whole of it), `board` and other looks, streaming a long answer in several chunks, a network transport. **Tests (written after the code, so not red first; the module and the command were added together and the tests then run against them):** `src/session/acp_tests.rs` against a members' gateway with a granted librarian (initialize, sessions, read as peek, history, who, claims, a query above the caller's clearance refused for all four looks with nothing leaked, a cleared librarian reading, no write reachable from any prompt including smuggled second statements, an argument naming another caller with no effect, an ordinary member held to its own clearance, unknown methods, notifications and junk) and `tests/acp.rs` against the real binary (a query over stdio, looking moves no cursor and posts nothing, no prompt writes, a clean exit when input closes, `--stdio` required).
