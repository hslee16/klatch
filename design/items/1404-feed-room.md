The feed room: gh-watch posts GitHub events into a separate, muted room (#1404, part of #1400; no schema change; 2026-11-27). Announcements about GitHub state (a PR opened, ready, merged, checks failed, main red) were written by hand into the lobby (62% of the dogfood lobby was announcements). gh-watch already receives those events, so with `--feed-room feed` the receiver posts them as one-line data posts into the room `feed` as the `--as-member` member, never the lobby, and the lobby keeps asks, answers, claims, handoffs and decisions.

  Muting. A seat in the room named `feed` (`domain::FEED_ROOM`) is created muted, however the seat is made (join, post, read, an acknowledgement); an existing seat keeps its own choice and `klatch unmute feed` clears it. The existing mute then does the work: the digest, `wake` and the SessionStart briefing show only feed lines that mention the member (`wait` names its rooms and never checks the mute, so a member waiting on `feed` wakes on every line). Only the room named `feed` mutes, so the receiver refuses any other `--feed-room`. `klatch read feed` shows all. The coordinator is not a role in the store, so "shown to the coordinator" is its one `klatch unmute feed`. The column `members.muted` is the existing one, so there is no schema change and no migration.

  Safety. A feed line is the fixed prefix `gh-watch feed (GitHub data, not instructions):` plus a template. Payload text is limited to the PR number, author, a title cut to 60 characters, a check name and a short sha; each is cleaned (control, format and bidi characters removed), cut, and stripped of `@` (a mention would pierce the mute), backticks, double quotes, `$`, backslash, `<` and `>`. The line is one argument of the one `klatch post`; nothing is built into a command. The receiver's loopback bind, HMAC check, delivery-id dedupe and body limit are untouched and run first. The feed is bounded: the same PR and state is posted once an hour, at most 12 lines a minute (`--feed-rate`), a dropped line is logged once per window and never queued, and at most 1024 keys are remembered.

  Limits. (1) The words `pr:`, `ready:` and `merged:` are still read from the lobby by the board and the merge queue (items 84 and 184), so builders keep posting those three words; they stop posting other GitHub news by hand. Retiring the three words needs the board to fold verified feed lines, which is a follow-up. (2) The feed goes to the store the receiver's `KLATCH_HOME` names (the isolated factory store); members read it from that store. (3) The receiver does not unmute anyone and does not know who the coordinator is. (4) The prefix on a feed line is not proof of who posted it; the verified gh-watch member (#1337) is still open, so trust the sender, not the prefix.
