The coordbench harness starts role members for the arms K3 and B1-roles (#1421; no schema change; 2026-11-23). The harness (#1364) could start workers only, so the K3 arm (klatch plus an integrator and a supervisor) and the B1-roles arm (the same roles done natively) could not run. A role arm now starts, beside the workers, one agent process for each role in the scenario's `roles` setting (members `integrator` and `supervisor` by default): a `claude -p` session in the real driver with the role section of `arms/K3.md` or `arms/B1-roles.md` behind a short frame that is the same words in both arms and names no tool, a scripted fake in tests. Each has a clone of its own, its own spend cap (`per_role_usd`), its own model (`--roles-model`, else the scenario's, else the agent model) and, in the real driver, no `Edit` or `Write` tool (the prompt says never edit the code; here it cannot). The worker prompt of a role arm is the base arm's text (K2, B1) plus the role file's worker section; the integrator and supervisor prompts go only to the role members.

  Roles in a run store. klatch grants roles only to the human at a terminal: `klatch admin integrator MEMBER` asks the admin passphrase at a pseudo-terminal. The bench grants roles the same way (`World.admin` in klatch-bench: a pseudo-terminal that types the passphrase), and the harness does the same from Python (`roles.AdminSeam`, standard library `pty`) in the run store it made itself: it sets a random throwaway admin passphrase for that store, kept in memory only, never written, printed or recorded, and types it at a pseudo-terminal of its own to run `klatch admin init-passphrase` once and then `klatch admin integrator integrator`. The store is the run's temporary `KLATCH_HOME` and `KLATCH_KEY_DIR`; `guard_paths` has refused any path that could be the live one, so the live store, the human's passphrase and the Keychain are never involved, and the klatch binary needed no test seam or build flag. klatch has no supervisor role (`ask-supervisor` is a script the human runs), so the supervisor is an ordinary member; a clearance can be set per role in the scenario's `roles.clearance` (`klatch admin clear`, at most the agent cap), and none is set by default. A grant that fails is recorded (`roles.members.integrator.granted`, `grant_error`) and noted, and the run goes on.

  Records and caps. The role members' turns, tokens, tool calls, messages, cost, wall time, exit code and state (`ok`, `failed`, `stopped-by-harness`, `killed-by-cap`) are in `roles.members` of the run record, apart from the workers' `turns`, `tokens` and `metrics`, which stay the team's work. `spend.usd` is the team total including the roles; `spend.workers_usd` and `spend.roles_usd` split it, so the per-run cap, the suite cap and the ledger all include the roles, and the report shows `roles_cost_usd` beside `cost_usd`. A role member that fails or never stops does not invalidate the run: the workers decide the outcome, and once every worker has ended the roles get `grace_s` (default 120) to finish, then are stopped and recorded as `stopped-by-harness`.

  The supervisor and restarts. The supervisor's `{{RESTART_COMMAND}}` is `restart_member.py`, which only writes a request file; the harness, which holds the budget, answers it. A replacement starts only for a worker whose process has ended, at most `max_restarts` (default 1) per worker, as a new member (`c-2`) with a fresh clone of the origin and the victim's job text plus a short note. It is not a second session of the victim: it lacks the victim's private files and unpublished work, as a replacement on another machine would. Its cost counts as the roles' (`roles.replacements`), and its commits are by someone other than the victim, so the S6 git metrics (`recovered_by_commit_author`, `time_to_module_recovery_s`) count the recovery while the stream-derived survivor metrics, which read the scenario's own agents, do not see it. The fake agent treats a role arm as its base arm plus roles (a step for K2 or B1 also runs) and, in a role arm, turns `sync` into a branch push, `ready: NAME` and a wait for the merge; `integrate` and `restart` are the scripted role steps. Tested with the fake driver only.
