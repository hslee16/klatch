The coordbench fixture hash covers what ran, not how it was made (#1516, #1510; no schema change; 2026-11-24). `Fixture.sha256()` used to hash every file in the fixture directory, so editing a generator (`gen.py`, `gen_facts.py`, `build_history.py`) or having Python write `__pycache__` changed `fixture.sha256` in every record although nothing an agent sees had changed, and pre-registered analyses key on that hash. Fixture hash version 2 (`fixhash.py`) covers the files an agent can receive or that decide the outcome (setup.sh, template/, task texts, private/, seed and history files, fixture.json, and reference/, which no agent gets but which the checker is validated against and the fake agents replay) and, for a generated fixture, the generator's output: scale's template, reference, tasks and scenario map, and the history's commit ids in arm B0 and arm B1. It leaves out the generator sources named under `generator_sources` in fixture.json (their output is either committed and proved by `--check`, or hashed), `__pycache__`, `*.pyc` and editor leftovers; loading a generator no longer writes bytecode into the fixture.

The owner chose this option (B) on #1516 over a one-time re-baseline that would have repeated at every generator edit. The hidden checker directory is hashed apart as `fixture.checker_sha256` (the independent review's finding I8: `checks/` was missing from the run identity), and each agent's built prompt as `prompt_sha256`, with the run's working directory, binary path, room and restart command left as placeholders so two runs of one arm and task agree. The hash is memoised per `Fixture` object, so the records of one suite agree (the review found a hash computed per run). Records carry `fixture_hash_version: 2`; a record without the field is version 1. `report.py` groups by it with the mechanism `metric_version` uses (`metricver.split_by`): older records appear as `SCENARIO [fixture hash vN]`, the scaling table uses the newest, and a comparison across versions is flagged, so versions never pool silently.

The re-baseline happens once, before any real run: the hashes of chain, history, recovery, scale and specialists change because their generator sources left the hash (history and scale also gain the output sections); trivial, onefile, tallykit and injection keep their hashes. The two pilot records are the only real records and are version 1. With the definition fixed, the five generators the code health pass left alone were refactored with byte for byte identical output, and the new hashes are the same before and after that refactor.
