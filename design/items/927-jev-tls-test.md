The Jev HTTP transport is tested to verify the server certificate and host name against a local TLS server (#927; no schema change; 2026-11-24).
`jev/http/tests.rs` starts a loopback TLS server (127.0.0.1, a free port, rustls, one connection at a time, every socket under a timeout, the thread stopped and joined on every path) with certificates made at test time by rcgen: a throwaway CA and server certificates whose validity is computed from the system clock, so an expired certificate is expired by construction and no secret or date is committed. The transport is refused (a `Network` error with no detail, and the server saw no request, so the key was not sent) for a certificate from an unknown CA, a self signed certificate nobody trusts, an expired certificate, a certificate not yet valid, a certificate for another DNS name, and a certificate for another address; the shipped trust anchors (the web PKI roots) refuse a private CA; and a certificate from a CA the transport is told to trust is accepted and the request arrives with the key in the `Authorization` header over the verified connection.
To trust a test CA the file adds a test-only constructor (`HttpTransport::tls_loopback_for_tests`) and an `agent_config_with_roots` that `agent_config` calls with the web PKI roots; shipped code never passes another set. New dev-dependencies only: `rcgen` (as in klatch-server), `time` (no features) and `rustls` (ring), all already in the tree; no shipped binary links them, `deny.toml` is unchanged and `THIRD-PARTY-LICENSES.txt` is unchanged (cargo-about ignores dev-dependencies).
Mutation check: with `disable_verification(true)` every refusal test fails by assertion (`Ok("{}")` where `Err(Network)` was expected). The tests pin existing behaviour, so they passed on the first run. The host name check cannot be switched off apart from the certificate check through ureq's configuration, so no mutation isolates it; the wrong name tests are paired with a test that accepts a certificate listing the right name among others, so they do not pass for the wrong reason. `tests.rs` was already past 600 lines and a second file would need a new `no_telemetry` allowlist entry, so the tests stay in it.
