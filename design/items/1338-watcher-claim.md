The gh-watch receiver holds a shared named claim watch:gh with a short lease, so a dead watcher is visible (#1338; no schema change; 2026-11-24).
With `--klatch-bin` the receiver takes `klatch claim ROOM watch:gh --ttl 90 --shared` in the isolated status room as the member it already posts as (no credential is issued or read; the klatch binary stays network-free and the receiver stays loopback). **Interval and lease:** renew every 30 seconds, lease 90 seconds: three intervals, so two missed renewals do not lapse it and a dead receiver is visible within 90 seconds; `--claim-renew` and `--claim-ttl` change them within `1 <= renew < ttl <= 300`. Renewal is the same claim again (the `ask:N` pattern), once per interval, never a burst after a stall.

    **Producer marking, conflict, stop:** `klatch stuck` (#1339) already reports any lapsed named claim, so nothing is marked. The claim is shared, so it conflicts with every scope; a second receiver binds its port, then claims, and a `refused:` answer makes it exit 2 without taking or releasing anything, which makes `ensure` idempotent across state dirs. Any other claim failure keeps the log working and retries next interval. A clean stop (SIGTERM, SIGHUP, Ctrl-C, which includes launchd bootout through the `serve` wrapper) releases the claim, so a deliberate stop raises no alarm; `kill -9` and a crash do not release, and the lapse is the signal. Only the fixed prefix `refused:` decides a conflict; no webhook or klatch text is printed or built into a command. Tests use a fake clock for the renewal logic and a fake klatch binary for the receiver. Known limit: #1586 (the store sweeps lapsed rows, so the lapse event is best effort).
