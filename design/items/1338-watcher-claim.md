The gh-watch receiver holds a shared named claim watch:gh with a short lease, so a dead watcher is visible (#1338; no schema change; 2026-11-24).
With `--klatch-bin` the receiver takes `klatch claim ROOM watch:gh --ttl 90 --shared` in the isolated status room under its own holder name `MEMBER.PID` (member names are unverified labels, so no credential is issued or read; the klatch binary stays network-free and the receiver stays loopback). **Interval and lease:** renew every 30 seconds, lease 90 seconds: three intervals, so two missed renewals do not lapse it and a dead receiver is visible within 90 seconds; `--claim-renew` and `--claim-ttl` change them within `1 <= renew < ttl <= 300`. Renewal is the same claim again (the `ask:N` pattern), once per interval, never a burst after a stall.

    **Producer marking, conflict, stop:** `klatch stuck` (#1339) already reports any lapsed named claim, so nothing is marked. The claim is shared, so it conflicts with every scope; a second receiver binds its port, then claims under its own pid-suffixed holder, and the real binary's `Error: refused: ` answer (matched exactly) makes it exit 2 without taking or releasing anything, which makes `ensure` idempotent across state dirs. Any other claim failure keeps the log working and retries next interval. A clean stop (SIGTERM, SIGHUP, Ctrl-C, which includes launchd bootout through the `serve` wrapper) releases the claim, so a deliberate stop raises no alarm; `kill -9` and a crash do not release, and the lapse is the signal. Only the fixed prefix `Error: refused: ` decides a conflict; no webhook or klatch text is printed or built into a command. With `--klatch-bin` the receiver refuses to start (exit 2) when `KLATCH_HOME` is unset or inside `.klatch` (case-folded, symlinks resolved), because a post would otherwise reach the live store too; a refusal is matched at the start of any stderr line (the #513 note may come first); a refusal after the first claim is retried once and then stops the receiver with exit 2; renewal uses the wall clock so a Mac sleep longer than the lease re-claims on waking; claim state changes are fixed-template INFO or ALERT lines in `gh-watch.log` (taken, not held, lost), never klatch text. The keeper lock is never held across the klatch call and a closed flag stops renewals after release. Tests use a fake clock for the renewal logic a fake klatch binary for the receiver, and, when a built binary exists, the real one (the refusal text the receiver relies on is the binary's, not a fake's). Known limit: #1586 (the store sweeps lapsed rows, so the lapse event is best effort).
