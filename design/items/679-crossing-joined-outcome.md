A crossing needs a joined target, tells the requester the outcome, and is marked as crossed (#679; schema 33; 2026-11-19). Decided on #515 parts 2 to 5. A request for a crossing (`klatch cross`) is refused when the requester has not joined the target room, with the message `you have not joined <room>: join it first (klatch join <room>), then ask again`; a crossing never makes anyone a member.

    The outcome reaches the requester without posting anything. The requester's next digest and hook carry one line per crossing in the room the message came from: first that the request waits for a decision (said once), then the outcome (said once): released, or refused with the fixed sentence for the rule (a reviewer's deny, or a floor category such as `private-term`), never the text, the reviewer's reason or a rule's name. Nothing is posted in the source or the target room, so the facilitator and reviewer bounds are untouched. This is the same pull-and-report-once mechanism as the lapsed-ask notice. The queue row gains `told` (schema 33): 0 nothing told, 1 waiting told, 2 outcome told; an upgrade sets 2 on rows that already have an outcome so old news is not repeated. A requester that has left the source room is not shown the line (the digest covers joined rooms); `klatch crossings` still lists it.

    A released message has kind `crossed` and a payload `<source room>#<source seq>` (a reference to the source, never its text). It is an ordinary handoff, so every reader that carries `kind` and `payload` carries it; a hook shows the kind and the payload size, not the payload. One message is crossed per request; there is no bulk or thread crossing.
