Three more test waits are removed, with no change to production timing or cost (#1353; no schema change; 2026-11-22).
After the Argon2 change (#1352) the CI test step was still bound by total CPU, and three waits remained that no test needed. The worker test that proves a used credential outlives its idle timeout up to its cap spent 9 s in real sleeps; it now runs on the test clock (`KLATCH_NOW_FILE` moves the time of the launcher and the worker, so nothing sleeps) in the CI step that already builds with `--features test-clock`, and it asserts more than before: it issues at second 0 with an idle timeout of 3 s and a cap of 8 s, posts at 2, 4, 6 and 7 s all work, and the first request at 8 s is refused although the post at 7 s had renewed the idle timeout past the cap, so the cap alone explains the refusal (the real-time form was also refused by the idle timeout). The renewal and cap rules are separately tested on a fake clock in the gateway. The stand-in `secret-tool` and `busctl` of the keyring tests were each a script written for the test; on macOS the first start of a new executable costs about 150 ms and, under load, those starts queue for seconds (3 to 8 s per test, with no retry involved: the "Text file busy" retry of #570 ran zero times in every measurement). They are now links to one shared script, kept in the temp directory under a name that carries its content hash and trusted only when it is ours and not writable by others, that reads the test's body from a file beside the link. The klatch-bench world tests needed a klatch binary only to make a store, so they use `find_plain_binary`, which asks cargo for the workspace's own build (a no-op after a workspace build, with a content-named private copy under a file lock as before) instead of `find_binary`, which compiles a second test-clock klatch into `target/bench-bin` for every fresh build; scenarios that move the clock still use `find_binary`.

The wake test `a_message_it_pointed_at_never_wakes_it_again_but_a_new_one_does` that ended with SIGKILL once was not reproduced (204 runs with six in parallel and 200 one at a time all passed). `klatch wake` takes a lock file and never signals another process, and nothing in klatch sends SIGKILL, so the kill came from outside the test (the machine was shared with other builders that kill processes); it is left as is and noted on #1353.
