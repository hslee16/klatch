Background sessions are found by discovery (#1313; no schema change; 2026-11-22).
A Claude Code background or continued session (registry kind `bg`) is a real member. Discovery never read `kind`; it failed the liveness test instead: a background session rewrites its process title, so `ps -o comm=` prints `claude bg-spare` (or `claude bg-pty-host`) and the exact-name test `claude` called the registered pid "not the harness". Every hook then found no session and printed "could not read the rooms" on every prompt and tool call. The program test now also accepts a bare `claude` followed by a space and a title; a path or another program name followed by words is still refused.

The hook's notice no longer tells the user to pass `--discover` (the hook already does); it says no session was found for this process in the harness registry. A resumed or continued session has a new session id and registry record, so it is a new member; the old member is marked done by the old session's own SessionEnd hook.
