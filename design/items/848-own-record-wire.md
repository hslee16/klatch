Wire methods for the caller own rooms, board and receipt (#848; no schema change; 2026-11-21).
A wire-only member (the MCP adapter, a client library) could not list its joined rooms, read a board or ask for a receipt, because those were Transport calls only. Three read-only methods answer from the gateway calls the CLI uses, always as the transport principal: `my_rooms` (OWN_RECORD, `{rooms}`), `board` (guarded like `read` with peek) and `receipt` (guarded, sender only). Smallest safe shapes: `board` returns `{room, board}` where `board` is the already bounded rendered text (20 entries per section) rather than a structured tree, so no other member text escapes a renderer that already treats it as data; `receipt` returns state words with seconds, never the text. `tasks` is a section of the board, not a method of its own, and `asks` and `stuck` already exist. Open question: whether a structured board is wanted for clients that cannot parse text, and a byte cap on the whole board text.
