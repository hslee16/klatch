Hooks that `klatch init` installs now carry an explicit 30 second timeout, so the first Keychain read after a migration (bounded at 5 seconds) can fail with its message before Claude Code kills the hook (#1246; 2026-11-21).
The Claude Code default hook timeout was not verified (#372 left it open), so the entry no longer relies on it. `init` writes `"timeout": 30` on the SessionStart, UserPromptSubmit, PostToolUse, SessionEnd and the optional claim hook, adds it to an older entry that has none, raises a lower one, and keeps a longer one a user chose. The wake hook keeps its 3600 s. The Codex hook file is unchanged. The 5 second limit is now the shared constant `KEYCHAIN_READ_LIMIT_SECS` in `keys`, and a test requires every installed entry to exceed it. The Keychain read message already says what to do (answer the dialog with Always Allow, or run the build that stored the key). The result is recorded on #372.
