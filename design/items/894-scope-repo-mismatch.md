A declared scope keeps winning; a mismatch with the derived repository is made visible (#894; no schema change; 2026-11-21).
A member's scope is the one it declared (flag or KLATCH_SCOPE), else the one it already has, else for a coding session the repository derived from where it started (item 27). The human decided on 2026-11-21 that this order stays: a declared scope wins for delivery and for claims, so two sessions in one repository that declared different scopes do not collide, which is the member's own statement. What changes is that a difference is no longer silent. When a member's scope names a repository (`git:...`) and the repository derived from where it runs (the #181 observation) is another, `who` and the board show the fixed marker `scope!=repo` on that member's line (the `MemberPlace` carries one boolean, `scope_differs`, filled by the gateway from the member's recorded scope and observed repository; the `who` wire answer adds `scope_differs: true` only when set), and the member's own SessionStart digest carries one fixed line saying so, once per session start and not on later hooks. Neither shows a path or either repository's name beyond what `who` already showed (the observed repository id and the short directory name).

A scope that names no repository (a role, a bot's area, a project word) never differs, so non-coding members that work from anywhere (#297) are never marked. The repository value stays an observation: a directory can name another repository's git dir, so the marker can be forged to appear or hidden, and nothing grants or refuses access by it. Conflict detection is unchanged; a real missed collision would be the evidence for counting both the declared scope and the repository in claims (the ticket's option 3), which is not built. No operation changes, so the authorization audit has no new row.
