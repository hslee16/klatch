The asks stop-waiting notes reach an agent that never times out a wait (#789; no schema change; 2026-11-21).
The asker's give-up note (#200), the helper's gone-asker note (#226, #790) and the ask-cycle line (#273) were printed only by a `klatch wait` that timed out (the cycle line before a wait blocks), so an agent that never lets a wait time out never saw them. **Design chosen (human, option B):** a derived rule. `domain::derived_asks_notes` computes the three notes from the room as it is now: the open asks, the live claims, the members and the liveness probe. Nothing is stored, so the same lines come at every hook digest while the condition holds, and none once it clears (ask answered or closed, claim released, asker back). The alternative, a report-once table like `asks_reported`, needs a schema bump and was not chosen. Each digest room carries `asks_notes`, rendered as indented lines among the member's own items (so a room with only these is not quiet and they sort first). `wait` (when it hands over messages) and `read` (not a peek) print the same lines as trailing `klatch: ` lines after the dm help; `wait` leaves the cycle out there because it already says it before it blocks. **Bounds:** fixed templates over validated names, an ask number, minutes and a count, never message text; at most three lines of each kind and one line counting the rest; the lines are units of the digest, so the digest byte budget (item 50) cuts them whole with its existing "more not shown" line; a room with no open ask costs one read and no probe. The gone-asker probe in the hook uses the same lease source as `process_exited` (unknown counts as alive).
