The bench gains four scenarios that need a credential or a verified harness, and a helper that issues one in its own store (#1049, follows #1045; no schema change; 2026-11-20).
#1045 skipped four groups because the bench had no way to act as a verified principal. **Helper:** `World::issue_worker` runs the launcher command `klatch worker issue` inside the world, so the credential lives only in the world's temporary store and key directory and its bundle sits under the world's temporary home; the live keychain item and `~/.klatch` are never read or written. `World::spawn_worker_piped` starts a worker process that stays up (`serve --stdio`), so a scenario can end a credential under a running process. A verified harness comes from the existing `FakeHarness` (a live `claude` process with a registry record), which is what the gateway accepts as evidence. **Scenarios** (new file `proto/klatch-bench/src/scenarios/credentials.rs`): own-record refusal after a credential ends (#835: at the door a revoked or idled-out bundle is refused, and on a live wire the own-record methods are refused with the `credential` rule once the launcher revokes under the running process); the release audit names the releaser (#836, #679: a reviewer's allow is audited as `applied by rev`, the released text arrives in the target room with its source pointer, and a judge deny is audited and releases nothing); `klatch worker list` shows the cap and the last renewal (#948, #1007: the idle timeout restarts on use, the cap counts down, renewal near the cap stops at the cap, and the worker is refused past it); the advisory mark in a flag-mode room-require room (#878, #990, #1032: a verified session is flagged where a capability is degraded and marked on `who`, `read`, `history` and the stream frame, a member admitted before the requirement is not, a verified session is admitted clean where it has the capability while a caller that names no harness is flagged for it). **Limits:** the release audit naming the judge as releaser needs an allow verdict from the opt-in hosted judge (a `claude` binary of the operator's), which the bench does not run, so only the reviewer path and the judge's deny are covered; credential expiry on a live wire cannot be exercised because a running process's clock is fixed by its environment, so expiry is covered at the door only; `tail` has no CLI command, so it is covered only through `history` and the stream. CI does not run the bench.
