The stale ask proposal follows a fixed five stage schedule, so a restart does not repeat it and a standing ask never floods the room (#1570; no schema or wire change)
What the ticket asks. #1570 (found while building #1205) says the stale ask line holds the ask's age in seconds, which grows while the ask stands. A restarted mediator seeds its done set by comparing each planned proposal's text with its own earlier posts exactly (#906), so the grown age made the text differ and the line was posted again once.

    The fix, and why not the #1205 lead. #1205 matched by a fixed lead because a long exchange is one case until it ends. A stale ask should be able to draw a later, firmer pointer as it gets older, so the age stays in the state but never in the text. The line holds only the start of its stage (`has had no taker for at least {floor}.`), never the age, so inside a stage the text is the same on every run and the exact-text seed matches it after a restart. The wording is otherwise unchanged: it names the asker, the ask number and the same two pointers, and stage 0 reads exactly as before apart from the age number (`at least 60s`).

    Schedule and why. The stages start at ages 60 s, 600 s, 1 h, 6 h and 24 h, and the line names them `60s`, `10m`, `1h`, `6h`, `24h`. There is no stage after 24 h. A fixed width bucket (an earlier draft used 600 s) would give an ask nobody answers a new line every 10 minutes forever, six an hour per ask in the shared room, which is worse than the bug. The repeat rate here falls and stops: an ask draws at most five proposals ever, however long it stands (a 30 day old ask draws one line from a fresh mediator and none after), and the five proposals per pass cap stays.

    How it is kept. A proposal carries a `stage` (0 for every other kind; the stale ask's is the schedule step its age has reached, at most 4). The mediator's done set maps a case key to the stage already proposed on. A pass skips a case whose stage equals the stored one and posts when it differs. A restart seeds the stage from its own earlier posts by exact text (only the mediator's own member name counts), so a post of an older stage does not match the standing ask's newer line and the new stage is posted exactly once. The long exchange keeps its #1205 lead and stage 0. A case that ends is forgotten as before.

    Known limit. A restarted mediator seeds only from the bounded history window (`HISTORY_MAX_MESSAGES`); a stage line that has scrolled out of it is posted again once. That is the same limit #906 has for every proposal.

    Tests. A fresh mediator over the same store does not repeat the line a minute later; the line holds no number that changes inside a stage; crossing a stage gives exactly one new proposal, across restarts too; a running mediator posts once per stage; an answered (claimed) ask gets none; two asks that cross their stages at different times do not interfere; an hour long ask with a restart at every pass yields only the three stages reached; a 30 day ask yields at most five lines in total and none after the last stage; the domain test pins the stage and floor at every schedule edge. Mutation checks, each restored: stage always 0 (domain and running-once tests fail); age back in the text (8 fail); dedup by key only (running-once test fails); no seed (8 fail); no stage cap, the stage growing daily past the last (domain and five-lines tests fail); dropping the sender filter (2 fail); dropping the claimed skip in the stuck rule (answered ask test fails).
