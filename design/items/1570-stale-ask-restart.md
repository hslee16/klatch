The stale ask proposal is fixed within an age bucket, so a restart does not repeat it (#1570; no schema or wire change)
What the ticket asks. #1570 (found while building #1205) says the stale ask line holds the ask's age in seconds, which grows while the ask stands. A restarted mediator seeds its done set by comparing each planned proposal's text with its own earlier posts exactly (#906), so the grown age made the text differ and the line was posted again once.

    The fix, and why not the #1205 lead. #1205 matched by a fixed lead because a long exchange has one case until it ends. A stale ask differs: the owner wants a later, more stale ask to be able to draw a fresh proposal, so the age must stay in the state, not be dropped. The age is bucketed: `stage = age_secs / STALE_BUCKET_SECS` with a 600 second bucket, and the line holds only the start of its bucket (`has had no taker for at least {floor}s`, floor = bucket start, never below the 60 second stale window), never the age itself. Inside a bucket the text is the same on every run, so the exact-text seed matches it after a restart. The wording otherwise is unchanged: it still names the asker, the ask number and the same two pointers.

    Bucket rule. Stage 0 is an ask from the stale window to 599 seconds old, stage 1 is 600 to 1199, and so on. A proposal now carries a `stage` (0 for every other kind of proposal). The mediator's done set maps a case key to the stage already proposed on. A pass skips a case whose stage equals the stored one, and posts when it differs, so crossing a bucket gives exactly one new proposal, from the same run or a restarted one (the restarted run's seed matches the posted text of the new bucket only). The long exchange keeps whole-case behaviour (stage 0, its #1205 lead unchanged). A case that ends is forgotten as before.

    Cost. The bucket makes a very long stale ask draw one more line every 10 minutes it stands, which is bounded by the one-post-per-case-per-bucket rule and the five proposals per pass cap. Known limit: the first pass after a restart posts again when the posted line is of an older bucket than the standing ask, which is the intended new stage.

    Tests. A fresh mediator over the same store does not repeat the line a minute later; the line holds no number that changes inside a bucket; crossing a bucket gives exactly one new proposal, including across restarts; a running mediator posts once per bucket; an answered (claimed) ask gets none; two asks with different bucket crossings do not interfere; the domain test pins the stage and text across the bucket edges. Mutation checks, each restored: stage always 0 (4 fail); age put back in the text (6 fail); bucket start off by one bucket (2 fail); key-only dedup (running once per bucket test fails); seed storing the wrong stage (6 fail); no seed (6 fail); no forgetting of ended cases (2 fail); dropping the sender filter (2 fail); dropping the claimed skip in the stuck rule (answered ask test fails).
