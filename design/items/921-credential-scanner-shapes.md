The credential scanner reads passwords, npm tokens and labelled secrets (#921; no schema change; 2026-11-19).
`credential_kind` (R20) matched only prefixed token shapes, so a post carrying a password in a URL or a command, or a secret after a label, was stored and could cross with no model in the loop (the judge eval of #914 counted 16 such corpus items). It now also recognises, each named by kind and never echoed: "an npm token" (`npm_` then 36 letters and digits); "a password" (the part after the first colon of the user info in `scheme://user:PASSWORD@host`, the value of `curl -u`/`--user user:PASSWORD`, `mysql -pPASSWORD` and `--password=PASSWORD`); and "a labelled secret" (the value after `password`, `passphrase`, `passwd`, `passwort`, `pw`, `pass`, `sessionid` or `secret`, directly or after a later `is`, `ist` or a word ending in a colon within fourteen words, so `passphrase is X`, `pw: X`, `password = "X"`, `| DB_PASSWORD | X |` and `Das Passwort ... ist X` all match; and a base64 value of 40 or more characters after `token`, `apikey` or `api_key`, the shape of a Kubernetes secret value).

A value counts only when it is not a placeholder (`<...>`, `{...}`, `${...}`, `*****`, `xxxx`, `%VAR%`, `password`, `changeme`, `redacted`), is at least 8 characters for a label (3 for a URL or command) and, after a label, holds a digit or one of `!#%^&*+=~@$`, so prose such as "the password is required", a hyphenated name (`billing-db`) or a path (`secret/prod/db`) passes. A label must start a word (`DB_PASSWORD` counts, `bypass` does not) and not run into a longer word (`password_hash`, `secrets.X`). The rules are deliberately narrow; a secret the shape cannot see (a passphrase of plain words, a value split, reversed or encoded by the writer) still needs the model judge.

Measured with `klatch-bench judge-eval --judge rules` on the main corpus: secret-credential and code-log-secret now have 0 leaks in dev and test (18/18, 9/9, 12/12, 6/6), over-blocking stays 0 of 118 (dev) and 0 of 79 (test), and the secret-lookalike category stays 100 percent. On the hard corpus over-blocking is 0 and the remaining secret leaks are the adversarial encodings listed in the follow-up ticket.
