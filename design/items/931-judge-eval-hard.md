A hard second judge-eval corpus (#931; no schema change, no new wire method, bench data and two loader additions; 2026-11-19).
The #914 corpus cannot rank strong judges: on its dev split on 2026-11-19 the rules judge scored 73.7 percent, Jev 87.4, Claude Sonnet 98.0 and Claude Opus 97.0, so Opus did not beat Sonnet (4 to 6 wrong items of 198 each) and no Jev confidence threshold could be read from so few errors. This item adds `proto/klatch-bench/judge-eval/corpus-hard.jsonl`, 271 items written to be hard for a Sonnet-class judge, with its own README (`README-hard.md`: the clarified labelling rules H1 to H6, how the items are hard, the counts, the label check). Same schema and placeholder rules as the first corpus, plus an optional `origin` field (`design` or `search`), a `passphrase` placeholder kind and placeholder transforms (`{{fake:github|b64}}`, `|hex`, `|pct`, `|rev`, `|sp4`, `|sp1`, `|zw`, `|cut:A:B`) so encoded, spaced, reversed and split secrets are stored as placeholders. Its own frozen test split (`FROZEN_HARD_TEST_DIGEST`, `HARD_SPLIT_SIZES`); the first corpus's digest is unchanged. The runner gains `--origin design|search`.

    Two groups, never pooled. Design items are hard by construction: obfuscated and split secrets, secrets in structured text, word-shaped passwords, paraphrased private business content, the to-internal split of the rules (the same text labelled differently for public and internal readers), personal data in many formats and in several forms at once, indirect, quoted, encoded, multilingual and look-alike-letter injections, harmless text that quotes injections, scrub terms with innocent meanings and obfuscated spellings, and 11 to 26 KB items with one sentence that matters, each with near-miss allows. Search items were found by running claude:sonnet over candidate items and keeping some it got wrong whose label survived a re-check against the written rules. Search items are selected against one judge, so that judge scores near zero on them by construction and other judges are compared on a set biased against Sonnet in particular: report them separately, never as an accuracy estimate, and use the design items (`--origin design`) for the unbiased number. The runner prints a note when a selection mixes the two.

    How to run each judge on it (from `proto/`; the dev split is the default, add `--split test` only for a final score, `--out FILE` to keep the rows, and `--origin design` or `--origin search` to score the groups apart):

        cargo run -p klatch-bench -- judge-eval --judge rules --corpus klatch-bench/judge-eval/corpus-hard.jsonl --origin design
        cargo run -p klatch-bench -- judge-eval --judge claude:sonnet --corpus klatch-bench/judge-eval/corpus-hard.jsonl --origin design --out sonnet-hard-design.json
        cargo run -p klatch-bench -- judge-eval --judge claude:sonnet --corpus klatch-bench/judge-eval/corpus-hard.jsonl --origin search --out sonnet-hard-search.json
        cargo run -p klatch-bench -- judge-eval --judge claude:opus --corpus klatch-bench/judge-eval/corpus-hard.jsonl --origin design --out opus-hard-design.json
        doppler run --project governingdocs --config dev_alex -- cargo run -p klatch-bench --features jev-http -- judge-eval --judge jev:<pinned model>:0.01 --corpus klatch-bench/judge-eval/corpus-hard.jsonl --origin design --out jev-hard-design.json

    Sonnet on the dev split, one run after the freeze: design items 93.8 percent [89.5, 97.2] (98.0 on the first corpus), strict leaks 6 of 80 (7.5 percent), over-blocking 2 of 66, one defer (a 22 KB redaction hit the per-call budget cap); search items 1 of 15 right, as their selection implies. The design errors are all personal data, the to-internal rule, over-blocked near misses and a long item; every secret and injection item on dev was right, so this set separates Sonnet mainly through personal data and redaction, and should still separate Jev (weak on injection and redaction on the first corpus) from Sonnet. The search used $2.24 of a $10 cap; all runs together $4.64. Details and the per-item errors are in README-hard.md.

    Limits. Every label is one author's (the agent that wrote the items), checked by a blind re-read of 50 items by a fresh agent of the same model (README-hard.md); an independent blind labelling with a different model is still to come, and the clarifications H1 to H6 are where a second labeller is most likely to differ. The corpus is still small (110 test items) and synthetic, so a category of a dozen items moves by about eight points per item. Hard items are hard for the failure modes the author could imagine and Sonnet showed on the candidates; a judge can be weak in ways this set does not probe. The search set is small and biased (above). The claude judge's prompt states the README rules but not the H1 to H6 wording, so on those items it is graded on applying the told rules to new cases, which is the point, but a disagreement there may be a rule a reasonable reader resolves the other way. Long items cost more tokens than the first corpus's (up to about seven thousand input tokens each). No Jev or Opus run on this corpus is part of this change.
