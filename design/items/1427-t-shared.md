The coordination bench runs scenario S2 in a shared working tree, topology T-shared (#1427; no schema change; 2026-11-23).
Epic #1362 needs the case where agents really edit the same file at the same moment, which a per-agent clone cannot show: with clones, a collision surfaces at the merge and nobody loses work without a trace in git. `run.py --fixture onefile --variant shared` makes ONE working tree, a clone of the run's bare origin, and starts every agent in it. Each agent keeps its own identity through its process environment (member name and `KLATCH_NAME`, `GIT_AUTHOR_NAME` and `GIT_COMMITTER_NAME`), its own stream, prompt and error log in the per-run log directory, and its own HOME and TMPDIR under the run's scratch, all outside the tree, so the tree holds only the repository and the agents' edits (`klatch init` runs once for the tree; its hooks are the same for every member). A fixture with private files is refused for T-shared. The variant is recorded as the separate scenario `onefile-shared` and never pooled with T-clone.

The prompts are variants, `arms/common-shared.md` and `arms/<arm>-shared.md` for B0, B1, K1 and K2: they say that colleagues are editing the same files in the same directory right now, that a save replaces the whole file, tell the agent to re-read a file before changing it, to commit only its own files, and have no clone, pull or push. `arms/check_parity.py` runs every existing check on the shared set as well (lengths within 15 percent, outline, prefixes, klatch words, composition) plus a check that no shared file mentions an own clone, a push or origin; the role arms have no shared variant.

The final state is defined once: when agents have left changes uncommitted, the harness commits the whole tree under the neutral author `harness-final` (recorded in `scenario_metrics.final_commit`), and the hidden checker runs on a clone of the tree's HEAD, so it scores what is on disk whether or not anyone committed. The poll that finds `time_to_first_pass_s` runs on a copy of the live tree.

Lost edits cannot come from history alone, because two saves of one file leave one version. They are measured two ways. A light watcher thread reads the shared file every `--snapshot-s` seconds (default 5) and whenever an agent exits, and keeps the versions that differ; a ticket whose behaviour (the checker's `--file` mode) is present in some snapshot and absent from the final tree is overwritten, source `snapshot`. Second, the agents' own Write, Edit and MultiEdit calls on the file are read from their streams: an event whose added lines (the lines the initial file lacked) are missing from the final file is a `lost_edit_events` entry, and its agent's ticket, if it fails in the final tree, is overwritten with source `stream`. `overwrites` is the union, with the split into silent and after-conflict as in T-clone. The resolution limit is stated in every record (`scenario_metrics.snapshots.limit`) and in `scenarios/s2.json`: an edit written and overwritten between two snapshots by an agent that keeps running is invisible to the snapshots; the stream measure sees file-tool edits only, counts an agent's deliberate removal of its own earlier line as lost, and cannot see a change made by a shell command such as sed. A shorter interval narrows the first limit at the cost of more checker runs.

The fake agent gained `read_into`, `write_from_var`, `signal`, `wait_signal` and `barrier`, so a test makes a deterministic lost update: two agents read the file, both write, the second silently overwrites the first. Tests cover a cooperating shared run, the lost update found by the snapshots and the checker, found by the exit snapshot with a long interval, found by the stream only when no snapshot held it, identity per agent in the shared history, harness state outside the tree, the final commit, the shared prompts and their parity, and unchanged T-clone behaviour. Nothing ran a model or spent money; a real T-shared run needs the human's budget approval like any other.
