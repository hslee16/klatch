Golden tests for the admin proof, key custody and admin acts (#1480; no schema change; 2026-11-23).
Test-only work that pins the observable text of the security code byte for byte before the code health refactors of it (K03, the K11 security slice of #1452 and others). No production file changed. The tests characterise behaviour that already exists, so they were green on the first run against the current main by construction; what they prove is that a later change of that text fails with a readable diff, not that the text is right. A planted change of one message in `proof/mod.rs` failed four of them with the changed line shown, and was reverted.

The helper is `tests/common/golden/` (`check`, `Sheet`, `Scrub`, `diff`, `forbid`). A golden is a committed text file under `tests/golden/`; a test compares to it and fails with a line diff (`-` committed, `+` this run). It is regenerated only with `KLATCH_WRITE_GOLDEN=1`, then the change is read in git. `Scrub` replaces what varies from run to run (the throwaway home, the binary path, terminal labels, process ids, ages, the countdown of a lockout wait, the time left on a worker credential) with fixed words, so a second run gives the same text. `forbid` refuses to compare or write a text that holds a passphrase or recovery code the test typed, so a regeneration cannot commit a secret. The test passphrases are typed through a pty by the existing harness, stores are throwaway, and the live `~/.klatch` store and the Keychain are never touched.

Pinned: the prompt of every admin and every launcher command with a wrong passphrase (`golden_admin_prompts`); the argument sanitiser output (printable ASCII only, a word of 48 characters whole and one of 49 cut to head and tail with the count unseen, a long command cut at a word, text before the family word), the store path line, the hidden recovery code and the shell text; every terminal refusal (no terminal, no passphrase set, standard output or error not the terminal, input or output on another pty, a piped confirmation or shell) for every command (`golden_admin_refusals`); the lockout with its wait, the per-terminal count, the recovery-code attempt limit, setting and changing the passphrase, and the typed confirmations (`golden_admin_limits`); the audit rows of every admin act, of the proof (failed, locked, refused, set, changed, reset, recovery attempts) and of the launcher commands (`golden_admin_audit*`); the hook commands, diff and listing of `klatch init` and `klatch consent` for all eight combinations of passive claims, checkpoint and machine status (the Stop hook and the fixed flag order), the whole settings file for the other consents, every switch and the refusals (`golden_consent_hooks`); and the discovery refusals for a subagent, a process with no session, and the first passphrase from inside a coding-agent session (`golden_discovery`).

Not pinned: the wait of a lockout as a number (it counts down in real time, so it is `<N>`; the schedule is covered by the unit tests of `proof::limit`); the text of `stats` (the K01 stats golden owns it; here only its audit row); the output of acts that print a secret (`recovery`, `rotate-key`, `rotate-label-key`, `export`, `run-archive`, `worker issue`), where only the audit rows are kept; the Keychain and Linux keyring backends of `keys/` (they need a real key store); the key bundle bytes and the label rotation internals of `member/custody`, which have their own tests; the harness conformance and probe text; the Codex `hooks.json` files; and the user-scope settings. The golden of a refusal that depends on the terminal driver (the pty layouts) is as stable as the existing pty tests are.
