A hosted verdict below a confidence band goes to the reviewer and the audit records it (#1013; no schema change; 2026-11-21).
The opt-in hosted judge (#960) returns allow, redact or deny with a confidence from 0 to 1. A verdict whose confidence is below the band (default 0.7, set with `klatch judge run --hosted-confidence-band <0..1>`, which needs `--hosted-judge`) is not applied: the judge answers defer, the item stays queued for the reviewer, and the drain writes one audit row (action `judge-defer`, target `room#seq`) whose detail names the hosted verdict, the confidence and the band, never the message text or the model's reason. A verdict at the band or above stands as before. The trait `Judge` gained `judge_noted`, which returns the verdict and an optional note for a deliberate deferral; `Narrowed`, `Breaker` and `BelowCeiling` forward it, and a plain failure still has no note. The breaker treats a noted deferral as an answer, not a failure, so a run of unsure verdicts does not open it. A resident loop sees a queued item every pass, so the audit row is written once per queued item (checked with `last_audit_ts` since the item was queued). Tests use fake runners only.
