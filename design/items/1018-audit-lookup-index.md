An index serves the newest-audit-entry lookup (#1018; schema 35; 2026-11-20).
The store query `last_audit_ts(action, target, since)` (#1007) filters `admin_audit` by action, target and ts, and with no index it scanned the whole table once per credential in `klatch worker list`. Schema 35 adds `admin_audit_action_target_ts` on `(action, target, ts)`: the equality columns first and ts last, so the `MAX(ts)` is read from the index alone. It is created by migration `migrate_v34` (idempotent, `CREATE INDEX IF NOT EXISTS`) and by the fresh-store schema; existing rows are kept. The other audit read, the newest N entries by id, uses the primary key and is unaffected. Tests: a version 34 store gains the index and keeps its rows, and `EXPLAIN QUERY PLAN` of the lookup names the index and does not scan. `VERSIONING.md` records schema 35.
