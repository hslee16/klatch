The integrator process: a helper outside the klatch binary merges the queue with its own gh and git login (#866, step 3 of epic #863; no schema change; 2026-11-20).
The merge queue (#864) and the `merge:main` claim (#865) say who may merge and what is waiting; this item is the member that does the code host work. Decision: it is a shipped helper, `proto/scripts/integrator` (bash and `python3 -I`, as `pr-sweep`), run by a member the human granted the `integrator` role, on its own machine, with its own `gh` and `git` credentials. The klatch binary stays network-free and credential-free (the `no_telemetry` test is untouched); the helper reaches klatch only through the `klatch` command line (`wait`, `board`, `post`, `claim`, `release`) and identity is the environment as for every helper.

    Events. The helper runs `gh webhook forward --repo <repo> --events pull_request,check_suite,workflow_run` as a child of its own process (it needs repo admin; gh creates a temporary webhook and removes it on exit, so the helper stops it with TERM and never `kill -9` first). Payload text is data: a normalizer keeps a number, a state, merged, a head sha, a status and a conclusion, each checked against a fixed shape, and drops titles, bodies, branch names and logins before anything else reads them. Events are lost while the forwarder is down and GitHub sends no event when a PR starts to conflict, so the helper reads the open PR list at start and every few minutes (at most 300 s), and the `mergeable_state` of each open PR after every merge; a queued PR that then conflicts in code is dropped at once. A cancelled check is a failure only for the PR's current head sha (it is only looked up for that sha), a check suite on main with no PR goes to a side log for #867 and never changes the queue. One forwarder per repository has been tested; concurrent forwarders have not.

    Waking and the claim. With an empty queue the helper holds nothing and waits in `klatch wait <room> --only ready:`, so klatch wakes it and GitHub is not polled for work; the queue is read from the board (digits and a state word only). It takes `merge:main` to prove the role at start (a refusal is exit 2 with the next step named), takes it again when there is work, renews it at each step and reconcile while the forwarder is alive, and declares the two long steps (the gate, the wait for checks) with a bounded `parked:` post, which is what the park rule of #865 is for. A dead forwarder gets no renewal: it is restarted, three quick failures in a row end the process with the claim released, and a process that goes silent lapses at the lease. A signal releases the claim, stops the forwarder and exits 0.

    Per PR: a `git merge-tree` pre-check (a code conflict posts `dropped: #N conflict` before anything is touched), `integrating: #N`, a merge of `origin/main` into the PR branch (never a rebase, never a force push; docs conflicts keep both sides through the resolver of `pr-sweep`), the gate, a plain push, `checking: #N`, the wait for the check runs of the current head sha to be green (an event wakes it; the check runs of that head are read before merging), `gh pr merge --match-head-commit`, a read that says merged, `merged: #N`. Any failure posts `dropped: #N <reason>` with a reason from a fixed list (`conflict`, `checks-failed`, `closed`, `timeout`, `head-changed`, `error`) and moves on. Every word posted is a fixed template of an integer and a listed word, never a PR title, body or branch text; a branch name is used in one git command only when it is a plain name, and a branch of another repository is not integrated.

    Limits. The helper trusts the members that can push to the repository, since it runs the project gate on a PR's content. A process stopped mid PR leaves the entry integrating or checking and the next start redoes it. Verifying main after a merge and reverting it are #867; retiring `pr-sweep` and `pr-ledger` is #868; klatch-server work is #1056. No bench scenario: the bench drives klatch members and cannot run this process against fakes of `gh` and a git remote. Tests: `proto/scripts/test-integrator.sh` (in the gate): a fake `gh`, a fake `klatch`, a fake gate and temp git repositories, with webhook fixtures shaped after GitHub's documented payloads; the scenarios are the ready word waking the helper through waiting, integrating, checking and merged, a code conflict, a docs conflict, a failed gate, a failed and a cancelled check (and a cancelled one for an old head, ignored), a check suite on main, a forwarder whose events are lost, a forwarder that dies once and one that cannot run, the claim renewed and released on a signal, a plain member refused, hostile titles and branch names that never reach a posted word or a command, and a fork branch. The tests were written after a first draft of the script, so they were red only because the script was absent when first run. Operator docs: `proto/scripts/INTEGRATOR.md`.
