Unit tests make their scratch directories with TestDir (#812; test only; no schema change; 2026-11-20).
About 35 test helpers inside klatch/src (anchor, identity, custody, scope, admin and roles command tests, harness, keys, gateway system lease, the SQLite leases, integrity and archive tests, the session tests) made a directory under the temp directory by hand and removed it as the last line of the test, so a failing test left it behind and nothing capped what it wrote. They now use `store::test_dir::TestDir` (removed on drop, also on a panic, capped at 256 MiB by the guard thread), and the name carries a per-call number, so two calls with one tag are two directories. A helper that returns an open store returns `test_dir::In<T>`, which derefs to the value and removes the directory after the value is dropped. The binary crate (identity, custody, scope, roles, admin, anchor) compiles the same file into its tests with a path attribute, because the library's `pub(crate)` module is not visible there.

The scan test `no_unit_test_makes_a_temp_directory_by_hand` fails when any file under klatch/src calls `temp_dir()` outside the guard itself, a `TMPDIR` handed to a child process, and the live jev report file, so a new helper cannot go back to the by-hand form. It was red against the 35 old sites first. The integration tests under klatch/tests and the bench crate cannot reach the module and are tracked in #995.
