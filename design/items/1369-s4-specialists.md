Scenario S4 of the coordination bench is built: ask and answer across three specialists, with a repeat and a late ask (#1369; no schema change; 2026-11-23).
Epic #1362 needs a scenario where the only way to be correct is to ask, and S4 is it: fixture F4 `specialists` is a small Python package (`linkkit`, four modules) owned by three agents, each holding one private specification file (`SPEC-FRAMING.md`, `SPEC-ROUTING.md`, `SPEC-LEDGER.md`) that the other clones lack, because the harness now copies a fixture's `private/<agent>/` files into that agent's clone only, untracked and excluded from git, never into origin. Every agent's functions need constants that only another agent's file defines; the constants are arbitrary, drawn from a fixed seed by `fixtures/specialists/gen_facts.py` (reproducible, tested) so none is inferable from a name and none is a conventional default, and each also has a superseded revision-2 value listed in the file, so a holder who answers from the wrong line gives a stale value. The visible tests check only types, so a guess passes them and only the hidden checker (`checks/specialists/`) sees it. Seven slots (one function each) make the units, 0 to 7: the spec's six needs plus a's second-phase need.

    Two needs are designed to test history. MAX_PAYLOAD was asked and answered before the run by a seeded pair (K arms: three posts into the room by two seed members before any agent starts; B1: a line on the seeded `TASKS.md`), so agent c asking again is a repeat and `klatch find` or reading the board avoids it. LEDGER_MODULUS is needed by b early and by a late: a's second phase starts only after b has published, by when c, whose job is small, has finished and stopped; a late ask goes to a holder that is gone and can be answered only from history (or from reading b's published code, a threat to validity the metric text states). The checker reports per slot correct, wrong (with which conventional default or `other`), stale, unanswered or broken, plus wrong guesses, unanswered dependencies, a committed private file and conflict markers.

    The ask metrics are computed from the agents' streams for every arm alike: `streams.py` now keeps each message sent (a `SendMessage` call or a klatch `post`, `ask`, `answer` command) with the harness clock, and `asks.py` classifies by first word (`seeking`, `answer`, `need-info`), attributes to a fact by its key or its value, and computes asks made and answered, asks lost, time to first answer, duplicate answers, repeat asks, repeat asks avoided, stale answers, late asks and their fate, wrong guesses with and without an ask, and need-info events (events observed, not a rate). The K arms' counts from `klatch admin stats` are not used: the store export is not wired into the harness, so the stream is the one source. The scenario file `scenarios/s4.json` holds arms B1 K1 K2 (B0 cannot ask, noted), N 10 per arm at M0 and 3 quick, caps 1.80 per run and 22.50 for the suite from SPEC 8.1, and the definitions. Tests cover the checker (reference 7 of 7; a guessed default, a wrong value, a stale value, a missing task, a deleted file, a raising function, a committed private file), the metrics on synthetic events, and the whole harness with fake agents that ask and get answers, never ask and guess, ask late after the helper stopped, repeat the seeded ask, and duplicate and stale-answer. Nothing here ran a model or spent money; the human's budget approval, the arms review (#1365) and the real runs remain, and the ticket closes when M0 results exist.
