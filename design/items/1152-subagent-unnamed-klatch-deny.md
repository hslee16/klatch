The PreToolUse hook denies an unnamed klatch command from an in-process subagent (#1152; no schema change; 2026-11-21).
A live run (2026-11-21, headless Claude Code) showed that a subagent the harness runs inside the session's own process cannot be told from its parent by anything its command can see: the environment has no agent id and the process chain is the parent's. The one signal is the hook input: the PreToolUse and PostToolUse of a subagent's tool call carry `agent_id` and `agent_type`, and the parent's own calls carry neither. klatch's PreToolUse hook already reads `agent_id` (#505), so the fix lives there and keeps the decision of #503 (a subagent that posts must name itself).
Rule: for a `Bash` call whose hook input has a non-empty `agent_id`, if the command invokes klatch and sets no name for itself, the hook exits 2 with a message on stderr: the command runs inside a subagent and does not name itself, set `KLATCH_NAME` to a name for this subagent (for example `KLATCH_NAME=<task>-1`) in front of the klatch command and run it again. A command that does not invoke klatch, a command that names itself, a call from the parent, a call with an empty `agent_id` and a tool that is not `Bash` are untouched.
Reading the command text: it is data, tokenized and never run (`domain::invokes_klatch_unnamed`). Quotes group a word and hide separators; an unquoted `;`, `&`, `|`, newline, parenthesis or backtick ends a simple command. In each simple command leading `NAME=value` words, wrappers (`env`, `command`, `exec`, `time`, `nohup`, `nice`, `sudo`, `builtin`, `xargs`, `!`) and flags are skipped, and the command word counts as klatch when its basename is `klatch`. `sh|bash|zsh|dash|ksh -c '<text>'` is read the same way, to a depth of four. So `grep klatch file`, `git commit -m 'klatch post'` and `echo "a; klatch post"` are not klatch commands. A name is a word `KLATCH_NAME=<non-empty>` or `--as-member` anywhere in the text, so `export KLATCH_NAME=x && klatch ...` counts; an empty value (`KLATCH_NAME= klatch ...`) does not.
Limits, stated so they are not mistaken for coverage: a klatch command hidden in a variable, an alias, a script file, `eval`, or a command substitution inside double quotes is not seen and not refused; a name set in one command of a list counts for the whole text; the member a name resolves to is not checked here (a subagent that types the parent's own name passes). The rule is the hook's half only; it was tested with fake hook inputs against the real binary, not in a real session. The process-walk refusal of #503 is unchanged and still covers a subagent that is its own `claude` process. No operation changed, so AUTHZ-AUDIT has no new row.
