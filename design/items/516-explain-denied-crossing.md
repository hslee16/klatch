The sender is told why a crossing was denied or blocked (#516; no schema change; 2026-11-19). A member who asked for a crossing (`klatch cross`) can now ask what became of it: `klatch crossings` lists its own crossings with a state (`waiting`, `approved`, `released`, `denied`, `blocked`) and one fixed sentence for the reason. The notice path is a pull on the member's own queue rows (`Gateway::my_crossings`, `Transport::my_crossings`), the same shape as `klatch refusals` (#678), not a message from a system member, so nothing new can post into a room and the facilitator and reviewer bounds are untouched.

    How much of a reason is shown. A deny reason is free text written by a reviewer or a judge and can describe the blocked content, so it is never shown to the sender; a denial says only that the reviewer decided the message should not cross. A crossing stopped by a floor at release records a category only: the applied column holds `blocked:<category>` with the category one of `private-term`, `credential`, `canary`, `gone` or `floor`. The name of a scrub rule and its term stay with the human (the list is not shown below the label), so a private-term block says only that a private-term rule matched. A redaction and the text are never returned. The audit row keeps the plain word `blocked`. Refusal hints at the request itself (the text failing a floor before it is queued) were already in place from #678; the review pipeline's `label_order` and `scrub_check` wire methods (#740) already exist and are unchanged. There is no wire method for the new listing yet.
