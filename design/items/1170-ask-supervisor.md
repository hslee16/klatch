The ask supervisor, a script outside klatch that starts a pre-issued helper for an unanswered ask (#1170, part 2 of #671; no schema change; 2026-11-21).
Decided on #627: klatch never spawns and never issues a credential. `proto/scripts/ask-supervisor` (bash 3.2, a supervisor/worker pair as the integrator, #1099) polls `klatch asks ROOM`, and for each unclaimed ask older than `ASKSUP_MIN_AGE_SECS` that no candidate posted and no running helper holds, asks the read-only core check `klatch could-answer ROOM ASK MEMBER` (#671 part 1) about each idle member of `ASKSUP_CANDIDATES`; the first `yes` is started by the human's `ASKSUP_LAUNCH` command with the ask number, member and room in its environment. The ask text is never run or passed on: only the number, sender and age are kept, each checked against a fixed shape. The script posts, claims, issues, renews and revokes nothing and must be run as the human (checking another member is an admin act).

Bounds: helpers at once, starts per ask (a second only after the first ended and the ask is still open, and another identity is tried first), a total spend cap against a per-start charge kept in `ASKSUP_STATE`, a wall clock limit per helper (`kill -9`), a pause between starts, an off file, and no helper starts a helper (asks posted by a candidate are skipped; `ASKSUP_ACTIVE=1` makes the script refuse to run, exit 2). `--dry-run` prints what it would start and writes no state; `--once` makes one pass and waits for its helpers. A signal ends the supervisor and kills the helpers it started. Tests (`proto/scripts/test-ask-supervisor.sh`, in the gate) use a fake klatch and a fake launcher: no real claude, no credential, no long sleep.

Left open: the spend is a charge per start, not measured (the launcher knows the real cost; a hook to report it is not built); the scope condition of the decision is not checked because the core check does not (see item 671-could-answer-check); the runs for #224 scenarios 2 and 5 need real agents and human-issued credentials (#671 part 4).
