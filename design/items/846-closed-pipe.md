Output commands end quietly on a closed pipe (#846; no schema change; 2026-11-19).
`klatch who lobby | head` used to print "internal error ... this is a bug" when the reader closed the pipe, because Rust ignores SIGPIPE and `println!` panics on the resulting write error. SIGPIPE stays ignored, since the socket and keystore code needs the write error rather than a killed process. Instead the panic hook recognises the standard library's "failed printing to stdout: Broken pipe" report and exits 141 (128 plus SIGPIPE) with no message, so a CLI in a shell pipeline behaves like any other. Any other panic still prints the redacted internal-error line (R37).
