A warn-only Stop hook line when a turn ends with background tasks or crons still running (#1344; no schema change; 2026-11-24).
A new opt-in consent, `klatch init --stop-warn` (off with `--no-stop-warn`; `klatch consent stop-warn on|off`), wired like `--machine-status`: the flag rides on klatch's PostToolUse and SessionEnd commands as the record of the consent, and on the one shared Stop command (the flags always in the fixed order `--passive-claims --checkpoint --machine-status --stop-warn`), so a re-run of init keeps it, `--no-stop-warn` removes it (and the Stop entry when nothing else needs it), uninstall removes it, and Codex refuses it. It needs no SessionEnd hook of its own, unlike the machine status. A hook command without the flag prints nothing.

  What it prints. The Stop hook, when it carries the flag and its input lists `background_tasks` or `session_crons` that are not empty, prints one JSON object `{"systemMessage": "<line>"}` and nothing else. The line has a fixed template: how many background tasks remain with their kinds in the fixed order shell, monitor, agent, other, how many crons remain, and a reminder to stop them or start one wait only (`klatch wait`). Input text is data: a task's command, description, id or any other field is never echoed; only a count and a kind from the fixed set reach the line. A kind is read from a string under `type`, else `kind`, matched case-insensitively against a few fixed words; no field, a non-string, a bare number in place of the list or an unknown word counts as other. Absent or wrong-typed arrays count as none and print nothing. It is warn only: it kills nothing, uses no network or credential, and writes nothing beyond what the Stop hook already records (the count of background tasks and crons, #1403 and DESIGN section 32 item 45).

  Who sees it. What the repo sources state: `systemMessage` is the hook output field that shows a message to the human; the repo's research notes (section 55.1) record that the Stop and SubagentStop inputs carry `background_tasks` and `session_crons`, and INTEGRATION.md records the same. The warning reaches the human, not the model: the line is not `additionalContext` and the Stop hook blocks nothing, so nothing here feeds the model a reminder. Unverified: what an entry of either list looks like (the kind field is an assumption, so real entries may all count as other), and which Stop output channel, if any, a model sees. Both need a live model session and are ticketed (#1593). `SubagentStop` is not registered; its layout and sync rule are a decision for #1594.

  Files that change what init writes to settings: `init.rs` (the flag, its place in the fixed order, the carriers and the Stop entry), `consent.rs` (the `stop-warn` consent, its listing line and the legend wording `stop-warn: a flag on PostToolUse, SessionEnd and Stop prints one warning line to you when a turn ends with background tasks or crons still running (counts and kinds only, never a command or description), and never stops anything`), `main.rs` and `args/agents.rs` (the flag pair and the hook flag) and `init_codex.rs` (the Codex refusal). Pinned by `tests/init_stop_warn.rs`, the `commands/stop_warn.rs` unit tests and the golden consent files (`tests/golden/consent_*.txt`).
