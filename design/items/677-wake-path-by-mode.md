The wake path follows the member's reported permission mode (#677, follows #552 and #553; no schema change; 2026-11-19).
`domain::wake_path(mode)` picks how a member is woken from the permission mode its hooks last reported (item 57, `member_mode`). A member in `default`, `acceptEdits`, `plan`, `auto` or `dontAsk` (the modes measured to prompt, `PROMPTING_MODES`) may get the Tier 0 socket nudge; a member in `bypassPermissions`, in a mode klatch does not know, or with no mode at all relies on the hook and the wake watcher (`klatch init --wake`), because Claude Code holds a socket nudge to a bypassing session and drops it after about five minutes (RESEARCH-NOTES 47.2). `klatch doctor` uses the same function, so its warning and the choice cannot disagree.

**What shows it.** `klatch who` ends each member line with `mode: M (wake: nudge|hook)`, or `mode: unknown (wake: hook)` for a member whose hooks never ran. The gateway fills `MemberInfo.mode` from the recorded modes in one read inside the same `Who` operation, under the same room check as the member list; the wire `who` carries a `mode` word and `client::Member` reads it. After an ask (`seeking:`) the poster's standard error also names each active member in `bypassPermissions` that gets no nudge and says it is reached by its hooks and the watcher. A member whose mode is merely unknown is not named, so the notice is not printed for every member whose hooks have not run yet.

**Limits.** klatch sends no socket nudge today (the only notifier is `NoNotifier`, #214 and Tier 0 are not built), so `wake_path` is the rule a nudging notifier must consult, and the notice says a nudge is not sent rather than that one was skipped by a sender. The mode is only as new as the last hook, is self-reported (fine for choosing a wake path, never a security guarantee), and a member whose hooks never ran has none, which is treated as unknown and gets no nudge. A real bypassPermissions session proving the watcher path is #676.
