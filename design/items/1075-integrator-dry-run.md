The integrator has a dry run: `--dry-run` checks the setup and says what a real run would post and merge, changing nothing (#1075, follows #866; no schema change; 2026-11-20).
The first run of the integrator process against the real repository needs the human-granted role, a gh login with admin, a clean clone and the gate, and the tests only use fakes, so `proto/scripts/integrator --dry-run` lets the human check all of it before the first real merge, as `pr-sweep --dry-run` does for the sweep. Decision: it is a mode of the same script, taken before the claim code, so it cannot reach a write by accident.

    What it reads. The queue from `klatch board` (digits only, as the real run), the open PR list and each queued PR through `gh api` GET calls, `gh auth status`, `gh extension list`, the repository permission read of `gh api repos/<repo>`, `klatch refusals`, and `git fetch` plus `git merge-tree` in the clone. The PR head is fetched into FETCH_HEAD only, so the clone gets no new branch or ref of ours.

    What it never does. No `klatch post`, no `merge:main` claim or release (it reads the holder from the board header), no push, no branch, no merge, no gate, no `gh webhook forward` (it prints that it would), and no `gh` call that writes. The tests hold this: the fake gh and fake klatch logs contain only read calls, the fake remote's refs are the same before and after, and the clone has the same head, the same branch and no new branch.

    What it prints. Setup checks, each `ok` or `PROBLEM <name>: <next step>`: the role, the gh login, the gh permission (admin, which the forwarder needs), the webhook extension, the clone (clean, on main), the gate script, and who holds `merge:main`. Then, for each queued PR in order, the words a real run would post, as the same fixed templates (`integrating: #N`, the two `parked:` words, `checking: #N`, `merged: #N`, or `dropped: #N <reason>` when the pre-check, a read or a fetch fails), and the steps between them (merge main into a local branch, gate, push, wait for checks, `gh pr merge --match-head-commit`). The last line is always `dry run: nothing was changed.`; the exit code is 1 when a setup problem was named, else 0. Titles, bodies, branch names and logins are never printed; a PR whose branch name is not a plain name is shown as `dropped: #N error`.

    Limits. klatch shows no role to the member, so the role check is the absence of a recorded refusal of the `merge:main` claim by the rule `integrator`; the first real run is what proves it (#1090 asks for a read of the caller's roles). Every queued PR is pre-checked against main as it is now, not as it will be after the PRs before it have merged. The real forwarder, the real gate and the real merge are not exercised.
