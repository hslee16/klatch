`klatch acp --stdio` checked against the published ACP specification text (#869, #115; 2026-11-20)
Checked on 2026-11-20 against the public pages at agentclientprotocol.com (overview, initialization, session-setup, prompt-turn, slash-commands, agent-plan, transports, schema). Not run against Zed or JetBrains; that is ticket #1041. No schema or wire change. **Per item (spec, then the code):** (1) `protocolVersion`: a single integer, major version, `1` in the examples; the agent echoes the client's version if supported, else returns its latest. Code returns 1 always: matches. `agentCapabilities`: `loadSession` boolean, `promptCapabilities` `{image, audio, embeddedContext}` booleans (default false), `mcpCapabilities`; omitted means unsupported. Code sends `loadSession` false and the three prompt flags false: matches. Only `protocolVersion` is required in the response (schema); `agentInfo` should carry `name` and `version` (required inside the object), `title` optional: code sends all three. `authMethods` is `[]` in the spec example: matches. (2) `session/new`: schema requires `cwd` (absolute) and `mcpServers` (array) in the request; the agent must return a unique `sessionId`. Code returns `klatch-librarian-N` and ignores both inputs: matches (ignoring is allowed; the librarian uses no MCP server). (3) `session/update` with `sessionUpdate` `agent_message_chunk`, `content` a content block, optional `messageId`: code sends one chunk with a text block and no `messageId`: matches. (4) `session/prompt` response `{"stopReason": "end_turn"}`; other values are `max_tokens`, `max_turn_requests`, `refusal`, `cancelled`. Code sends `end_turn` after the chunk: matches. A wire refusal is returned as answer text with `end_turn`, not `refusal`; the spec defines `refusal` as the agent declining to continue, so either reading is allowed and the text is kept because the editor shows it. (5) `session/cancel` is a notification with only `sessionId`; the agent must stop, and must answer the pending prompt with `stopReason` `cancelled`. Code gets no reply to a cancel (correct) and has nothing running when it arrives, because stdin is read one line at a time and a look is answered first; so the `cancelled` reply is never needed while looks are instant. That is a limit if a look ever becomes slow (ticket #1042). (6) `authenticate` is listed as a baseline agent method ("if required"); `methodId` must be one the agent advertised, and the response has no required fields. The spec does not say what an agent with no methods answers. **Code was wrong:** it answered -32601 (method not found), which says the method is missing; it now answers -32602 with "no authentication method is advertised". A client that honours `authMethods: []` never calls it. Test first (red, then green). (7) `session/load` is optional and needs `loadSession` true; clients MUST NOT call it when false or absent: -32601 for a client that does anyway is within JSON-RPC rules and is kept. (8) Slash commands (`available_commands_update`) and plans are optional (MAY); the agent must not send plan updates unless the client advertised `plan`. Nothing more is needed to answer a prompt, so none is sent. (9) Transport: each message is one line with no embedded newline and nothing but ACP messages on stdout (stderr may log). The code writes compact JSON, one per line; a new test pins a multi-line answer to one physical line per message. **Gaps not fixed here:** `resource_link` blocks (baseline for every agent) are ignored and only `text` is read, and cancel cannot interrupt a look (ticket #1042); a real-editor run (ticket #1041). **Tests added:** `authenticate` is invalid params (red first); one physical line per message for a multi-line answer; a cancel notification gets no reply and the session survives (the last two were already green, they pin the spec text).
