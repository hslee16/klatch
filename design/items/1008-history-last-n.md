`history --last N` fills its window with visible messages (#1008; no schema change; 2026-11-20).
It used to take the newest N rows and only then drop the canary and archived kinds, so a room whose newest row was a freshly planted canary returned too few messages, and `more` counted the dropped rows. `Gateway::history` now scans back a window at a time (each window sized by how many visible rows are still missing) until it holds N visible messages or reaches `since` (or the start of the room); a forward page (`--since` alone) scans on the same way until the page is full or the room ends. `more` counts the rows after the scanned window, so a hidden row at the edge is no "more". Other last-N surfaces: `tail` callers that page by count already page by rows scanned (`tail_scan`, #954); the admin export reads the whole room; the rate check and run-end archive read raw rows by design. No operation changed, so AUTHZ-AUDIT.md is unchanged.
