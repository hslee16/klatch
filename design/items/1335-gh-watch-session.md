gh-watch is part of the start of a session (#1335; no schema change; 2026-11-22).
`gh-watch status` and `gh-watch ensure` let a Claude session use the watcher by default. **status** prints whether the receiver is up (the pid in `gh-watch.pid`, written by `serve` and removed when it ends, must be alive AND a TCP connect to `127.0.0.1:PORT` must succeed), whether a `gh webhook forward` process for this repository exists (a `ps` check; only yes or no is printed because the secret is on that command line), the age of the last write to `gh-watch.log`, and a last line `gh-watch: ok`, `gh-watch: receiver down` or `gh-watch: forwarder down` with exit codes 0, 3 and 4. **ensure** creates the state dir and a 0600 secret file if missing, starts ONLY the receiver detached when it is down, and prints the status; it never starts the forwarder and never runs `gh`, because the forwarder needs the human's `admin:repo_hook` token.

The routine (run `ensure`, arm a Monitor on the log filtered to `ALERT|INFO`, re-arm after 30 minutes, keep the slow poll) is in PR-SWEEP.md, with pointers from FACTORY.md and CONTRIBUTING.md, and a root `CLAUDE.md` states the repository rules that are already documented elsewhere. **Not included:** a SessionStart hook; installing hooks belongs to `klatch init` and the hook installer. **Limits:** the receiver check cannot tell a receiver from another program that took its pid after a reboot and its port; the forwarder check matches the command line, so a forwarder run through a wrapper that changes the text is not seen.
