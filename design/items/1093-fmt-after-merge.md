A merge of main runs cargo fmt and re-checks the compile (#1093; no schema change; 2026-11-21).
A union merge (#1065) keeps both `mod x;` lines two branches added at the same place, in an order rustfmt rejects, so a clean merge failed CI at Format check (#1087 and #1085 did). The new `proto/scripts/fmt-after-merge` runs `cargo fmt --all` in proto/, commits the result when it changed anything (a normal commit, never pushed by itself), then runs `cargo check --workspace --all-targets --locked`; it exits 1 if either step fails and skips a repo with no proto workspace. The integrator runs it after merging main into a PR branch, before the gate (a failure drops the PR as `checks-failed`), and pr-sweep runs it after each merge it makes. `proto/scripts/test-fmt-after-merge.sh` uses real temp git repos and a fake cargo, and it was red first (the script did not exist). The coordinator scratchpad integrate.sh is not in the repo and must call the same script.
