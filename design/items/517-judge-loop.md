Resident judge loop with a local rules judge and a breaker (#517, epic #10; no schema change; 2026-11-19).
`klatch judge run` now loops (every `--interval-secs`, default 5) and `--once` keeps the single pass. Each pass drains the review queue through the rules judge (`RulesJudge`: the credential scanner, then the scrub list, matched as the gateway matches it and only below the agent cap) and then applies recorded verdicts through `release_crossings`, which checks the floors again. The rules judge denies on a match and otherwise defers: it never vouches for text, so clean text stays queued for the reviewer, the same as before. A pass that fails is reported and retried; it decides nothing. The command is still refused for a worker and from inside a coding-agent session.

    Composition for a judge that can say Allow: `Narrowed` runs the rules first and a rules deny stands, with the inner judge never shown that text, so an inner judge can only narrow what the floors and rules allow. `Breaker` wraps any judge: a `Defer` or a panic counts as a failure, a decision resets the count, and after `limit` failures in a row it answers `Defer` without calling the judge, so a failing judge cannot allow by default and a down service is not hammered. The default loop does not wrap the rules judge in the breaker because deferring clean text is its normal answer.

    Owner decision kept (#942, #53): Claude Sonnet is the recommended hosted judge, it stays off by default, it sees only text strictly below the ceiling label, and nothing in this change or its tests sends text to a network service.
