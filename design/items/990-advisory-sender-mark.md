A flagged sender is marked on read, wait and digest message lines (#990, follows #878; no schema change; 2026-11-20).
#878 marked a flag-mode room-require member as advisory in `who` and the board, but the sender on a message line still showed no mark. **Shape:** `Message` has a display-only `advisory` flag that the store always leaves `false`. One gateway overlay, `Gateway::mark_advisory`, sets it from the room's `room:ROOM:advisory:MEMBER` policy keys on what `read`, `wait` and the hook digest return (one prefix read, skipped when there is nothing to mark), and `Message::sender_label` appends the fixed text `(advisory)` after the name and any `(unverified)`. The `read` session method adds `"advisory": true` to a flagged sender's message and omits the key otherwise, so the wire stays backwards compatible. **Why an overlay and not a stored field:** the latest admission decides, so a clean rejoin clears the mark on every message at once, and no stored message is rewritten. **Forgery:** the mark is a constant, never built from member text; the mark comes from the gateway's policy record keyed by the sender name the gateway attributed, a member name cannot contain a space or a parenthesis (so no name can carry the mark), and a member named `advisory` shows as that name with no mark. **Limits:** display only and never authority, as in #878; it names no capability; `tail`, `history` and the live stream do not carry the mark (the stream frame is unchanged); a requirement lifted after a flagged join leaves the mark until that member rejoins. The audit table is unchanged: no operation is added and `read`, `wait` and the digest are admitted exactly as before.
