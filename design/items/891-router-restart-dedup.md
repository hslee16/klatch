The router does not repeat an invite after a restart (#891; no schema change; 2026-11-20). A restarted `klatch router` used to forget which members it had invited and post the same invite pointer again for a member who had not joined. On its first pass it now reads the lobby's recent history through the same guard-checked `history` call a member makes (no new privilege path, no local file) and counts an invite as made when a message the router itself sent is exactly the fixed invite text for that member and room (the text of `invite`, one source for both). A post by any other member never counts, whatever its text, so no one can stop the router inviting by copying the pointer.

    Limits: the read looks back at most the history maximum, so a pointer older than that window is not seen; and an invite the guard refused leaves no pointer, so a restarted router tries it once more (a refusal is still not retried within a run). Same pattern as the mediator (#906).
