The SemVer to PEP 440 mapping is one script, and check-versions.sh checks the Homebrew formula (#1234, #1235; no schema change; 2026-11-21).
**Question.** The first release is 0.2.0-alpha.1 (PyPI 0.2.0a1, tag v0.2.0a1), but only `-dev.N` was mapped, in five copies (check-versions.sh, install.sh and three checks in build-release.yml). How do alpha, beta, rc and dev share one rule so the sites cannot drift, and how does a version bump stop leaving the Homebrew formula behind?

**Decision.** `release/pep440.sh` is the one definition, POSIX sh, sourced: `semver_to_pep440`, `pep440_to_semver`, `release_tag`, `semver_of_tag`, `tag_matches`, `archive_name`, `is_prerelease`. The table is `-alpha.N` to `aN`, `-beta.N` to `bN`, `-rc.N` to `rcN`, `-dev.N` to `.devN`, a plain X.Y.Z unchanged; anything else is refused with a non-zero status rather than passed through, because a pass-through is how five copies drifted. `check-versions.sh` and the three tag checks in build-release.yml source it (each of those lines became one line that calls `tag_matches`, which accepts the PEP 440 tag and the SemVer spelling as before). `install/install.sh` is downloaded alone and cannot source a file, so it carries a copy of the marked block; `release/test-pep440.sh` fails when the copy and the source differ, and when another script spells the mapping again. check-versions.sh now requires PyPI and the wheel to equal the PEP 440 spelling of the crate version exactly (before, either spelling passed).

The formula lives in the tap `hslee16/homebrew-klatch`; a staged copy is in `release/homebrew/klatch.rb`. check-versions.sh reads it (or a path argument) and checks `version`, that there is exactly one URL per platform archive and that each is `https://github.com/hslee16/klatch/releases/download/<tag>/klatch-<semver>-<target>.tar.gz`, and the SHA-256 lines when present (64 hex digits). With a SHA256SUMS file as the third argument every archive's sha256 must match its line, and the formula must carry the lines.

**Alternatives.** Sourcing pep440.sh from install.sh at run time (the installer is read, checksummed and run alone, so it cannot). Generating install.sh from a template (a build step for a file people read before running; the sync test is cheaper). A mapping table in a data file read by sed (still needs a reader in every site).

**Ordering.** Never `0.1.0-alpha.1`: SemVer compares labels as text, so it sorts below the published `0.1.0-dev.2`. `0.2.0-alpha.1` sorts above every `0.1.0-*` in both schemes (tested). SemVer and PEP 440 disagree about `dev` against `alpha` on the same X.Y.Z, so one X.Y.Z line uses one kind.

**Not covered.** The staged formula is a copy; nothing compares it with the tap's file (the bump script ticket owns the copy to the tap). The wheel job in build-release.yml compares the tag with PyPI's spelling by plain equality, not through the mapping. The real version numbers are not bumped here (#1248).
