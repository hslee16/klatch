CI runs two parallel jobs, test and test-clients, so the critical path is the longer of the two (#1349; no schema change; 2026-11-22).
The single CI job took about 395 s with every step in sequence. `.github/workflows/ci.yml` now has two jobs on ubuntu-latest. `test (ubuntu-latest)` keeps its name because branch protection requires it, and keeps fmt, clippy, the workspace build, nextest and the doctests, the client and bare feature builds, the crates.io dry run and the test-clock `no_plaintext` test. `test-clients (ubuntu-latest)` runs the Python and TypeScript conformance suites and the recipes tests (they need the klatch binary, so the job builds it with `cargo build -p klatch --locked`, with its own rust-cache `shared-key` so the two jobs do not write one cache), the installer test, the version, timeout, changelog and release scripts, actionlint, shellcheck, the README quickstart, the integration guide and launcher recipes, the cargo-about notices check and cargo-deny. Every action is pinned by full commit SHA, permissions stay `contents: read`, and concurrency and timeouts are unchanged. The name starts with `test` so the merge keeper waits on it. Branch protection is not changed here: only the human can add `test-clients (ubuntu-latest)` to the required checks. The measured durations are in the pull request.
The local gate (`proto/scripts/gate`) is unchanged and still runs every step in order; it has no check that reads `ci.yml`, so nothing there needed to learn about two jobs. A third job could split further (for example the feature builds and the dry run out of `test`).
