Shared gateway fairness is measured: no second path is needed yet (#1086; no schema change; 2026-11-21).
**Question.** The owner thread of `SharedGateway` (#140) serves one request at a time, so a slow request delays every other handle. Does any operation need its own path (a second read-only connection, or chunking) now that the daemon (#102) exists?

    **Measured** (`gateway/shared_fairness_tests.rs`, `shared_fairness_measurement`, ignored; release build, SQLCipher temp file, two rooms of 10000 messages of about 200 bytes, one prober thread calling `who` in a loop beside each slow request; the daemon queues on the same owner, so this is the wait a daemon connection sees, minus socket and framing cost, which the daemon tests did not time). A short request alone: p50 0.94 ms, max 1.6 ms. Beside `history` (capped at 200 messages by `HISTORY_MAX_MESSAGES`): the slow call takes 0.5 ms and the worst short request waits 1.1 ms. Beside `admin_audit` with a huge limit: 0.6 ms and 1.1 ms. Beside `read` of a 10000 message backlog: 12 ms and 11.7 ms. Beside `admin_run_end` deleting 10000 messages: 49 ms and 49.6 ms. Queued short requests are never starved: the channel is first in, first out, and every probe completed.

    **Decision: no change.** The worst wait is the length of the slowest single request, and the slowest one measured (a run end that deletes a whole run) is about 50 ms for 10000 messages, an admin act a human or the facilitator does once per run. Every reader path is bounded (history is capped; a read pages). A second read-only connection would add what the owner design avoids: a second set of label keys per principal, a second open (key read and schema check), and reads that would skip the guard, clock and sequence order the owner keeps. Chunking `admin_run_end` would give up its all-or-nothing delete. Revisit if a measured request exceeds roughly 250 ms (the client wait poll interval is the scale that matters) or the store grows past the sizes here; the ignored measurement is the tool to rerun.

    **Added.** The measurement, and a real-thread test that a short request queued behind a run end is served when it ends and one issued after it returns at once. That test passed on first run (it records the property; no code changed, so it was not red first).
