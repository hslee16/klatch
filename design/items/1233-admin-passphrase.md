The human's proof for admin, launcher and keystore acts is the admin passphrase (#1233, option 1 of #318; no schema change; 2026-11-21). The terminal and process-tree heuristic (`admin::gate`, and the `refusal(holds_a_bundle, agent_above)` of `worker`, `anchor`, `run` and `judge`) is deleted, not kept as a fallback: it was a guess, a detached process escaped it (#834), and it never covered the keystore family. In its place `klatch admin init-passphrase` stores an Argon2id verifier (`argon2id$m=,t=,p=$salt$hash`, parameters in the value so they can be raised, rewritten at the next success when weaker than the current cost) in the policy table under `admin-passphrase`; the table holds it, so there is no schema change. Every admin command, every launcher command and every keystore act calls `prove::require` first. The secret is read by `klatch::proof::TtyPrompt` from a terminal only: standard input when it is a terminal, else the controlling terminal (`/dev/tty`), with echo and signal keys off and typed-ahead input flushed; never the environment, an argument, a file or a pipe, so a process with no controlling terminal (detached, `setsid`, a worker's, a script's) is refused and one that opens a pseudo-terminal is asked and refused for not knowing it.

  Only a correct answer builds an `AdminProof` (private constructor, not `Clone`). `AdminProof::principal` is the principal `human` with `Attribution::Verified`; `human` joins the reserved names so no member, worker or session can be it. `RequireHuman` is the guard of every gateway the person's commands use: it refuses every operation unless the principal is exactly that, and composes with `ForbidFloors` for the launcher commands. The agent roles are untouched: the admin agent acts on a members' gateway where the role check and its allowlist decide, and floors stay the human's. The keystore family acts outside the gateway, so `key_command` takes the proof as an argument, runs as `human`, and asks the new gateway method `admin_authorize` for the act by name before it opens the real store (on a gateway over a store of its own, because `recover` and `restore` run exactly when there is no usable key); each act still writes its own audit row.

  The failure limit is policy too (`admin-passphrase-fails`, count and time). An attempt is charged in one write transaction before it is checked, so a killed process and many processes at once each cost one; three are free, then 30 seconds doubling to 15 minutes, nothing is asked while the wait runs, only a success clears it, and a damaged value reads as the strictest wait. The audit gets `proof-ok` (window length), `proof-failed` (`failures=N`; never the attempt), `proof-locked` and `proof-refused` (one a minute each, so a loop of refused commands cannot fill the audit), `passphrase-set`, `passphrase-changed`, `passphrase-reset`, `passphrase-rehashed`, `unlock-window`. The comparison is constant time (`subtle`) and the typed text is `Zeroizing`.

  The unlock window is a `static` in the memory of the process (`Instant`, measured from the entry, not sliding, tied to the verifier's salt so a change of passphrase voids it), length from policy `admin-unlock-secs` (10 to 1800, default 300). A `klatch` command is one short-lived process, so on its own every command asks; the one long-lived process is the new `klatch admin shell`, which asks once and reads admin, worker, anchor, run and judge commands (no other command, not itself). Nothing is written to disk or the environment, and a child or another `klatch` starts locked. Migration: an existing install has no verifier, so every admin, launcher and keystore command refuses with "no admin passphrase is set; run `klatch admin init-passphrase`" and `init-passphrase` sets the first one (twice, at a terminal, refused from a detected coding-agent session; the first set has nothing to prove, so an install that has not set one is open to a program with a terminal until the human does, #1262). With one set, `init-passphrase` changes it after asking for the old one. Recovery: `klatch admin reset-passphrase` takes the store's recovery code (constant time, charged like a passphrase attempt) and sets a new passphrase; the code can already restore the key and read the store, so it weakens nothing.

  Limits, stated in SECURITY.md: the proof is knowledge of a secret typed at a terminal, not proof of a person. A process that watches the keyboard or reads the memory of an unlocked shell is out of scope. A process of the same user that does not use the command line but opens the store with its readable key can rewrite the verifier and the counter (#1261); the Keychain item with user presence and the separate OS user stay open in #318. Linux and macOS both: the read is termios on a tty descriptor, no OS keystore is involved.

  Review fixes (same item). The prompt names what the passphrase approves (`admin passphrase to approve \`admin close lobby\``; a recovery code given as an argument is left out; the shell says it opens an unlock window for ALL admin and launcher commands), because a program that shares the person's terminal can make a prompt appear even with a pipe on standard input. The typed-back confirmation is read from the terminal (`Prompt::line`), never from a pipe, and `klatch admin shell` refuses unless standard input is itself a terminal (checked before anyone is asked). `recover` (store key) and `restore` run before the store opens when it cannot be read, because the verifier is in it: `recover` is approved by the recovery code given (it must open the store file) and `restore` by the typed recovery code (constant time), each then followed by the typed confirmation; a readable store always uses the passphrase. `init-passphrase`'s check and store are one write transaction, the passphrase buffer is allocated to its maximum so it never reallocates and is wiped, and argon2 runs with its `zeroize` feature. Not fixed here, ticketed: a lockout by an agent with a pseudo-terminal of its own (#1274), the integrity of the verifier row (#1275, relates to #1261), the removed worker and agent-session refusals (#1276: the proof replaced them; a worker or agent that shares the person's terminal can still make a prompt appear), the macOS monotonic clock that stops in sleep (#1277), and a terminal left silent by SIGTERM during the prompt (#1278).

  Second review fixes (same item). Commands that print a secret (`recovery`, `export`, `run-archive`, `rotate-key`, `rotate-label-key`) refuse before any prompt when standard output is not a terminal, and `recovery` takes a typed confirmation. Store-less `recover` needs an existing encrypted store file that the code opens (`custody::opens_encrypted_store`), and the proofs by recovery code are built inside `klatch::proof` from the keystore and the store file, so nothing outside can build an `AdminProof` from a bare yes. The `restore` prompt names the backup file, every prompt names the store, and prompt text from arguments is stripped of control characters, escapes, bidi overrides and zero-width marks, never cuts the family and command words, cuts a long word with its length and a digest, and hides every non-flag word after `recover`. `prove` reads the verifier again once the attempt is typed and rewrites a weaker one only if the row is unchanged, in one transaction. Ticketed: `anchor github` payload (#1279), the open shell window on a shared terminal (#1280), the store-less recovery code limit (#1281), `worker issue` output (#1282), and the shared lockout now also noted on #1274.

  Third review fixes (same item). The stdout-must-be-a-terminal rule is now stdout-must-be-THIS-process's-controlling-terminal (`proof::is_controlling_tty`: a terminal, `tcgetpgrp` succeeds and `tcgetsid` is our session), because a pty an agent owns on fd 1 is a terminal too; it covers every act that prints stored text (the audit, refusals, review queue, scrub terms, archive listing as well as the secrets), and the admin shell needs fd 0 and 1 to be it. Prompt text from arguments is a whitelist (printable ASCII, everything else `?`), `recover` is hidden only when it is the command word and then every later word is, non-UTF-8 arguments are shown lossily, and the confirmation label says what it confirms. SECURITY.md states the residual: a passphrase typed into a terminal that a program hosts or relays is captured. Ticketed: the digest of a cut argument cannot be checked (#1283) and the rehash compare for non-canonical row text is untested (#1284).

  Fourth review fixes (same item). Being the controlling terminal is not enough for output: a program can lead a session on a pty of its own (forkpty), making that pty the controlling terminal of the child while standard input is the person's terminal, so the prompt appears on the person's terminal and the answer goes to the program. `proof::output_is_the_prompt_terminal` now also requires standard output to be the very device the prompt is read from and written to (`fstat` on both: device, inode, terminal), and standard error to be it or `/dev/null`; the shell needs fd 0 and 1 to be one controlling terminal. A recovery code is hidden by the PARSED command (`AdminCmd::Recover`), never by looking at words, so global flags before the subcommand or a flag value that is a family name cannot defeat it and a room named `recover` still shows. A confirmation label for a name that had to be cleaned shows its length and the digest of the real name. SECURITY.md no longer claims `setsid` is refused: it is not, and says exactly what the same-device check does and does not do.
