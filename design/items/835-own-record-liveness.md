Own-record methods re-check the credential (#835; no schema change; 2026-11-20).
The methods that act only on the caller's own record (`note_session`, `note_parent`, `note_member_mode`, `record_stop`, `sign_of_life`, `set_scope`, `scope_of`, `set_kind`, `kind_of`, `my_refusals`, `my_crossings`, `delivery_view`, `set_delivery_view`, `rooms`, and `record_hook_run` for every event but `SessionEnd`) now refuse a verified principal whose issued credential is revoked or expired (rule `credential`), through `check_own_record_live` in `roles.rs`. It is the same decision `check_guard` makes, without the renewal: a hook writing its own record does not keep a credential alive.

The end of a worker's session is the exception, listed with a reason in `AFTER_END` in `gateway/gateway/tests/zero_trust.rs`: `release_all` (frees only the caller's own claims, so a credential that idled out before the hook does not leave them held), `record_hook_run` for the `SessionEnd` event only, and `end_credential` (it only revokes and a second call does nothing). The session-end hook frees claims first, so an expired credential no longer stops it before it gets there. A table-driven test over every own-record method that takes a principal proves each row for the three ways a credential ends (the worker's own end, an admin revoke, expiry), and the classification test fails for a new own-record method that is in neither `NO_PRINCIPAL` nor `AFTER_END`. Unattributed principals and verified ones with no credential record are untouched.
