The admin passphrase failure limit counts per controlling terminal (#1274; no schema change; 2026-11-22).
The failure count was one global policy row, so a program with a pseudo-terminal of its own could type wrong passphrases and drive the wait to 15 minutes for the human too. The human decided on 2026-11-22 to count per terminal. The schedule is unchanged (three free attempts, then 30 seconds doubling up to 15 minutes), applied to each terminal.

The terminal is the label `<device>/s<session id>` of the process's controlling terminal (`ttys003/s4121`), from the first of standard input, output or error that is the controlling terminal, else `/dev/tty`. The human's terminal gives the same label for every command typed in it; a new pty has its own device and session, so it gets its own counter. The label comes from the prompt (`Prompt::terminal`, a test supplies its own), is cleaned to plain characters and 48 characters, and is not secret. A process with no terminal is labelled `none`; it is refused before anything is charged.

The counters stay in the existing policy row `admin-passphrase-fails`, now one `<label>=<count>,<unix secs>` entry per terminal separated by `;`, read and written in the same write transaction as before (charge before check, so many processes at once each cost one). No migration: a row in the old `count,time` form is read as the asking terminal's own entry once and rewritten in the new form; a damaged row reads as the strictest wait for the asking terminal. A success (proof, first passphrase or recovery-code reset) clears only that terminal's entry. Entries idle for 7 days are dropped, and at most 64 are kept, the oldest going first; a program can still shed its own counter by making new terminals, which is the accepted trade-off. `proof-failed` and `proof-locked` audit rows record `terminal=<label>` next to the count and wait, never an attempt.

No global backstop is built: any ceiling low enough to matter is again a way for an agent to lock the human out, and a high one adds little against a program that can open terminals at will. Whether to add one is ticketed. The store-less recover and restore limit (#1281) is a file beside the store and stays global.
