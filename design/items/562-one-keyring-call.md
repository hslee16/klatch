The Linux keyring is asked once per command, not twice (#562; no schema or wire change; 2026-11-18).
`detect` ran one `secret-tool lookup` for a throwaway name to see that the service answers, then the real `get` ran another (about 8 ms of a 25 ms hook in the container measurement, budget 50 ms). **Decision:** the question that proves the service answers is the first read of the key. `default_source(dir, name)` now takes the store key name the caller is about to read, and `SecretService::detect(name)` reads that key once, keeps the result (a key, a miss, a locked keyring, a malformed item), and hands it to the first `get` of the same name. A reach failure (bus gone, a hung call, no `secret-tool`) is the only result that is not "the service answers", so the fallback to a key file is unchanged. **Why not skip the probe or stat the bus socket (the ticket's other ideas):** letting the first `get` decide would need a source that switches to the file after a failed first call and a way to show the key-file warning later; a `stat` of the socket cannot see a stale socket file left by a dead bus, which today falls back and would turn into a hard failure on every command. **Safety:** the held result is used once and cleared by `put` and `delete`, so a key made or removed after detecting is never answered from the early read, and a `get` of a different name never uses it. **Not measured:** the saving is the container figure from the ticket; there is no Linux host here to re-measure it, and the container run (`proto/linux-keys/run.sh bus --bench`) is part of #563. **Tests (stand-ins, written first; compile-red because the signature changed, then each mutant by hand):** `detecting_and_the_first_read_of_the_key_cost_one_call_not_two` (counts calls of a `secret-tool` stand-in), `the_read_made_while_detecting_serves_only_the_key_name_it_asked_for`, `a_miss_and_a_locked_keyring_seen_while_detecting_are_handed_on_as_they_were`, `a_put_or_delete_after_detecting_never_leaves_the_early_read_to_be_served_stale`. Mutants caught: serving the early read to any name, not clearing it on `put`, and treating any non-`Ok` early read as "no service" (which would turn a locked keyring into a fallback to the key file).
