Park, unpark and the review queue have shared conformance tests (#956; no schema change; 2026-11-20).
The feature declaration of #485 runs the conformance tests of each declared feature, but park and unpark (under member notes) had none and the review queue (reviews) was probed by one inline check. Now `conformance::members` covers a park holding live claims to its return time and not after, a parked member listed with its reason and return time until unparked, a second park replacing the first, an unpark cutting a stretched claim back to a normal lease, and an unpark of a member that is not parked changing nothing. A new `conformance::reviews` module covers oldest-first pending items, one verdict per item, the drain limit and one queue entry per message and label, the newest-first listing, a crossing keeping its target, requester and outcome, only an allow or redact crossing being due to apply, and a requester being told once while waiting and once for the outcome. `conformance::features` runs all of them for the declared features and the inline probe is gone; SQLite runs each one by name and the four review tests that duplicated them moved out of its own test file.

  Each new test is shown able to fail. A test double on top of the in-memory spike (`memory_spike/faulty.rs`) is sound when its fault is none and carries exactly one defect otherwise (for example a park that leaves claims alone, a second verdict that wins, a notice that repeats); one test asserts every new test passes on the sound double and fails on the double broken in the way it guards. The double declares MemberNotes and Reviews but the spike keeps no status, so only the review probe is run through `features::probe` on it; the park tests are checked directly.
