Coordbench scenario S7 measures scale, 8 and 16 agents, with a generated fixture (#1372; no schema change; 2026-11-23).
Scenario S7 of the coordination bench (epic #1362) runs the S1 job with 8 and then 16 agents to see what each member pays to read the room and where adding agents stops helping. Nothing here changes klatch; it is bench code under `experiments/coordbench`, built and tested without a model and without spend.

    Fixture F7 `scale` is generated. `fixtures/scale/gen.py` (standard library, deterministic: every choice comes from a string-seeded `random.Random`) writes M = 2 x agents modules (16 and 32), each a small pure function drawn from a table of 18 kinds with seeded parameters stated in the stub's docstring, plus the same two shared files as S1 (a registry and a changelog that every ticket appends to), so the chance of a real merge conflict grows with N. The seed belongs to the fixture, not to the run, so every run of a size starts from the same repository; the sizes are the fixture variants `n8` and `n16` and are recorded as the separate scenarios `scale-n8` and `scale-n16`, never pooled. The reference solution is generated by the same code and is never in a checkout; the hidden checker `checks/scale` tests each module against oracles that are a different formulation of each contract (the reference and the oracles must agree, which the tests check at N = 2, 8 and 16), and reports units 0 to M, tickets, merge state and the contribution per agent.

    Metrics. Coordination overhead is messages posted per agent and the tokens a member spends reading the room (the tool results of `klatch read`, `wait`, `digest`, `board` and `history` and of reads of `TASKS.md`, from the stream, characters over 4), with the hook output counted apart and, for K arms, the bytes the hooks injected as the store counted them (`hook_runs`, the export of #1433; null without it). The largest single coordination tool result is reported, which is where the 88 KB `wait` output of the lobby shows. Throughput is units per agent per turn, units per dollar and tickets per agent-minute. Conflicts, overwrites and duplicate work are S1's. The report gains a "Scaling curve" section: per arm, each metric against N with the ratio of 16 to 8, and the units-per-dollar ratio, below 1 meaning that adding agents stopped helping.

    Cost. At S1's 0.50 USD per agent on Haiku with the coordination share growing with the team, a run costs about 5.20 USD at 8 agents and 15.20 at 16 (twice the agents, 2.9 times the cost); six runs per arm over B1 and K2 is 46.80 to 78.00 USD and 136.80 to 228.00 USD. The proposed caps are 15.60 and 45.60 USD a run and 78 and 228 USD a suite; the human changes them before M0.

    Left open. No real run has been made, so the figures above are planning numbers and `#1372` closes only when M0 results exist and the cost curve is plotted from them. The store export for the K arms' hook bytes arrives with #1433.
