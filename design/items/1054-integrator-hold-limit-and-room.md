The integrator releases its own merge:main hold after a time with no merged word, and merge:main has one room, the lobby (#1054, #1055; follow-ups to #865 and #866; no schema change; 2026-11-21).
Decisions by the human: the progress check lives in the integrator helper only (option C of #1054): no gateway change and no new authority, and the release stays with the holder's own identity. A hold that has gone `INTEGRATOR_MAX_HOLD_MINUTES` (default 60) with no `merged:` word posted since the claim was taken (or since the last merged word) is released by the helper, which posts `released: held merge:main Nm with no merged word, waiting for a new ready:` (a fixed template of one integer) and then takes the claim again only when a fresh `ready:` word arrives, read through `klatch wait <room> --only ready:`. The check runs between PRs, so a gate run or a wait for checks is never cut off mid merge; a PR that runs longer than the limit is checked when it ends. A misbehaving holder that is not the helper is still only stopped by the lease, the park bound and the claim-age reminder of #865.

    The room (#1055): claims are per room, and the team takes `merge:main` in one room, the lobby, which is documented as THE one room in `proto/scripts/INTEGRATOR.md`. The helper probes the claim in its configured room (`INTEGRATOR_ROOM`, default the lobby) before it starts the forwarder; if it cannot hold it there it refuses to run (exit 2 for a refused role, exit 3 otherwise) and the message names the room and the lobby. A room name that is not a plain name is exit 1. A cross-room claim in the gateway was not chosen. Tests: `proto/scripts/test-integrator.sh` (a wrong room refused, the default room is the lobby, a bad room name, the hold released with its word, no retake until a fresh ready word, a merged word resetting the clock, a bad limit setting).
