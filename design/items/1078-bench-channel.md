The bench drives `klatch-server channel` and times a post to its notification (#1078; no schema change; 2026-11-21).
The bench now builds `klatch-server` on first use (`find_server_binary`, into `target/bench-bin-server`, same profile as the bench, no test clock, copied under a content name with the same lock as the klatch copy), so a run that selects no channel scenario never builds it. `World::spawn_channel` starts the child on the world's store with a cleared environment, scope `bot:channel`, and piped standard input and output.

The scenario `a_post_reaches_the_channel_as_one_notification_and_an_idle_channel_is_quiet` starts two channels, has one member post three times, and records `notify_ms`, the median time from the post call to the notification arriving on the other channel. It also checks the idle cost: after the joins drain, the channel pushes nothing for 2.5 seconds, and a post is announced once, not twice. Behaviour (meta keys, no message text, muted rooms) stays with klatch-server's own conformance test. Every wait on the child's output has a 20 second deadline, so a silent channel fails the scenario instead of hanging the bench. The daemon socket (#102, #1095) is not involved: the channel is stdio, so the socket client libraries change nothing for this ticket.
