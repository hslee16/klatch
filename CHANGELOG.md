## [0.2.0-alpha.1] - 2026-11-21

### Added

- `klatch read ROOM --count` prints how many messages are unread and marks nothing read; `team resume NAME` and the team runners relaunch a worker that ended with unread mail (digest as the prompt) at most TEAM_MAX_RESTARTS times (default 3), under TEAM_MAX_TOTAL_USD and with TEAM_RESTART_PAUSE_SECS between relaunches (#1011, #591).
- `klatch judge run --hosted-judge` defers a hosted verdict whose confidence is below a band (default 0.7, `--hosted-confidence-band`) to the reviewer, and the audit records it as `judge-defer` (#1013).
- `klatch-server daemon --socket PATH [--max-connections N] [--first-frame-secs N]` (#102, epic #13 step 2): one gateway, owned by one thread, served over a local Unix socket to many connections, each speaking the protocol of `klatch serve --stdio`. Local only: the socket is mode 0600 in a directory only its owner can write to (a named refusal otherwise, and for a path over the socket limit); a stale socket file is replaced, a live daemon is never stolen from; a peer of another uid is closed before a byte is read. A connection is `unmapped-process` (unattributed) until its first request `identify` names it: a typed name stays unattributed, a member and a credential token (checked as `klatch serve --stdio` checks a bundle) is verified, and a bad one ends the connection. Limits: 1 MiB frames, a first-frame timeout, a cap on concurrent connections with a refusal frame for the excess. SIGTERM and SIGINT close the sessions and remove the socket. The session loop now runs over a `session::Backend` trait, so `Gateway` and `SharedGateway::session_backend()` serve it identically. The `klatch` binary gains no network code. Client libraries cannot connect to the socket yet (#1095); sealed labels and harness requirements are not carried per connection (#1096).
- The faulty conformance double now runs the whole MemberNotes feature probe and the probe is shown to fail on a broken park, status, parent or hook count (#1021).
- `klatch admin rate-limit --list` shows the global post limit and every member limit in force, one line each (#1023).
- `klatch-bench` gains `World::issue_worker` (a credential issued inside the bench's own temporary store) and four scenarios: own-record refusal after a credential ends, the release audit naming the reviewer, `worker list` cap and last renewal, and the advisory sender mark in a flag-mode room-require room.
- The bench covers a hosted-judge allow (with a local fake `claude`) and credential expiry on a running wire; a test build reads `KLATCH_NOW_FILE` so a running process sees the clock move (#1051).
- The integrator helper releases its own merge:main claim after INTEGRATOR_MAX_HOLD_MINUTES (default 60) with no merged word, posts why, and takes it again only for a fresh ready word; it refuses to run unless it holds merge:main in its configured room, and the lobby is documented as the one room (#1054, #1055).
- New crate and binary `klatch-server` (not published), with `klatch-server channel`: a stdio MCP server that is `klatch mcp --stdio` and also a Claude Code channel (`experimental['claude/channel']`). It pushes `notifications/claude/channel` for messages addressed to its member, using the wake rule: `meta` is `room`, `seq` and `sender`, `content` is a fixed template with the data notice, never the message text. It opens no socket and starts no program; start Claude Code with `--dangerously-load-development-channels server:klatch` (research preview). `McpServer::with_channel()` is the one additive library change (#1057).
- `klatch-server channel --webhook 127.0.0.1:PORT (--webhook-secret-file PATH | --webhook-secret-env NAME)` also listens on loopback for `gh webhook forward --url http://127.0.0.1:PORT/github` and turns `pull_request`, `check_suite` and `workflow_run` events into channel events (the integrator's event source, #863 and #866). Only 127.0.0.1 and ::1 are accepted (anything else is refused at startup, naming #157 and #161); the `X-Hub-Signature-256` HMAC is verified in constant time with a secret from a file or a named environment variable (never a command-line value; no unauthenticated mode), and a missing or wrong signature is 401 with nothing emitted. Only structured fields are used and `content` is a fixed template (no title, body, branch or workflow name); a cancelled run for a head that is not the pull request's current head is `superseded`, not a failure; runs on main carry no PR number. The listener is a small bounded loopback module (`loopback.rs`) that phases 3 and 4 reuse; the `klatch` binary gains no network code (#1058).
- `klatch-server http --listen 127.0.0.1:PORT` (#1059, epic #1056 phase 3, #109): the klatch wire protocol over HTTP and server-sent events, loopback only (any other address is refused). `GET /v1/stream` opens a session as an event stream (every frame is one event with the same JSON line as stdio, a `message` event carries `id: room:seq`), `POST /v1/frames` with `X-Klatch-Session` writes frames into it, and a new stream resumes by subscribing from the last sequence number seen. Every request needs a worker credential (`Authorization: Bearer` and `X-Klatch-Member`), checked live; there is no unauthenticated tier. Same session loop and shared gateway as the daemon; limits on headers, bodies, time and connections. The `klatch` binary gains no network code.
- `klatch-server http` also serves MCP over Streamable HTTP at `POST /mcp` on the same loopback listener (#1060): the nine klatch tools, the worker credential and member header of the wire routes checked on every request, an Origin check, and no channel capability (channels stay stdio only).
- Append-only files (`proto/AUTHZ-AUDIT.md`, the `mod x;` registries) merge with git's built-in union driver, set in the root `.gitattributes`, so two branches adding lines at the same place no longer conflict; AUTHZ-AUDIT rows must be unique by operation, and `proto/scripts/test-merge-union.sh` (in the gate) proves the merge and the duplicate check (#1065).
- `klatch serve --stdio --ssh-key LABEL` for an ssh forced command: the member is the one the human mapped LABEL to with `klatch admin ssh-key LABEL MEMBER` (a floor act, audited; never an agent's), an unmapped label does not start, no typed name or environment variable is read, and a request that claims an identity is refused (rule `member-fixed`); a deployment guide, `clients/recipes/ssh-transport.md`, covers `authorized_keys`, mandatory host key verification, connection multiplexing and threat notes (#107).
- `proto/scripts/integrator --dry-run`: checks the first-run setup (the integrator role as far as it can be read, the gh login and its admin permission, the webhook extension, a clean clone on main, the gate script, who holds `merge:main`), reads the queue and the open PRs, runs the conflict pre-check, and prints the fixed-template words a real run would post and the merge it would make, in order. It posts, claims, pushes, branches, merges, runs no gate, starts no forwarder and makes no write call to gh; the last line says nothing was changed (#1075).
- The bench builds and drives `klatch-server channel` over stdio, with a scenario that times a post to its channel notification and checks an idle channel stays quiet (#1078).
- `klatch role` shows the role you hold (`integrator`, `reviewer`, ...) or `none`, a read of your own role only (#1090).

Only an integrator or the human counts, as for the other state words (#1094).

The conformance scenario of each library runs over the daemon as well as over stdio (#1095).

A stream that drops is reopened and every subscribed room is resubscribed from the last `seq` seen, so messages resume without a gap or a repeat (#1114). The Rust client is #1122.

It goes through the same gateway checks as every other front end, answers under the identity of the process and its clearance, and has no way to post, claim or change anything (#115).

- `klatch find ROOM TEXT` lists earlier asks in a room that someone already answered and that look like TEXT, each with its answer, so an asker can use a past answer instead of asking again. A match is TEXT as a substring of the ask (case and spacing ignored) or two shared words of four or more letters (one when TEXT has one); the line says which. It is read only (it pages `history`), moves no cursor and posts nothing (#239).

Audited, never above an ask claim's 300 second cap or the 24 hour claim cap (#242).

- `klatch card ROOM [MEMBER]` shows one member in one place: its scope and status, its offer, the asks it posted and their state, the asks it serves, its claims, tasks and pull requests. Derived from the board and the claims, bounded like the board, and every entry is data (#251).

- `klatch mcp --stdio`: an MCP (Model Context Protocol) server, so any agent runtime that can attach a tool server can use klatch with no harness. Six tools (`klatch_post`, `klatch_read`, `klatch_claim`, `klatch_release`, `klatch_wait` bounded at 55 seconds, `klatch_who`), each going through the same gateway checks as the wire and the command line; the caller is the member of the process and no argument can name another; the convention text is sent as the server's instructions (#299).
- A member has a kind (`session`, `bot`, `service` or `human`), shown by `klatch who` and on the board. A coding session gets `session` from klatch's own session record; a bot, a service or a human declares its own with `--member-kind` or `KLATCH_KIND` (or the wire method `kind`). Display only: it changes who may do what for no one (#301).
- A `mute` request (`room`, `muted`) over the wire protocol mutes or unmutes a room for the caller (#334), so a member that is not the CLI (`serve --stdio`, a client library) can do what `klatch mute` and `klatch unmute` do; the Python, TypeScript and Rust clients gain `mute`.
- `klatch --codex ...` gives a Codex session a stable member with no typed name and no registry record: a Codex hook's `session_id` and `cwd` on standard input name it (`codex-<directory>`, a few id characters added when another session already has that name), a resumed session keeps its member, and a command the agent runs is the same member through `CODEX_THREAD_ID`. The Python, TypeScript and Rust clients gain `dm`. The scrub list and the label order stay off the wire: they are floors, set only by the person at a terminal.
- Labelling a room `private` or above with `klatch admin label` now plants a canary in it by itself (a random per-room token, shown once in each member's first digest and hidden from read, history, tail and wait). An admin agent's label act plants none, and rooms labelled before this release get one when you label them again. `klatch admin canary-retire <room>` ends a room's canary (#347).
- `klatch admin rotate-label-key <label>` moves a sealed label to a new key: every message of the label in the store and in the archive files is sealed again under it in one crash-safe step (a repeated run finishes an interrupted one), the old key and its recovery code open none of them, and a sealed text that opens with neither key refuses the rotation with nothing changed. It prints the new recovery code and says to relaunch workers that hold the label (#378).
- `klatch doctor` probes the coding agent with `claude --version` and reports what it supports. A Claude Code older than 2.1.319, the oldest on which `asyncRewake` was measured, turns the wake watcher off (`klatch wake` exits at once and says why on standard error; hooks still deliver messages at the next prompt) and doctor warns with the version. A probe that cannot tell (no `claude` on the path, an answer with no version) turns nothing off (#482).
- `klatch doctor` reports row counts for the tables that only grow (live messages, audit, refusals, claim notes). Information only; no pruning is done (#487).
- `klatch crossings` tells the sender what became of each crossing it asked for: waiting, approved, released, denied or blocked, with a fixed reason that names the category of rule and never the text, a reviewer's words or the name of a private term (#516).
- `klatch judge run` is now a resident loop (`--once` for one pass, `--interval-secs`) backed by a local rules judge that denies credential and scrub-list matches and leaves clean text for the reviewer; `Breaker` and `Narrowed` keep a failing or wider judge from allowing anything by default (#517).
- `klatch history ROOM [--last N] [--since SEQ]` and the `history` request look back in a room without moving any cursor (#518): the newest 20 messages by default, everyone's, in the format `read` prints with the data rule; the label, clearance and sealed-label behaviour of `read --peek`, usable by a librarian; output bounded by count and bytes with a `N more messages not shown; run klatch history ROOM --since SEQ` line.

The Python, TypeScript and Rust clients gain `role_act` and `prune`.

- A recipe for turning a GitHub webhook into `klatch anchor github` with a signature check: `clients/recipes/github-webhook-anchor.py` verifies `X-Hub-Signature-256` (HMAC-SHA256 of the raw body, constant-time compare, secret read from a file) and only then pipes a `pull_request` or `issues` payload to klatch, with `clients/recipes/github-webhook.md` and offline tests with fixtures; the gate and CI run them (#531).

It creates nothing, never prints a key, and gives up on a stuck keystore after 5 seconds.

- `klatch sessions`: the live coding-agent sessions on this machine, from the harness registry (pid, name, directory, session id); `--all` adds the records that are not live and why. Read only; never opens a key file.

- `klatch init --uninstall`: removes every hook klatch installed and nothing else, with a diff and a question per scope.
- Static Linux builds (musl, x86_64 and aarch64): no glibc or other system library needed (tested in containers on Alpine 3.20, Debian 11 and Ubuntu 22.04, arm64 only). The installer chooses them when
  glibc is older than 2.34 or the system is not glibc; the dynamic builds need glibc 2.34 or later.

- A liveness probe in the harness module (`klatch::harness::probe`): from process identity, zombie or stopped state, the registry turn state and progress (transcript size and time, process-tree CPU between two samples, live children, background-task output) it says gone, waiting on a human, working, waiting on a tool, stuck or unknown, with the evidence. An unreadable layer is unknown, never gone. Reads file metadata only (#309).
- An ignored test, `liveness_real`, runs the liveness probe against the real Claude Code sessions on a machine and prints verdicts, evidence and cost; RESEARCH-NOTES section 46 records the first run (#310).
- `klatch doctor` now tries each liveness probe layer on the live sessions and says which are readable on this machine, warning when the registry status or the transcript layout stopped being readable for every session (a Claude Code change). An unreadable layer is unknown, never a dead session (#311).
- The Linux Secret Service backend is now run against a real gnome-keyring in containers (`proto/linux-keys/run.sh`, a manual workflow, never on pull requests) and covered by tests: round trip, replace, delete, wrong size, unsafe names, no secret on any command line, headless fallbacks (#381 #382 #383 #384 #385).
- `klatch admin archives` lists the archive files with rooms, message counts, ages and size, opening each with the store key and checking it for damage (exit status 1 if any is unusable); `klatch doctor` checks them too and warns about a file left by an interrupted `admin archive`. Archives are still never pruned (#487, #568).
- Clearer identity messages: a missing member name says to set `KLATCH_NAME` or pass `--discover`; `join` by discovery prints the name to set next; an empty `read` explains that earlier reads and processes sharing a name consume messages (#495, #500).
- The review queue is now real (#497): `klatch cross ROOM SEQ --to ROOM` queues a crossing into a lower-labelled room, an allow or redact verdict from the judge or the reviewer releases the text (floors checked again), a deny releases nothing, and `klatch admin review-queue` lists the queue without text. Store schema is now 24.
- Changelog fragments: one file per change in `changelog.d/`, checked by the gate and CI, so parallel pull requests no longer collide on CHANGELOG.md; CONTRIBUTING.md says how to reserve a DESIGN item number (#502).
- A member path for roles (#506, #509, #507): `klatch act <act>` and the wire method `role_act` let the admin agent call close, reopen, remove, allow, clear, label, audit and refusals as itself; `klatch review next|verdict` and the wire methods `review_next` and `review_verdict` let the reviewer review. No floor act has a form there, `klatch admin` stays human-only, and a member without the role is refused (`admin-scope`, `floors`, `reviewer`).
- A quarantined reviewer role (#51): `klatch admin reviewer <member>` (`--off` to remove). A reviewer can read queued review items and record allow, redact or deny on them (final, audited without the text), and every other operation is refused before the guard runs. A member holds one role at a time.
- Claims can be anchored to a GitHub pull request or issue (`gh:pr:OWNER/REPO/N`, `gh:issue:OWNER/REPO/N`; `klatch anchor github` reads `gh api` output or a webhook payload and frees the claims of merged or closed items), to a worktree (`wt:NAME`; `klatch anchor reap --worktrees DIR`) and to a session (`session:ID`, freed by `reap` once the session is marked done); klatch makes no network call (#57, #58).

### Changed

- macOS: the store key is kept in a 600 file, not the Keychain. The Keychain asks for the login password whenever a program it has not seen (every rebuild of an unsigned binary) reads an item, and no setting on an unsigned item avoids that (#480). A key found only in the Keychain is copied into the file the first time it is read (one Always Allow); a Keychain read gives up after 5 seconds with the reason.
- Claims follow their holder's liveness (DESIGN section 29, #304): when a member asks about claims (a claim attempt, `claims`, `who`), every other holder is probed. A holder that is working, waiting on a tool or waiting on a human keeps its claims even past their time to live (an expired row nobody took is put back); a holder that is gone loses them a grace period later (5 minutes), a stuck one at once, and one busy with no progress for the cap (4 hours; policy key `lease:cap` in seconds raises it) at once. A holder the probe cannot read, or with no session (a bot), keeps only its explicit time to live.
- A claim no longer lapses while its owner is working: any activity by the owner in the room (a hook, a post, a read) renews each of its live claims back to the ttl that claim was made with, counted from that moment (a `--ttl 60` claim stays 60 s from the last activity, a 3600 s claim stays 3600 s). It never shortens a lease, never revives a lapsed claim, and leaves `ask:` leases alone; the 24 h maximum still holds (#494, schema 26 stores the ttl; claims made before it are not renewed).
- Every job in the release workflows now has a time limit (builds 30 minutes, publishing 15 to 20, the binaries build 45), and `release/check-timeouts.sh` fails the gate and CI if one is missing.

### Fixed

- A hook that fires for a subagent's tool call (Claude Code marks it with `agent_id`) now prints nothing and moves no cursor. It used to run as the parent session, echo the subagent's own posts and claims back as other people's, and consume the parent's unread mail (#493).
- A hook digest is now kept within 8000 bytes (counted after JSON escaping) so it stays under Claude Code's hook output cap, past which the model sees only a 2 KB preview. What does not fit is counted in a line that says to run `klatch read ROOM --peek` (#549).
- The wake pointer now carries the unread count and the newest seq (`3 unread in room r, newest #41`), because Claude Code silently drops a nudge whose text equals a recent one (#550).
- On Linux a session bus address that points nowhere (an inherited one over ssh or cron) no longer makes every command fail: klatch falls back to the key file with the usual warning. Every `secret-tool` call is also bounded to 10 seconds and has no terminal, and a failure to reach the keyring is an error, no longer a missing key (#560).

## [0.1.0-dev.1] - 2026-11-14

The first release published through the release workflow, to PyPI, npm and crates.io together, with binaries for macOS
(arm64, x86_64) and Linux (x86_64, aarch64).

### Added

- Rooms with a durable log, a board of asks and offers, statuses, direct messages and mute.
- Claims on paths with expiry, conflict detection by scope, and an optional PreToolUse hook that blocks an edit of a
  path another member claimed.
- Claude Code hooks installed by `klatch init` (with a diff and a yes per scope), an idle-session wake watcher, and
  `klatch invite`.
- Encryption at rest (SQLCipher, key in the OS keystore or a 0600 key file, printed recovery code, no escrow) and
  per-label sealed bodies.
- Worker credentials: key bundles written by a launcher, expiring and revocable, so a worker's messages are verified.
- Factory features: typed handoffs, anchored claims, run-scoped rooms with encrypted archives.
- The wire protocol (version 1) and clients in Python, TypeScript and Rust (the `client` feature) with one
  conformance scenario each.
- Release files with provenance attestations, a CycloneDX SBOM per target, signed checksums and third-party licence
  notices; an installer script, a Homebrew tap and cargo-binstall metadata.

### Changed

- The ten workspace crates are one package, `klatch`, with the `cli` (default) and `client` features.
- `klatch --version` also prints the protocol and store schema versions.
